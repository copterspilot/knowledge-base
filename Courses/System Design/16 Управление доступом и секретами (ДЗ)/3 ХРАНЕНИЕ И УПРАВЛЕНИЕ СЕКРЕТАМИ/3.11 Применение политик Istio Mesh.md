## 🔄 1. Flowchart: Цепочка действий при применении политик Istio

```mermaid
flowchart TD
    A[Сервис A хочет вызвать Сервис B<br/>POST /process] --> B[Отправка запроса через Envoy A]
    B --> C[Envoy A устанавливает mTLS-соединение<br/>с Envoy B]
    C --> D[Envoy B перехватывает запрос]
    D --> E[Проверка PeerAuthentication<br/>→ mTLS включён?]
    E --> F{mTLS активен?}
    F -- Нет --> G[403: mTLS не настроен]
    F -- Да --> H[Проверка RequestAuthentication<br/>→ Есть ли JWT?]
    H --> I{JWT валиден?}
    I -- Нет --> J[401: Невалидный или отсутствующий токен]
    I -- Да --> K[Проверка AuthorizationPolicy<br/>→ Разрешён ли вызов?]
    K --> L{Доступ разрешён?}
    L -- Нет --> M[403: Доступ запрещён политикой]
    L -- Да --> N[Передача запроса Сервису B]
    N --> O[Сервис B обрабатывает запрос]
    O --> P[Ответ через Envoy B → Envoy A]
    P --> Q[Сервис A получает ответ 200 OK]

    style A fill:#e1f5fe
    style G fill:#ffcdd2
    style J fill:#ffcdd2
    style M fill:#ffcdd2
    style Q fill:#c8e6c9
```

```
    note right of K
      Проверяются:
      - Principal (SPIFFE ID)
      - Метод (POST)
      - Путь (/process)
    end note

    note right of E
      Проверяется:
      - mTLS между sidecar'ами
    end note
```

## 📊 2. StateDiagram: Состояния запроса при прохождении через Istio

```mermaid
stateDiagram-v2
    [*] --> Инициация_вызова
    Инициация_вызова --> Отправка_через_Envoy_A: Сервис A → Envoy A

    state "Отправка через Envoy A" as Отправка_через_Envoy_A
    Отправка_через_Envoy_A --> Установка_mTLS: mTLS-соединение с Envoy B

    state "Установка mTLS" as Установка_mTLS
    Установка_mTLS --> Прием_запроса_Envoy_B: Envoy B получает запрос

    state "Прием запроса Envoy B" as Прием_запроса_Envoy_B
    Прием_запроса_Envoy_B --> Проверка_PeerAuth: Проверка mTLS (PeerAuthentication)

    state "Проверка PeerAuth" as Проверка_PeerAuth
    Проверка_PeerAuth --> Проверка_JWT: Проверка RequestAuthentication

    state "Проверка JWT" as Проверка_JWT
    Проверка_JWT --> Проверка_AuthorizationPolicy: Проверка AuthorizationPolicy

    state "Проверка AuthorizationPolicy" as Проверка_AuthorizationPolicy
    Проверка_AuthorizationPolicy --> Доступ_разрешен: Политики пройдены

    state "Доступ разрешен" as Доступ_разрешен
    Доступ_разрешен --> Передача_в_Сервис_B: Запрос → Сервис B

    state "Передача в Сервис B" as Передача_в_Сервис_B
    Передача_в_Сервис_B --> Обработка_запроса: Сервис B обрабатывает

    state "Обработка запроса" as Обработка_запроса
    Обработка_запроса --> Ответ_через_Envoy_B: Ответ → Envoy B

    state "Ответ через Envoy B" as Ответ_через_Envoy_B
    Ответ_через_Envoy_B --> Ответ_в_Сервис_A: Ответ → Envoy A → Сервис A

    Ответ_в_Сервис_A --> [*]: Завершение

    note right of Проверка_PeerAuth
      Проверяется:
      - mTLS STRICT mode
      - Сертификаты SPIFFE
    end note

    note right of Проверка_JWT
      Проверяется:
      - Наличие JWT
      - Валидность подписи
      - Issuer и audience
    end note

    note right of Проверка_AuthorizationPolicy
      Проверяются:
      - Principal (идентичность вызывающего)
      - Метод и путь запроса
      - Разрешения по политике
    end note
```

## 📌 Что показывают диаграммы?

### 🔁 Flowchart:
- **Цепочка действий** от момента вызова до получения ответа.
- **Участники**: сервисы, sidecar-прокси, Istio Control Plane.
- **Проверки**: mTLS, JWT, политики авторизации.
- **Результаты**: успех или ошибка (401, 403).

### 📊 StateDiagram:
- **Состояния** запроса при прохождении через Istio.
- **Переходы** между этапами проверки безопасности.
- **Контекст**: сетевой поток с применением политик.
