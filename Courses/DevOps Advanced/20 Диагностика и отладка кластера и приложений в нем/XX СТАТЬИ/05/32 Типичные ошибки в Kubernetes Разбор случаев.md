### **Статья 31: Типичные ошибки в Kubernetes: Разбор случаев**

#### **Введение**

Практически каждый инженер сталкивается с этими ошибками. `CrashLoopBackOff` — это когда ваш под постоянно перезапускается. Причина почти всегда в логах (`kubectl logs --previous`). `ImagePullBackOff` — значит, Kubernetes не может скачать образ. Проверьте имя образа и права доступа к реестру в `describe pod`. Если поды не могут общаться, проверьте `NetworkPolicy` и DNS. А если вы видите `Insufficient CPU`, значит, вашим подам нужно больше ресурсов, чем есть на узлах. Как указано в `Бранд А., Ландер Р., Россо Д., Харрис Д. - Kubernetes на практике`, понимание этих сценариев — основа для эффективной работы с Kubernetes.

#### **Ошибка 1: `CrashLoopBackOff`**

Это одна из самых частых и тревожных ошибок. Она означает, что контейнер запускается, падает, а Kubernetes пытается его перезапустить, что приводит к бесконечному циклу.

*   **Возможные причины:**
    *   **Ошибка в коде приложения:** Исключение при запуске, неправильная конфигурация.
    *   **Отсутствие переменной окружения:** Приложение не может запуститься без необходимых переменных.
    *   **Неудачное подключение к зависимостям:** Невозможно подключиться к базе данных, кешу или другому сервису.
*   **Диагностика:**
    1.  Проверьте логи **упавшего** контейнера:
        ```bash
        kubectl logs my-app-pod-7d5b8c9c4-xl2v9 --previous
        ```
        Ищите стектрейсы (stack traces), сообщения об ошибках и исключения.
    2.  Проверьте события в `describe pod`:
        ```bash
        kubectl describe pod my-app-pod-7d5b8c9c4-xl2v9
        ```
        Убедитесь, что нет проблем с выделением ресурсов или подключением томов.

#### **Ошибка 2: `ImagePullBackOff`**

Kubernetes не может скачать образ контейнера, из-за чего под не может запуститься.

*   **Возможные причины:**
    *   **Неправильное имя образа:** Опечатка в имени образа, теге или пути к реестру.
    *   **Отсутствие доступа к приватному реестру:** Kubernetes не может аутентифицироваться в реестре.
    *   **Образ не существует:** Тег был удален или образ не был загружен.
*   **Диагностика:**
    1.  Проверьте секцию `Events` в выводе команды:
        ```bash
        kubectl describe pod my-app-pod-7d5b8c9c4-xl2v9
        ```
        Там будет точное сообщение об ошибке, например: `Failed to pull image "my-registry.com/my-app:v1.2": unauthorized: authentication required`.
    2.  Убедитесь, что вы создали `Secret` типа `docker-registry` и указали его в `imagePullSecrets` манифеста пода.

#### **Ошибка 3: Поды не могут общаться**

Поды в одном namespace не могут установить соединение между собой.

*   **Возможные причины:**
    *   **`NetworkPolicy`:** Существующая политика безопасности может блокировать трафик между подами.
    *   **Ошибка в DNS:** Имя сервиса не разрешается.
    *   **Неправильный порт:** Приложение слушает на одном порту, а сервис указывает на другой.
*   **Диагностика:**
    1.  Проверьте наличие `NetworkPolicy`:
        ```bash
        kubectl get networkpolicy
        ```
    2.  Проверьте разрешение имени сервиса:
        ```bash
        kubectl exec my-pod -- nslookup postgres-service
        ```
    3.  Убедитесь, что порт в `spec.ports` сервиса соответствует порту, на котором слушает приложение.

#### **Ошибка 4: Недостаточно ресурсов (`Insufficient CPU/Memory`)**

Планировщик Kubernetes не может найти узел, на котором можно запустить под, потому что запрашиваемые ресурсы превышают доступные.

*   **Возможные причины:**
    *   Запросы (`requests`) в манифесте пода слишком высоки.
    *   На узлах недостаточно свободных ресурсов.
*   **Диагностика:**
    1.  Проверьте события в `describe pod`:
        ```bash
        kubectl describe pod my-app-pod-7d5b8c9c4-xl2v9
        ```
        Ищите сообщение: `0/3 nodes are available: 3 Insufficient cpu.`.
    2.  Проверьте потребление ресурсов узлами:
        ```bash
        kubectl top nodes
        ```
    3.  Проверьте конфигурацию пода:
        ```bash
        kubectl get pod my-app-pod-7d5b8c9c4-xl2v9 -o yaml | grep -A 5 resources
        ```
