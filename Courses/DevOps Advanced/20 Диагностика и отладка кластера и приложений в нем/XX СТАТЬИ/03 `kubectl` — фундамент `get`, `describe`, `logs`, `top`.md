### **Статья 3: `kubectl` — фундамент: `get`, `describe`, `logs`, `top`**

#### **Что такое `kubectl` и почему он главный инструмент?**

`kubectl` — это **единственный CLI-инструмент**, который вам нужен для взаимодействия с кластером Kubernetes. Он является вашим "проводником" в мире контейнеров. Все, что вы делаете — от развертывания приложений до диагностики проблем — проходит через `kubectl`.

#### **Основные команды для диагностики**

Для диагностики состояния кластера и приложений вам понадобится всего четыре команды. Освоив их, вы сможете решить большинство повседневных задач.

1.  **`kubectl get` — Получение информации**
    *   **Что делает:** Показывает список ресурсов (pods, nodes, services, deployments и т.д.).
    *   **Примеры:**
        ```bash
        # Показать все поды во всех namespace'ах
        kubectl get pods -A
        
        # Показать поды с меткой app=frontend
        kubectl get pods -l app=frontend
        
        # Показать сервисы
        kubectl get services
        
        # Наблюдать за изменениями в реальном времени
        kubectl get pods -w
        ```

2.  **`kubectl describe` — Глубокая диагностика**
    *   **Что делает:** Показывает подробную информацию о конкретном ресурсе, включая его конфигурацию, состояние и **события (Events)**. Секция `Events` — это **ключ к диагностике**.
    *   **Пример:**
        ```bash
        kubectl describe pod my-app-pod-7d5b8c9c4-xl2v9
        ```
        *   Ищите в секции `Events` сообщения типа `FailedScheduling`, `ImagePullBackOff`, `Back-off restarting failed container`.

3.  **`kubectl logs` — Анализ логов приложения**
    *   **Что делает:** Показывает логи, выводимые процессом в контейнере.
    *   **Примеры:**
        ```bash
        # Показать последние 20 строк логов
        kubectl logs my-app-pod-7d5b8c9c4-xl2v9 --tail=20
        
        # Показать логи в реальном времени (follow)
        kubectl logs my-app-pod-7d5b8c9c4-xl2v9 -f
        
        # КРИТИЧЕСКИ ВАЖНО: Показать логи УПАВШЕГО контейнера
        kubectl logs my-app-pod-7d5b8c9c4-xl2v9 --previous
        ```

4.  **`kubectl top` — Анализ потребления ресурсов**
    *   **Что делает:** Показывает текущее потребление CPU и памяти подами и узлами.
    *   **Примеры:**
        ```bash
        # Показать потребление ресурсов узлами
        kubectl top nodes
        
        # Показать потребление ресурсов подами, отсортированными по памяти
        kubectl top pods --sort-by=memory
        ```
    *   **Важно:** Для работы `kubectl top` требуется `metrics-server`.

#### **Путь вперед**

Эти четыре команды — ваш фундамент. В следующих статьях мы построим на этом фундаменте более сложные техники, такие как проброс портов и отладка с помощью `eBPF`.

**Запомните:** Хороший инженер — это не тот, кто знает все команды, а тот, кто умеет правильно использовать эти четыре.
