### **Статья 21: `kubectl trace` и `ksniff`: Захват трафика на уровне узла**

#### **Введение**

`kubectl trace` и `ksniff` — это два мощных инструмента для диагностики на уровне узла, но они работают по-разному. `ksniff` — это как осциллограф: он показывает форму сигнала (сетевой пакет). `kubectl trace` — это как анализатор протокола на уровне микросхемы: он показывает, какой процесс вызвал создание этого сигнала. Если вам нужно понять, *почему* под не может установить соединение, используйте `kubectl trace` для поиска ошибки в системном вызове. Если вам нужно понять, *как* строится TCP-рукопожатие, используйте `ksniff` для захвата пакетов. Эти инструменты дополняют друг друга.

#### **`ksniff`: Захват трафика на уровне пода**

`ksniff` — это специализированный плагин для `kubectl`, который упрощает захват сетевого трафика с пода и его анализ в графическом интерфейсе `Wireshark`.

*   **Как это работает:**
    1.  Вы запускаете команду `kubectl sniff`.
    2.  `ksniff` создает временный отладочный контейнер внутри целевого пода (или рядом с ним) и устанавливает в него утилиту `tcpdump`.
    3.  `tcpdump` начинает захватывать пакеты с сетевого интерфейса пода.
    4.  Поток данных передается напрямую на ваш локальный компьютер и открывается в запущенном `Wireshark`.
*   **Преимущества:**
    *   **Глубокий анализ пакетов:** Позволяет видеть содержимое IP-пакетов, флаги TCP, DNS-запросы и ответы.
    *   **Привычный интерфейс:** `Wireshark` — стандарт для сетевых инженеров.
*   **Недостатки:**
    *   **Ограниченный контекст:** Показывает "что" передавалось, но не "какое приложение" это инициировало.
    *   **Высокая нагрузка:** Захват большого объема трафика создает значительную нагрузку.

#### **`kubectl trace`: Трассировка на уровне ядра с помощью eBPF**

`kubectl trace` — это CLI-инструмент, который использует технологию eBPF для безопасного выполнения кода внутри ядра Linux узла.

*   **Как это работает:**
    1.  Вы запускаете команду `kubectl trace run` с указанием узла и eBPF-программы (например, трассировщика системных вызовов).
    2.  Инструмент создает Job в кластере, который разворачивает агент на целевом узле.
    3.  Агент загружает eBPF-программу в ядро, которая начинает перехватывать события.
    4.  Результаты отправляются обратно в ваш терминал.
*   **Преимущества:**
    *   **Глубокий контекст:** Показывает, какой *процесс* в каком *контейнере* сделал системный вызов (например, `connect`, `open`).
    *   **Низкая нагрузка:** eBPF-программы оптимизированы и создают минимальные накладные расходы.
    *   **Широкие возможности:** Может трассировать не только сеть, но и файловые операции, планировщик и потребление ресурсов.
*   **Недостатки:**
    *   **Более сложная установка:** Требует установки `krew` и самого плагина `trace`.
    *   **Нет "содержимого пакета":** Не показывает полезную нагрузку (payload) сетевых пакетов.

#### **Практические примеры**

1.  **Использование `ksniff`:**
    ```bash
    # Установка плагина
    kubectl krew install sniff
    # Захват трафика и открытие в Wireshark
    kubectl sniff my-app-pod -n default
    ```

2.  **Использование `kubectl trace`:**
    ```bash
    # Установка плагина
    kubectl krew install trace
    # Трассировка всех попыток открытия файлов
    kubectl trace run node/my-node -e tracepoint:syscalls:sys_enter_openat
    # Трассировка установления TCP-соединений
    kubectl trace run node/my-node -e tcpconnect
    ```

#### **Заключение**

Оба инструмента являются мощными дополнениями к базовому набору команд `kubectl`. `ksniff` незаменим для анализа сетевого протокола, а `kubectl trace` — для поиска причин сбоев на уровне ядра. Современный инженер должен уметь использовать оба. В следующей статье мы рассмотрим `inspektor-gadget`, который объединяет возможности eBPF в одном удобном пакете.
