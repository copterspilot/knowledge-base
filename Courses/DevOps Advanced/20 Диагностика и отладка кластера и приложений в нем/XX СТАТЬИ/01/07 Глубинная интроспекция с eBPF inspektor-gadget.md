### **Статья 7: Глубинная интроспекция с eBPF: `inspektor-gadget`**

#### **Введение**

До сих пор мы говорили о том, что разрешено, а что запрещено. А что, если злоумышленник уже проник в под? Как понять, что он на самом деле делает? Для этого существует eBPF. Это технология, которая позволяет безопасно запускать программы внутри ядра Linux. Инструмент `inspektor-gadget` использует eBPF, чтобы показать нам, какие файлы открывает процесс, какие сетевые соединения он устанавливает. Это следующий шаг в эволюции диагностики и безопасности, ведущий к 'eBPF Everywhere'.

#### **Что такое eBPF?**

`eBPF` (extended Berkeley Packet Filter) — это не просто фильтр пакетов. Это виртуальная машина внутри ядра Linux, которая позволяет безопасно выполнять песочницу (sandboxed) код для мониторинга и модификации системы.

*   **Безопасность:** Перед выполнением код проверяется встроенным верификатором, который гарантирует, что он не может повредить ядро или вызвать его зависание.
*   **Производительность:** eBPF-программы выполняются с минимальными накладными расходами, что делает их идеальными для постоянного мониторинга.
*   **Глубина:** eBPF предоставляет "невидимый микрофон и камеру" на уровне ядра, позволяя видеть все системные вызовы.

#### **Что такое `inspektor-gadget`?**

`inspektor-gadget` — это набор CLI-инструментов, упакованных в удобный оператор Kubernetes. Он использует eBPF для предоставления глубокой интроспекции.

*   **Установка:**
    ```bash
    # Установка оператора в кластер
    kubectl apply -k github.com/inspektor-gadget/inspektor-gadget/config/default?ref=v0.20.0
    ```
*   **Использование:** После установки вы получаете команду `kubectl gadget` с несколькими подкомандами (гаджетами).

#### **Практические примеры**

1.  **Трассировка открытия файлов:**
    ```bash
    # Отследить все попытки открытия файлов в namespace 'my-app'
    kubectl gadget trace open -n my-app
    ```
    Эта команда покажет, какой процесс в каком контейнере пытается открыть какой файл. Это незаменимо для диагностики `CrashLoopBackOff`.

2.  **Мониторинг сетевых соединений:**
    ```bash
    # Отследить все TCP-соединения
    kubectl gadget trace tcp-connect
    ```
    Вы увидите, какие поды устанавливают соединения с какими IP-адресами и портами.

3.  **Профилирование потребления CPU:**
    ```bash
    # Профилирование CPU (похоже на `perf top`)
    kubectl gadget profile-cpu -c my-container
    ```
    Помогает найти "прожорливые" функции в коде приложения.

#### **Заключение**

`inspektor-gadget` — это переход от статической проверки конфигурации к динамическому мониторингу поведения. Он позволяет видеть не только "что разрешено", но и "что на самом деле происходит". Это технология будущего для диагностики, безопасности и наблюдаемости. В следующей статье мы сравним его с традиционным инструментом `ksniff`.
