### **Статья 9: Проброс портов - `kubectl port-forward`**

#### **Введение**

Представьте, что вы хотите проверить веб-интерфейс вашего приложения, которое работает в кластере, но оно не имеет внешнего IP или Ingress-правила. Вы не хотите его открывать на весь мир. Решение — `kubectl port-forward`. Эта команда создает зашифрованный туннель от вашего локального порта (например, 8080) прямо к порту в поде. Все соединения идут через API-сервер, используя вашу существующую аутентификацию. Как указано в `Burns B., Villalba E., Strebel D., Evenson L. - Kubernetes Best Practices`, это один из самых безопасных способов доступа к внутренним сервисам.

#### **Как работает `kubectl port-forward`**

Команда `port-forward` действует как "труба", соединяющая ваш локальный компьютер с ресурсом в кластере.

*   **Технология:** Она использует существующее соединение к API-серверу (установленное с помощью `kubeconfig`) для создания зашифрованного туннеля.
*   **Безопасность:** Это означает, что трафик не проходит через открытые порты в сети кластера, а защищен аутентификацией и шифрованием TLS.
*   **Назначение:** Вы можете пробросить порт как к конкретному поду, так и к сервису (в этом случае трафик будет распределяться между всеми подами сервиса).

#### **Практические примеры**

1.  **Доступ к веб-приложению:**
    ```bash
    # Проброс локального порта 8080 к порту 80 в поде my-web-pod
    kubectl port-forward pod/my-web-pod 8080:80
    ```
    Теперь вы можете открыть браузер на `http://localhost:8080` и увидеть ваше приложение.

2.  **Доступ к сервису:**
    ```bash
    # Проброс локального порта 8080 к порту 80 сервиса my-web-service
    kubectl port-forward service/my-web-service 8080:80
    ```
    Трафик будет распределяться между всеми подами, входящими в этот сервис.

3.  **Доступ к базе данных:**
    ```bash
    # Проброс к PostgreSQL (порт 5432)
    kubectl port-forward service/postgres 5432:5432
    ```
    После этого вы можете подключиться к базе данных с помощью локального клиента (например, `psql`), используя `localhost:5432`.

#### **Важные нюансы**

*   **Живучесть:** Команда `port-forward` работает только пока запущена в терминале. Закрытие терминала разрывает туннель.
*   **Однопользовательский доступ:** Туннель доступен только с того компьютера, где запущена команда.
*   **Производительность:** Для интенсивных нагрузок туннель через API-сервер может стать узким местом.

#### **Заключение**

`kubectl port-forward` — это незаменимый инструмент для разработчиков и DevOps-инженеров. Он предоставляет безопасный и простой способ получить доступ к любому сервису в кластере без изменения его конфигурации. В следующей статье мы рассмотрим команды для выполнения команд внутри контейнеров.
