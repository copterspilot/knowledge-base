**1. Визуальный ряд**
*   Логотип `ksniff`.
*   Скриншот терминала: `kubectl sniff my-pod-7d5b8c9c4-xl2v9`.
*   Скриншот Wireshark с захваченным трафиком.
*   Логотип `inspektor-gadget`.
*   Скриншот терминала: `kubectl gadget trace open -n my-app`.
*   Иконки: Wireshark, eBPF, лупа.

**2. Демо-сценарий (если уместен)**
*   Показать в реальном времени команду `kubectl sniff` на тестовом поде и продемонстрировать, как трафик появляется в Wireshark.
*   Показать в реальном времени команду `kubectl gadget trace open` для отслеживания файлов, открываемых приложением.

**3. Ключевые тезисы**
*   `ksniff` решает задачу анализа сетевого трафика в Kubernetes, когда стандартные команды бессильны.
*   `inspektor-gadget` предоставляет "суперсилы" для глубокой интроспекции на уровне ядра с помощью eBPF.
*   Эти инструменты позволяют диагностировать проблемы, которые невозможно увидеть с помощью `kubectl describe` или `logs`.

**4. Описание (для выступающего)**
*   **Цель слайда:** Представить два мощных инструмента для решения сложных, нетривиальных проблем в Kubernetes, когда базовых команд недостаточно.
*   **Ключевое сообщение:** Когда стандартные команды `kubectl` не дают ответа, `ksniff` и `inspektor-gadget` предоставляют "суперсилы" для глубокой диагностики.
*   **Основные тезисы:**
    *   **`ksniff`:** Плагин для захвата сетевого трафика из пода и его анализа в Wireshark. Работает путем копирования `tcpdump` в контейнер или запуска привилегированного контейнера (с флагом `-p`). *(Из PDF 2019, слайд 6.2)*
    *   **`inspektor-gadget`:** Набор инструментов на основе eBPF для интроспекции на уровне ядра. Позволяет трейсить системные вызовы, отслеживать открытие файлов и сетевых сокетов. *(Из PDF 2019, слайд 7.1, 7.2)*
    *   Эти инструменты решают задачи, которые раньше требовали сложных ручных операций (например, `kubectl debug` + `strace`). *(Из PDF 2019, слайд 7.2)*
*   **Связь с источниками:** Тезисы основаны на PDF 2019 года (слайды 6.1, 6.2, 7.1, 7.2) и субтитрах (упоминание "суперсилы").

**6. Типовые вопросы и ответы (Q&A)**
*   **В:** Почему не использовать просто `kubectl exec` с `tcpdump`?
    *   **О:** Потому что `ksniff` автоматизирует процесс и работает с любыми образами, включая `scratch`, создавая привилегированный контейнер для захвата трафика.
*   **В:** Насколько сложно установить `inspektor-gadget`?
    *   **О:** В 2025 году установка упростилась. Обычно достаточно установить оператор через Helm и CLI-инструмент `kubectl gadget`. Поддержка CRI улучшена.
*   **В:** Можно ли использовать `inspektor-gadget` в managed-кластерах (GKE, EKS)?
    *   **О:** Это зависит от провайдера. Некоторые ограничивают права, но многие современные managed-сервисы начинают поддерживать eBPF.

**7. Примеры использования / Типовые сценарии**
*   **Анализ сетевых проблем:** Приложение не может подключиться к базе данных. `kubectl sniff` помогает увидеть, идут ли пакеты, и есть ли ошибки на уровне TCP.
*   **Отладка приложения:** Подозреваете, что приложение читает конфиг из неправильного файла. `kubectl gadget trace open` покажет все открываемые файлы.
*   *(Из PDF 2019, слайд 7.2)* "Просмотр открываемых файлов, сетевых сокетов и запускаемых процессов в Pod".

| **Параметр**            | **`ksniff`**                                           | **`inspektor-gadget`**                                                                         |
|:----------------------- |:------------------------------------------------------ |:---------------------------------------------------------------------------------------------- |
| **Основное назначение** | Анализ сетевого трафика на уровне пода.                | Глубокая диагностика ядра и системных вызовов.                                                 |
| **Технология**          | Использует `tcpdump` внутри контейнера.                | Использует eBPF для безопасного выполнения кода в ядре.                                        |
| **Диагностика**         | Сетевые пакеты (DNS, HTTP, TCP).                       | Системные вызовы, открытие файлов, сетевые сокеты.                                             |
| **Установка**           | Плагин для `kubectl` (через `krew`).                   | Требует установки демона на нодах кластера.                                                    |
| **Использование**       | `kubectl sniff <pod-name>`                             | `kubectl gadget <подкоманда>` (например, `trace open`)                                         |
| **Интерфейс**           | Перенаправляет трафик в Wireshark или файл.            | Выводит результат в терминал.                                                                  |
| **Преимущества**        | Простота, интеграция с Wireshark, работает везде.      | Глубокая интроспекция, безопасность, отсутствие необходимости в привилегированных контейнерах. |
| **Недостатки**          | Требует повышенных привилегий для минимальных образов. | Сложность установки и настройки.                                                               |

**Вывод:** `ksniff` — это специализированный инструмент для анализа сети, а `inspektor-gadget` — это набор "суперсил" для диагностики на уровне ядра.
