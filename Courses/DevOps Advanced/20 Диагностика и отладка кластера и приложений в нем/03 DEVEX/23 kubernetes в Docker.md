```markdown
## 23. kubernetes в Docker

**Содержимое слайда (для PowerPoint):**
- **Заголовок:** kubernetes в Docker
- **Основной текст:**
  - **Docker Desktop** — встроенный кластер Kubernetes (на базе `kubeadm`)
  - Включает: `kube-apiserver`, `etcd`, `kubelet`, `kube-proxy`, `coredns`
  - Управляется через интерфейс Docker или `kubectl`
  - Поддержка `Ingress`, `StorageClasses`, `Helm`
  - Отличное решение для локальной разработки и тестирования
- **Визуал:** Скриншот Docker Desktop с включенным Kubernetes.
- **Подпись:** "Kubernetes прямо в вашем Docker"
```

#### **Цель слайда**
Показать, как **Docker Desktop** предоставляет простой способ запустить **локальный кластер Kubernetes** для разработки и тестирования, без необходимости настройки `minikube` или `kind`.

#### **2. Ключевые тезисы (для аудитории)**
- Docker Desktop — самый простой способ запустить Kubernetes локально.
- Он включает все основные компоненты кластера.
- Удобно для тестирования манифестов и Helm-чартов.
- Не предназначен для production.

#### **3. Ключевые тезисы (для преподавателя)**
- Подчеркните, что это **не полноценный production-кластер**, а инструмент для разработки.
- Укажите, что Docker Desktop использует `kubeadm` под капотом.
- Напомните, что после включения Kubernetes нужно перезапустить Docker.

#### **4. Подробное описание сути слайда (пример речи выступающего)**

> - Разработки Helm-чартов,

#### **8. Типовые вопросы и ответы (Q&A)**
- **В:** Безопасен ли Kubernetes в Docker Desktop?  
  **О:** Да, он изолирован и работает на вашей машине.
- **В:** Можно ли использовать его для production?  
  **О:** Нет, это инструмент для разработки и тестирования.
- **В:** Как переключиться между контекстами?  
  **О:** `kubectl config use-context docker-desktop`.
