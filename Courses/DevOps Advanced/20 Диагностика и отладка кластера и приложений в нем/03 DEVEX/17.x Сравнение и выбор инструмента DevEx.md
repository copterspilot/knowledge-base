**3. Ключевые тезисы**
*   `ksync` — простой инструмент для синхронизации файлов.
*   `telepresence` — мощный инструмент для глубокой интеграции локальной среды с кластером.
*   `Tilt` и `Skaffold` — фреймворки для автоматизации локального CI/CD-цикла.
*   Инструменты часто используются в комбинации, а не как взаимоисключающие решения.

**4. Описание (для выступающего)**
*   **Цель слайда:** Помочь слушателям понять, когда и какой инструмент DevEx использовать.
*   **Ключевое сообщение:** Выбор инструмента зависит от конкретной задачи. Часто наиболее эффективно использовать их в комбинации.
*   **Основные тезисы:**
    *   **`ksync`:** Лучше всего подходит для задач, где нужно быстро обновить код в поде (например, HTML, CSS, шаблоны). Его простота — главное преимущество. *(Из PDF 2019, слайд 10.1)*.
    *   **`telepresence`:** Идеален, когда нужно, чтобы локальный процесс полноценно взаимодействовал с сервисами в кластере (например, для отладки микросервиса, зависящего от базы данных в кластере). Его можно использовать для подмены целого `Deployment`. *(Из PDF 2019, слайд 11)*.
    *   **`Tilt` и `Skaffold`:** Это не просто инструменты для синхронизации, а полноценные фреймворки для локальной разработки. Они отслеживают изменения в коде, автоматически пересобирают образы, деплоят изменения и агрегируют логи. Лучше подходят для постоянной разработки. *(Из субтитров 2019: "Потом поговорим о том, как облегчить жизнь разработчикам")*.
    *   **Комбинация:** Например, можно использовать `Tilt` для основного цикла разработки, а `telepresence` — для временной подмены одного сервиса, который сложно или невозможно развернуть локально.

**6. Типовые вопросы и ответы (Q&A)**
*   **В:** Что выбрать: `Tilt` или `Skaffold`?
    *   **О:** Оба отличны. `Skaffold` от Google, хорошо документирован. `Tilt` часто имеет более удобный UI и мощные возможности для описания сложных зависимостей. Выбор зависит от предпочтений команды.
*   **В:** Можно ли использовать `ksync` и `telepresence` вместе?
    *   **О:** Да, в некоторых сценариях это возможно, но они решают разные задачи. `ksync` синхронизирует файлы, `telepresence` создает сетевой туннель.
*   **В:** Нужно ли использовать все эти инструменты?
    *   **О:** Нет. Начните с одного, который решает вашу основную боль. Например, `Tilt` для автоматизации или `telepresence` для доступа к кластеру.

**7. Примеры использования / Типовые сценарии**
*   **Разработка веб-интерфейса:** Использовать `ksync` для мгновенного обновления статики.
*   **Отладка бэкенд-сервиса:** Использовать `telepresence` для запуска бэкенда локально с доступом к базе данных в кластере.
*   **Полный цикл разработки:** Использовать `Tilt` для автоматической пересборки и деплоя приложения при любом изменении кода.

### **Краткий гид по выбору**

*   **Вам нужно просто и быстро подменить файлы в поде?** -> Раньше **`ksync`**, сейчас лучше использовать `ephemeral containers` или другие методы.
*   **Вы разрабатываете микросервис, которому нужен доступ к БД, кешу и другим сервисам *внутри кластера*?** -> **`telepresence`**. Это ваш главный инструмент.
*   **Вы работаете над монолитом или набором сервисов и хотите максимально автоматизировать сборку, деплой и визуализировать процесс?** -> **`Tilt`**.
*   **Вам нужен унифицированный, приближенный к продакшену пайплайн для сборки, тестирования и деплоя, который можно использовать и локально, и в CI?** -> **`Skaffold`**.

**Современный тренд:** Комбинировать инструменты. Например, использовать **`telepresence`** для доступа к кластеру и **`Tilt`** для автоматической пересборки и управления зависимостями локальных сервисов.
