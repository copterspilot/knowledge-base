## [10] Выполнение команд - `kubectl exec`, `attach`, `cp`

**Содержимое слайда (для PowerPoint):**
-   **Заголовок:** Выполнение команд - `kubectl exec`, `attach`, `cp`
-   **Основной текст / список:**
    *   **`kubectl exec`:** Выполнение команды внутри контейнера.
        *   `kubectl exec my-pod -it -- /bin/sh` — интерактивная оболочка.
        *   `kubectl exec my-pod -- ps aux` — выполнение одной команды.
    *   **`kubectl attach`:** Подключение к stdin/stdout основного процесса.
        *   Полезно для просмотра логов процесса, который не пишет в файл.
    *   **`kubectl cp`:** Копирование файлов между локальной машиной и контейнером.
        *   `kubectl cp my-pod:/path/to/remote/file ./local/file` — копирование из контейнера.
        *   `kubectl cp ./local/file my-pod:/path/to/remote/file` — копирование в контейнер.
    *   **Ключевое ограничение:** Не работает в `distroless` образах (нет `/bin/sh`).
-   **Дополнительная информация (внизу):** "Используйте эти команды для диагностики, но не для постоянного управления."

#### **Цель слайда**
Познакомить аудиторию с тремя основными командами для взаимодействия с контейнерами: `exec`, `attach` и `cp`. Научить использовать их для диагностики проблем и передачи файлов.

#### **1. Описание визуального оформления**
Слайд должен содержать три крупные иконки, каждая с названием команды и примером использования. Используйте цветовую кодировку: синий для `exec`, зеленый для `attach`, оранжевый для `cp`. Внизу — предупреждающий знак и ключевое сообщение о ограничениях.

#### **2. Ключевые тезисы**
*   `kubectl exec` — это основной способ "войти" в контейнер.
*   `kubectl attach` позволяет подключиться к уже запущенному процессу.
*   `kubectl cp` — это аналог `scp` для контейнеров.
*   Эти команды не работают в образах без оболочки (`distroless`).

#### **3. Описание для выступающего (речь)**
"Когда вы хотите посмотреть, что происходит внутри контейнера, вы используете `kubectl exec`. Это как `docker exec`, но для Kubernetes. Вы можете запустить интерактивную оболочку или выполнить одну команду. Если вам нужно подключиться к потокам ввода-вывода основного процесса, используйте `attach`. А если нужно передать файл, используйте `cp`. Эти команды являются основой для отладки, но помните, что они бесполезны, если в контейнере нет `sh` или `bash`. В таких случаях мы используем `kubectl debug`, о котором поговорим далее."

#### **6. Типовые вопросы и ответы (Q&A):**
*   **В:** В чем разница между `exec` и `attach`?
    *   **О:** `exec` запускает новую команду в контейнере, `attach` подключается к потокам ввода-вывода *уже запущенного* основного процесса.
*   **В:** Можно ли использовать `cp` для каталогов?
    *   **О:** Да, добавьте флаг `-r` для рекурсивного копирования: `kubectl cp -r ./local/dir my-pod:/remote/dir`.

#### **7. Примеры использования / Типовые сценарии**
*   **Диагностика `CrashLoopBackOff`:** Использование `exec` для проверки переменных окружения и файловой системы.
*   **Анализ логов:** Использование `attach` для просмотра вывода процесса, который не пишет в файл.
*   **Передача конфигурации:** Использование `cp` для копирования конфигурационного файла в контейнер для тестирования.
