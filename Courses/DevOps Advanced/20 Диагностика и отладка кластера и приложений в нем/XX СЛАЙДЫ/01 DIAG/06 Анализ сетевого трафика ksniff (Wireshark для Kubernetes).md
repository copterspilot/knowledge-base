## [6] `kubectl debug` — отладка в `distroless` образах

**Содержимое слайда (для PowerPoint):**
-   **Заголовок:** `kubectl debug` — отладка в `distroless` образах
-   **Основной текст / список:**
    *   **Проблема:** В `distroless` образах нет оболочки (`sh`, `bash`), поэтому `kubectl exec` не работает.
    *   **Решение:** `kubectl debug` создает **ephemeral-контейнер** (временный) с отладочными инструментами.
    *   **Пример:**
        _bash
        # Создать ephemeral-контейнер с образом debug-tools
        kubectl debug my-app-pod-7d5b8c9c4-xl2v9 -it --image=debug-tools
        # Или использовать образ с busybox
        kubectl debug my-app-pod-7d5b8c9c4-xl2v9 -it --image=busybox --target=my-container
        _
    *   **Ключевая концепция:** Ephemeral Containers (временные контейнеры).
-   **Дополнительная информация (внизу):** "Отлаживайте даже самые 'чистые' образы без необходимости пересборки."

#### **Цель слайда**
Познакомить аудиторию с командой `kubectl debug`, которая решает критическую проблему отладки приложений, запущенных в `distroless` образах. Научить использовать ephemeral-контейнеры для диагностики.

#### **1. Описание визуального оформления**
Слайд должен контрастировать "старый" и "новый" подходы. Слева — изображение контейнера с красным крестом и `kubectl exec` (недоступно). Справа — тот же контейнер с зеленой галочкой и `kubectl debug`, создающим ephemeral-контейнер с инструментами. Внизу — ключевое сообщение о возможностях.

#### **2. Ключевые тезисы**
*   `distroless` образы повышают безопасность, но затрудняют отладку.
*   `kubectl debug` — это встроенный в `kubectl` способ создания временных контейнеров для диагностики.
*   Ephemeral Containers — это специальный тип контейнера, предназначенный исключительно для отладки.

#### **3. Описание для выступающего (речь)**
"Представьте, что ваше приложение падает, и вы пытаетесь войти в контейнер с помощью `kubectl exec`. Вы получаете ошибку 'executable file not found'. Почему? Потому что образ `distroless` не содержит `sh` или `bash`. Это хорошо для безопасности, но плохо для отладки. Решение — `kubectl debug`. Эта команда создает временный контейнер *внутри того же пода*, который имеет доступ к его процессам, сети и файловой системе. Как указано в `Muschko Benjamin - Certified Kubernetes Application Developer (CKAD) Study Guide`, умение работать с `kubectl debug` — это ключевой навык для CKA и CKAD."

#### **6. Типовые вопросы и ответы (Q&A):**
*   **В:** В чем разница между `kubectl debug` и обычным контейнером?
    *   **О:** Ephemeral Containers не перезапускаются, не участвуют в управлении жизненным циклом пода и предназначены только для отладки.
*   **В:** Нужно ли настраивать что-то на узле для `kubectl debug`?
    *   **О:** Нет, команда использует стандартный CRI (containerd, CRI-O). Однако, если используется `k8s.gcr.io/pause`, может потребоваться флаг `--set-image-pull-policy=IfNotPresent`.

#### **7. Примеры использования / Типовые сценарии**
*   **Диагностика `CrashLoopBackOff`:** Использование `kubectl debug` для проверки файловой системы и переменных окружения упавшего контейнера.
*   **Анализ сети:** Использование утилит в отладочном контейнере для проверки DNS и сетевых соединений.
