## [7] Анализ сетевого трафика: `ksniff` (Wireshark для Kubernetes)

**Содержимое слайда (для PowerPoint):**
-   **Заголовок:** Анализ сетевого трафика: `ksniff` (Wireshark для Kubernetes)
-   **Основной текст / список:**
    *   **Проблема:** Как посмотреть "на проводе" сетевой трафик, проходящий через под?
    *   **Решение:** `ksniff` — плагин для `kubectl`, который объединяет `tcpdump` и `Wireshark`.
    *   **Как это работает:**
        1.  `ksniff` разворачивает специальный отладочный контейнер в поде.
        2.  Запускает `tcpdump` для захвата пакетов.
        3.  Передает поток данных напрямую в локальный `Wireshark`.
    *   **Пример:**
        _bash
        # Захват трафика с пода и открытие в Wireshark
        kubectl sniff my-app-pod-7d5b8c9c4-xl2v9 -n default
        _
-   **Дополнительная информация (внизу):** "Видеть весь трафик — значит понимать всю проблему."

#### **1. Описание визуального оформления**
Слайд должен содержать крупный заголовок. Основной текст — в виде списка. В центре — скриншот Wireshark с захваченными пакетами из Kubernetes. Стрелки показывают поток: Под → tcpdump → Wireshark. Внизу — ключевое сообщение о глубине диагностики.

#### **2. Ключевые тезисы**
*   `ksniff` — это мост между миром Kubernetes и классическими сетевыми инструментами.
*   Он позволяет диагностировать проблемы на уровне сетевых пакетов (L3/L4).
*   Это незаменимый инструмент для анализа DNS-запросов, TCP-соединений и TLS-рукопожатий.

#### **3. Описание для выступающего (речь)**
"Представьте, что вы видите, что сервис не может подключиться к базе данных. Вы проверили `describe` и `logs`, но ответа нет. Что делать? Вам нужно заглянуть 'на провод'. Для этого есть `ksniff`. Это как `kubectl exec`, но вместо запуска команды он запускает `tcpdump` и передает захваченные пакеты напрямую в ваш локальный Wireshark. Вы можете увидеть, идет ли запрос DNS, устанавливается ли TCP-соединение, и завершается ли оно с ошибкой. Это один из самых эффективных способов диагностики сетевых проблем."

#### **6. Типовые вопросы и ответы (Q&A):**
*   **В:** Нужен ли Wireshark для `ksniff`?
    *   **О:** Да, `ksniff` напрямую взаимодействует с графическим интерфейсом Wireshark. Если его нет, можно использовать флаг `--to-file` для сохранения `.pcap` файла.
*   **В:** Безопасно ли использовать `ksniff` в production?
    *   **О:** С осторожностью. Захват трафика создает нагрузку. Используйте только для краткосрочной диагностики и фильтруйте трафик (например, `--interface eth0 --filter 'port 5432'`).

#### **7. Примеры использования / Типовые сценарии**
*   **Диагностика DNS:** Поиск причины, почему под не может разрешить имя `redis-service`.
*   **Анализ TCP-соединений:** Понимание, почему соединение с базой данных закрывается с `RST`.
*   **Отладка TLS:** Проверка, проходит ли TLS-рукопожатие.
