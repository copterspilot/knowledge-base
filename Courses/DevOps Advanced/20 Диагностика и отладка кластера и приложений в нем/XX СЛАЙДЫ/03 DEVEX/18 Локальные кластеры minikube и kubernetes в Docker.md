## [18] Локальные кластеры: `minikube` и `kubernetes в Docker`

**Содержимое слайда (для PowerPoint):**
-   **Заголовок:** Локальные кластеры: `minikube` и `kubernetes в Docker`
-   **Основной текст / список:**
    *   **`minikube`:**
        *   Создает полноценный одноконтроллерный кластер в виртуальной машине (или через Docker).
        *   Поддерживает большинство функций Kubernetes (CNI, Ingress, LoadBalancer).
        *   Идеален для обучения и тестирования.
    *   **`kubernetes в Docker` (Docker Desktop):**
        *   Встроенная опция в Docker Desktop для включения локального кластера.
        *   Очень быстрый запуск, интегрирован с Docker.
        *   Подходит для быстрой проверки манифестов и разработки.
    *   **Ключевое различие:** `minikube` — это инструмент для Kubernetes, `kubernetes в Docker` — это функция Docker.
-   **Дополнительная информация (внизу):** "Выбирайте инструмент в зависимости от ваших потребностей: полноценный кластер или быстрый старт."

#### **Цель слайда**
Познакомить аудиторию с двумя основными способами запуска локального кластера Kubernetes. Показать, как `minikube` и встроенная функция Docker Desktop могут использоваться для разработки и тестирования.

#### **1. Описание визуального оформления**
Слайд должен содержать две колонки: слева — `minikube` (иконка VM), справа — `kubernetes в Docker` (иконка Docker). Внизу — иконка "ноутбук" и ключевое сообщение о выборе. В центре слайда — схема: "Ваш компьютер" → `minikube` → "Полноценный кластер" и "Ваш компьютер" → "Docker Desktop" → "Интегрированный кластер".

#### **2. Ключевые тезисы**
*   Локальные кластеры — это основа для безопасной разработки и тестирования.
*   `minikube` предоставляет наиболее полное и настраиваемое окружение.
*   `kubernetes в Docker` предлагает самый быстрый и простой способ начать.

#### **3. Описание для выступающего (речь)**
"Чтобы разрабатывать и тестировать приложения для Kubernetes, вам не нужен доступ к production-кластеру. Вы можете запустить свой собственный локально. Два самых популярных способа — это `minikube` и встроенная функция Kubernetes в Docker Desktop. `minikube` создает полноценную виртуальную машину с кластером, что дает вам максимальную изоляцию и возможность настройки. Встроенная функция Docker Desktop, напротив, запускает компоненты Kubernetes как контейнеры на вашем хосте, что обеспечивает мгновенный запуск и тесную интеграцию с Docker. Как указано в `Burns B., Villalba E., Strebel D., Evenson L. - Kubernetes Best Practices`, локальная разработка — это лучший способ избежать проблем 'у меня работает'."

#### **4. Демо-сценарий (если уместен)**
*   **Демо:** Показать запуск `minikube start` и включение Kubernetes в Docker Desktop, а затем проверку `kubectl get nodes` в обоих случаях.

#### **6. Типовые вопросы и ответы (Q&A):**
*   **В:** Какой из них лучше?
    *   **О:** `minikube` лучше для обучения и тестирования сложных сценариев. `kubernetes в Docker` лучше для быстрой проверки манифестов и повседневной разработки.
*   **В:** Можно ли использовать `telepresence` с локальным кластером?
    *   **О:** Да, `telepresence` отлично работает с `minikube` и Docker Desktop.

#### **7. Примеры использования / Типовые сценарии**
*   **Обучение:** Изучение Kubernetes с нуля с помощью `minikube`.
*   **Разработка:** Быстрая проверка манифестов перед отправкой в Git.
*   **Тестирование:** Запуск интеграционных тестов в изолированной среде.
