## **Расширенный глоссарий: термины Kubernetes и их источники**

Этот глоссарий объединяет терминологию из всех предоставленных книг и курсов, предоставляя не только определения, но и ссылки на **точные источники знаний**.

---

### **A**

*   **AppArmor (Профили безопасности приложений):** Система Mandatory Access Control (MAC) в Linux, которая позволяет ограничивать возможности процессов (например, контейнеров) с помощью профилей. Используется для повышения безопасности.
    *   **Источник:** `Kubernetes Изнутри` (стр. 310)

*   **Argo CD:** Популярный инструмент с открытым исходным кодом для реализации практики GitOps, который автоматически синхронизирует состояние кластера Kubernetes с манифестами, хранящимися в системе контроля версий.

*   **Authn и Authz (Аутентификация и Авторизация):** Два основных компонента системы безопасности Kubernetes. **Authn** (Authentication) определяет, кто вы. **Authz** (Authorization) определяет, что вы можете делать.
    *   **Источник:** `Kubernetes Изнутри` (стр. 327)

*   **Автомасштабирование (Auto-scaling):** Процесс автоматического изменения количества ресурсов (например, подов или узлов) в зависимости от нагрузки.
    *   **Источник:** `Kubernetes на практике` (стр. 409)

*   **Аутентификация (Authentication):** Процесс проверки подлинности пользователя или сервиса, пытающегося получить доступ к кластеру Kubernetes.
    *   **Источник:** `Kubernetes на практике` (стр. 293)

*   **Авторизация (Authorization):** Процесс определения того, разрешено ли аутентифицированному пользователю или сервису выполнять определенное действие в кластере.
    *   **Источник:** `Kubernetes на практике` (стр. 293)

### **C**

*   **Calico:** Один из самых популярных CNI-провайдеров, который использует BGP для маршрутизации и iptables для реализации сетевых политик. Обеспечивает высокую производительность и безопасность.
    *   **Источник:** `Kubernetes Изнутри` (стр. 142), `Kubernetes и сети` (стр. 80)

*   **Ceph:** Распределенная система хранения с открытым исходным кодом, которая может использоваться для предоставления хранилища в кластерах Kubernetes через Rook.
    *   **Источник:** `DevOps Advanced` (тема 1)

*   **CKA (Certified Kubernetes Administrator):** Профессиональная сертификация от Linux Foundation, подтверждающая глубокие знания по администрированию и управлению кластерами Kubernetes.

*   **CKAD (Certified Kubernetes Application Developer):** Профессиональная сертификация от Linux Foundation, подтверждающая навыки разработки и развертывания приложений в Kubernetes.

*   **CNCF (Cloud Native Computing Foundation):** Фонд, поддерживающий развитие и популяризацию облачных нативных технологий, включая Kubernetes. Является домом для множества проектов (например, Prometheus, Envoy, Cilium).

*   **ConfigMap:** Объект Kubernetes для хранения неконфиденциальных данных в виде пар ключ-значение. Используется для конфигурации приложений.
    *   **Источник:** `Kubernetes Изнутри` (стр. 355)

*   **Containerd:** Стандартный CRI-совместимый runtime для запуска контейнеров в Kubernetes. Отвечает за управление жизненным циклом контейнера.
    *   **Источник:** `Бранд А., Ландер Р., Россо Д., Харрис Д. - Kubernetes на практике - 2022` (стр. 94)

*   **control plane (Плоскость управления):** Набор компонентов, которые управляют кластером Kubernetes: API-сервер, etcd, kube-scheduler, kube-controller-manager. Это "мозг" кластера.
    *   **Источник:** `Бранд А., Ландер Р., Россо Д., Харрис Д. - Kubernetes на практике - 2022` (стр. 43)

*   **CoreDNS:** Сервис DNS по умолчанию в Kubernetes. Предоставляет службу разрешения имен для сервисов и подов.
    *   **Источник:** `Бранд А., Ландер Р., Россо Д., Харрис Д. - Kubernetes на практике - 2022` (стр. 168)

*   **CrashLoopBackOff:** Состояние пода, при котором контейнер запускается, немедленно падает (crashes), и Kubernetes входит в цикл перезапуска с экспоненциально возрастающей задержкой (back-off).

### **D**

*   **DevEx (Developer Experience):** Набор практик, инструментов и культуры, направленных на улучшение удобства, скорости и удовлетворенности разработчиков при работе с платформой Kubernetes.

*   **Distroless образ:** Docker-образ, содержащий только приложение и его зависимости, но не включающий полноценной операционной системы (например, нет `sh`, `bash`, `curl`). Цель — минимизация поверхности атаки.

*   **Docker Engine:** Традиционный контейнерный runtime, который был заменен на containerd в современных кластерах Kubernetes.
    *   **Источник:** `Бранд А., Ландер Р., Россо Д., Харрис Д. - Kubernetes на практике - 2022` (стр. 93)

*   **Динамическое выделение хранилищ (Dynamic Provisioning):** Процесс автоматического создания PersistentVolume (PV) при создании PersistentVolumeClaim (PVC), на основе StorageClass.
    *   **Источник:** `DevOps Advanced` (тема 1)

### **E**

*   **eBPF (extended Berkeley Packet Filter):** Технология ядра Linux, позволяющая безопасно и эффективно запускать программы в пространстве ядра для мониторинга, фильтрации сети, профилирования производительности и безопасности без изменения исходного кода ядра.
    *   **Источник:** `Бранд А., Ландер Р., Россо Д., Харрис Д. - Kubernetes на практике - 2022` (стр. 140), `Kubernetes и сети` (стр. 87)

*   **etcd:** Распределенная, отказоустойчивая система хранения ключ-значение, которая служит "единственным источником истины" для всех данных конфигурации кластера Kubernetes.
    *   **Источник:** `Бранд А., Ландер Р., Россо Д., Харрис Д. - Kubernetes на практике - 2022` (стр. 47), `Kubernetes Изнутри` (стр. 258)

### **H**

*   **Helm:** Менеджер пакетов для Kubernetes, который позволяет упаковывать, версионировать, развертывать и обновлять сложные приложения с помощью шаблонов (чартов).

*   **Helm Chart (Чарт Helm):** Пакет, содержащий все необходимые ресурсы Kubernetes для развертывания приложения. Аналогичен "установочному пакету" для ОС.
    *   **Источник:** `Salatino M. - Platform Engineering on Kubernetes - 2024` (стр. 74)

*   **hostPath:** Тип тома, который монтирует файл или директорию с узла (хоста) в под. Используется в основном для разработки или специфических задач демона.
    *   **Источник:** `Kubernetes Изнутри` (стр. 214)

*   **HTTP headers (HTTP-заголовки):** Заголовки запросов и ответов HTTP, которые могут использоваться для маршрутизации трафика в Service Mesh.
    *   **Источник:** `Salatino M. - Platform Engineering on Kubernetes - 2024` (стр. 226)

### **I**

*   **ImagePullSecret:** Объект Kubernetes, который содержит учетные данные для доступа к приватным реестрам образов.
    *   **Источник:** `Kubernetes Изнутри` (стр. 240)

*   **Ingress:** Объект Kubernetes, который управляет доступом к сервисам извне кластера, обычно по HTTP/HTTPS. Часто используется для балансировки нагрузки и терминации TLS.

*   **Ingress Controller:** Компонент, который реализует функциональность Ingress (например, NGINX, Traefik). Он отслеживает объекты Ingress и настраивает реальный балансировщик нагрузки.

*   **init контейнер (Init Container):** Специальный контейнер, который запускается и завершается до запуска основных контейнеров в поде. Используется для подготовки окружения.
    *   **Источник:** `Kubernetes Изнутри` (стр. 119)

*   **Inspektor-gadget:** Набор инструментов с открытым исходным кодом, основанный на eBPF, для диагностики и мониторинга в кластерах Kubernetes. Позволяет трассировать системные вызовы, сеть, файловую систему и процессы.

*   **IOPS (Input/Output Operations Per Second):** Метрика, измеряющая производительность хранилища по количеству операций ввода-вывода в секунду.
    *   **Источник:** `Kannaiah Govardhana - Kubernetes Anti-Patterns - 2024` (стр. 88)

### **K**

*   **KCNA (Kubernetes and Cloud Native Associate):** Вводная сертификация от Linux Foundation, подтверждающая базовое понимание экосистемы Kubernetes и облачных нативных технологий.
    *   **Источник:** `Sanchez Adrian, Valenzuela Jorge - Kubernetes and Cloud Native Associate (KCNA) Study Guide - 2024` (название)

*   **kubectl:** Основной CLI-инструмент для взаимодействия с кластером Kubernetes. Позволяет управлять ресурсами, просматривать состояние и диагностировать проблемы.

*   **krew:** Официальный менеджер плагинов для `kubectl`. Позволяет легко устанавливать, обновлять и управлять сторонними плагинами.

*   **k9s:** Текстовый пользовательский интерфейс (TUI) для Kubernetes, работающий в терминале. Предоставляет удобную навигацию по ресурсам, просмотр логов и выполнение команд.

*   **kube-bench:** Инструмент для аудита безопасности кластера Kubernetes в соответствии с рекомендациями CIS (Center for Internet Security).

*   **kubeconfig:** Файл конфигурации, который `kubectl` использует для подключения к одному или нескольким кластерам Kubernetes. Содержит информацию о серверах, пользователях и контекстах.

*   **kubelet:** Агент, который работает на каждой ноде (узле) кластера. Отвечает за запуск и управление подами, а также за взаимодействие с control plane.
    *   **Источник:** `Kubernetes Изнутри` (стр. 268)

*   **kubeadm:** Инструмент, предназначенный для быстрого и стандартизированного развертывания production-готовых кластеров Kubernetes.

*   **KubeVirt:** Проект с открытым исходным кодом, позволяющий запускать виртуальные машины (VM) как поды в кластере Kubernetes.

*   **K3s:** Легковесная, сертифицированная дистрибуция Kubernetes, оптимизированная для edge-устройств, IoT и сред с ограниченными ресурсами.

*   **KubeEdge:** Платформа для управления edge-устройствами и приложениями на них с помощью Kubernetes.

*   **KubeVirt:** Проект с открытым исходным кодом, позволяющий запускать виртуальные машины (VM) как поды в кластере Kubernetes.

### **L**

*   **Lens:** Графическая IDE (Integrated Development Environment) для Kubernetes. Позволяет управлять несколькими кластерами одновременно, просматривать ресурсы, логи, события и терминалы в едином интерфейсе.

*   **Лог (Log):** Запись событий, генерируемых приложением или системой. Ключевой источник информации для диагностики проблем.

*   **Label (Метка):** Пара ключ-значение, которая присоединяется к объектам Kubernetes (например, подам) для организации и выборки.
    *   **Источник:** `Kubernetes Изнутри` (стр. 355)

### **M**

*   **Manifest (Манифест):** Файл (обычно YAML или JSON), который описывает желаемое состояние ресурса Kubernetes (например, Deployment, Service).

*   **minikube:** Инструмент для запуска однодоменного локального кластера Kubernetes на одной виртуальной машине или в контейнере. Идеален для обучения и разработки.

*   **Mount (Монтирование):** Процесс подключения тома (volume) к файловой системе контейнера.
    *   **Источник:** `Kubernetes Изнутри` (стр. 70)

### **N**

*   **Namespace (Пространство имен):** Механизм в Kubernetes для логического разделения ресурсов в рамках одного физического кластера. Позволяет изолировать проекты, команды или среды (dev, stage, prod).

*   **Node (Нода / Узел):** Физическая или виртуальная машина, которая является рабочей станцией в кластере Kubernetes. На нодах запускаются поды.

*   **NetworkPolicy (Сетевая политика):** Объект Kubernetes, который определяет правила для входящего (ingress) и исходящего (egress) трафика между подами.

### **O**

*   **OOMKilled (Out of Memory Killed):** Причина завершения контейнера, означающая, что он был убит системой из-за превышения установленного лимита памяти (`resources.limits.memory`).

*   **Operator:** Паттерн проектирования и тип пользовательского ресурса (CRD), который позволяет инкапсулировать знания по управлению сложным приложением (например, базой данных) в виде контроллера.

### **P**

*   **Pod:** Наименьшая и основная развертываемая единица в Kubernetes. Может содержать один или несколько тесно связанных контейнеров, которые разделяют сеть и хранилище.

*   **Port-Forwarding (Перенаправление портов):** Техника, позволяющая локально получить доступ к порту в поде, как если бы он был запущен на вашей машине. Полезна для отладки.

*   **PersistentVolume (PV):** Объект, представляющий кусок хранилища в кластере (например, диск в облаке). Обычно создается администратором.

*   **PersistentVolumeClaim (PVC):** Объект, создаваемый пользователем для запроса определенного объема хранилища. PVC привязывается к PV.

*   **Probe (Проба):** Механизм проверки состояния пода. Включает:
    *   **livenessProbe:** Проверяет, "живо" ли приложение. Если пробы не проходят, под перезапускается.
    *   **readinessProbe:** Проверяет, готово ли приложение принимать трафик. Если пробы не проходят, под удаляется из пула балансировщика нагрузки.

*   **Production (Продакшен):** Основная рабочая среда, в которой работают реальные пользователи.

### **R**

*   **RBAC (Role-Based Access Control):** Механизм управления доступом в Kubernetes, основанный на ролях. Позволяет определять, какие действия могут выполнять пользователи, группы или сервисные аккаунты.

*   **ReadinessProbe:** См. Probe.
*   **ReplicaSet:** Объект, который гарантирует наличие заданного количества реплик пода. Обычно управляется через Deployment.

*   **Resource (Ресурс):** Любой объект в Kubernetes: Pod, Service, Deployment, ConfigMap и т.д.

*   **Rollout:** Процесс обновления приложения (например, изменение образа контейнера), при котором Kubernetes постепенно заменяет старые поды на новые.

### **S**

*   **Secret:** Объект Kubernetes для хранения конфиденциальных данных, таких как пароли, токены и ключи. Данные в Secret шифруются при хранении (в etcd).

*   **Service:** Объект Kubernetes, который предоставляет стабильный IP-адрес и DNS-имя для набора подов. Делает приложения доступными для других компонентов.

*   **Service Mesh:** Архитектурный паттерн, который добавляет инфраструктурный уровень для управления сервис-ту-сервис взаимодействием. Обеспечивает функции, такие как mTLS, балансировка нагрузки, трассировка, политики доступа. Примеры: Istio, Linkerd.

*   **Skaffold:** Инструмент с открытым исходным кодом для упрощения разработки приложений в Kubernetes. Автоматизирует сборку, развертывание и отладку.

*   **Sidecar:** Паттерн проектирования, при котором в один Pod добавляется дополнительный контейнер для предоставления вспомогательных функций (например, прокси-сервер в Service Mesh).

*   **Staging (Stage):** Тестовая среда, максимально приближенная к продакшену, используемая для финального тестирования перед релизом.

*   **stern:** CLI-инструмент для агрегации и цветного отображения логов нескольких подов одновременно. Очень полезен для мониторинга сервисов с множеством реплик.

*   **StorageClass:** Объект Kubernetes, который определяет "класс" хранилища (например, "fast-ssd", "slow-hdd") и позволяет использовать динамическое выделение PV.

### **T**

*   **Taint (Загрязнение):** Механизм, который позволяет "отталкивать" поды от определенных нод, если они не имеют соответствующего Toleration.

*   **Toleration (Толерантность):** Настройка пода, которая позволяет ему запускаться на нодах с определенными Taints.

*   **TUI (Text-based User Interface):** Текстовый пользовательский интерфейс, работающий в терминале (например, `k9s`).

*   **Telepresence:** Инструмент для разработчиков, который позволяет локально запущенному процессу подключаться к кластеру Kubernetes, как будто он работает внутри него. Решает проблему "расхождения сред".

### **V**

*   **Volume (Том):** Объект, представляющий хранилище, которое может быть примонтировано в контейнер. Может быть временным (emptyDir) или постоянным (PersistentVolume).
    *   **Источник:** `Kubernetes Изнутри` (стр. 219)

### **W**

*   **Watch (Наблюдение):** Механизм в Kubernetes API, который позволяет клиентам получать поток событий о изменениях в ресурсах в реальном времени.
    *   **Источник:** `Kubernetes Изнутри` (стр. 355)
