## **Инструкция: Поиск ошибок до `Deploy` (Pre-Deployment Checks)**

Этот чек-лист поможет вам найти и устранить ошибки в манифестах Kubernetes **до того**, как вы примените их к кластеру, что сэкономит время и предотвратит сбои в production.

---

### **1. Статическая проверка YAML-синтаксиса**

Первый шаг — убедиться, что ваш YAML-файл вообще валиден.

*   **Команда:**
    ```bash
    # Проверить синтаксис YAML
    yamllint манифест.yaml

    # Проверить синтаксис JSON
    jsonlint манифест.json
    ```
*   **Цель:** Найти опечатки, неправильные отступы, пропущенные кавычки.

---

### **2. Валидация схемы Kubernetes**

Проверьте, соответствует ли ваш манифест схеме API Kubernetes.

*   **Инструменты:**
    *   **`kubeval`:** Проверяет YAML на соответствие официальным схемам OpenAPI.
        ```bash
        kubeval манифест.yaml
        ```
    *   **`kubectl apply --dry-run=client`:** Использует локальную копию схемы API для проверки.
        ```bash
        kubectl apply -f манифест.yaml --dry-run=client
        ```
*   **Цель:** Обнаружить ошибки в названиях полей, неправильные типы данных, отсутствующие обязательные поля.
*   **Источник:** `Kannaiah Govardhana - Kubernetes Anti-Patterns - 2024`.

---

### **3. Проверка best practices и anti-patterns**

Найдите распространенные ошибки и антипаттерны, которые могут привести к проблемам в будущем.

*   **Инструменты:**
    *   **`kube-score`:** Анализирует манифесты на наличие анти-паттернов (отсутствие `resources`, `readinessProbe`, `securityContext`).
        ```bash
        kube-score score манифест.yaml
        ```
    *   **`polaris`:** Похож на `kube-score`, но более настраиваемый, использует YAML-правила.
        ```bash
        polaris audit -f манифест.yaml
        ```
    *   **`conftest`:** Позволяет писать собственные политики на языке Rego для проверки любых аспектов манифеста (например, "все образы должны быть из `registry.company.com`").
        ```bash
        conftest test манифест.yaml
        ```
*   **Цель:** Убедиться, что манифест соответствует корпоративным стандартам и лучшим практикам.

---

### **4. Сканирование образов на уязвимости**

Проверьте Docker-образы, указанные в манифесте, на наличие известных уязвимостей.

*   **Инструменты:**
    *   **`Trivy`:** Стандарт де-факто для сканирования образов, файлов и конфигураций.
        ```bash
        trivy image имя_образа:тег
        ```
    *   **`Grype`:** Альтернатива Trivy, также очень популярна.
        ```bash
        grype имя_образа:тег
        ```
*   **Цель:** Найти CVE (Common Vulnerabilities and Exposures) в базовом образе и зависимостях приложения.

---

### **5. Проверка конфигурации безопасности**

Убедитесь, что ваш манифест не нарушает политики безопасности.

*   **Инструменты:**
    *   **`Checkov`:** Проверяет манифесты на соответствие политикам безопасности (например, запрет привилегированных контейнеров, требование `readOnlyRootFilesystem`).
        ```bash
        checkov -f манифест.yaml
        ```
    *   **`kube-bench`:** Проверяет, соответствует ли сам кластер рекомендациям CIS (Center for Internet Security). Это не проверка манифеста, но важно знать, что кластер безопасен.
        ```bash
        kube-bench run --targets node
        ```
*   **Цель:** Обеспечить соответствие требованиям безопасности и compliance.

---

### **6. Проверка переменных окружения и секретов**

Убедитесь, что вы не храните конфиденциальные данные в манифестах.

*   **Действия:**
    *   Найдите в манифесте строки вроде `password:`, `token:`, `key:`.
    *   Убедитесь, что такие данные передаются через `Secret` или `ConfigMap`, а не в открытом виде.
    *   Используйте `git-secrets` или `gitleaks` для поиска секретов в коде перед коммитом.
        ```bash
        gitleaks detect --source . --no-git
        ```
*   **Цель:** Предотвратить утечку паролей и токенов.

---

### **Итоговый чек-лист (для интеграции в CI/CD):**

| Шаг                        | Инструмент              | Команда                          |
|:-------------------------- |:----------------------- |:-------------------------------- |
| 1. Проверка синтаксиса     | `yamllint`              | `yamllint *.yaml`                |
| 2. Валидация схемы         | `kubeval` / `--dry-run` | `kubeval манифест.yaml`          |
| 3. Проверка best practices | `kube-score`            | `kube-score score манифест.yaml` |
| 4. Сканирование образов    | `Trivy`                 | `trivy image nginx:latest`       |
| 5. Проверка безопасности   | `Checkov`               | `checkov -d .`                   |
| 6. Поиск секретов          | `gitleaks`              | `gitleaks detect`                |

Выполняя эти шаги **до** `kubectl apply`, вы значительно повышаете надежность и безопасность своих развертываний.
