**1. Визуальный ряд**
*   Скриншот терминала: `kubectl debug my-pod-7d5b8c9c4-xl2v9 -it --image=nicolaka/netshoot -- sh`.
*   Логотип `kubectl`.
*   Иконки: контейнер, отладчик (жучок).

**2. Демо-сценарий (если уместен)**
*   Показать в реальном времени команду `kubectl debug` для запуска отладочного контейнера и выполнения команды `ps aux`.

**3. Ключевые тезисы**
*   `kubectl debug` — это встроенная команда для запуска временных (ephemeral) контейнеров.
*   Он решает проблему отладки в контейнерах без стандартных инструментов (`scratch`, `distroless`).
*   Не требует установки отдельного плагина.

**4. Описание (для выступающего)**
*   **Цель слайда:** Представить `kubectl debug` как современный, встроенный инструмент для отладки, заменивший сторонние решения.
*   **Ключевое сообщение:** Это не плагин, а часть ядра Kubernetes, который должен быть в арсенале каждого инженера.
*   **Основные тезисы:**
    *   **Встроенная функция:** В 2025 году функциональность ephemeral containers является стабильной и встроена в `kubectl`. Это означает, что для использования `kubectl debug` больше не нужно устанавливать отдельный плагин.
    *   **Принцип работы:** Команда запускает временный контейнер (например, `nicolaka/netshoot`) внутри пода, предоставляя доступ к полноценному набору сетевых и диагностических утилит (`tcpdump`, `strace`, `nslookup`).
    *   **Преимущества:** Позволяет диагностировать проблемы в минимальных образах, где отсутствуют `sh`, `bash`, `curl`. Это решает ключевую боль, упомянутую в чате ("если у нас так называемый минимальный образ, там никаких шеллов, ничего нам не будет").
*   **Связь с источниками:** Тезисы основаны на PDF 2019 года (слайды 5.1, 5.2, 5.3), субтитрах (00:13:10 - 00:14:08) и чате (вопросы о `debug`).

**6. Типовые вопросы и ответы (Q&A)**
*   **В:** Работает ли `kubectl debug` с containerd/CRI-O?
    *   **О:** Да, в 2025 году `kubectl debug` (ephemeral containers) поддерживает различные CRI, включая containerd и CRI-O. Процесс установки и интеграции значительно упростился по сравнению с 2019 годом.
*   **В:** Безопасен ли `kubectl debug`?
    *   **О:** Да, если правильно настроены RBAC. Вы можете создать роли, разрешающие `debug` только определенным пользователям или только для определенных namespace'ов.
*   **В:** Какие образы лучше использовать для отладки?
    *   **О:** Самые популярные — `nicolaka/netshoot` и `praqma/network-multitool`. Они содержат полный набор утилит для диагностики.

**7. Примеры использования / Типовые сценарии**
*   **Диагностика `CrashLoopBackOff`:** Использовать `kubectl debug` для запуска `strace` на процессе приложения и выявления проблем с открытием файлов или сетевыми вызовами.
*   **Анализ сети:** Использовать `kubectl debug` для запуска `tcpdump` внутри пода, чтобы захватить трафик.
*   **Проверка конфигурации:** Использовать `kubectl debug` для доступа к файлам внутри контейнера и проверки их содержимого.

**8. Предложения по дополнительному контенту слайда**
