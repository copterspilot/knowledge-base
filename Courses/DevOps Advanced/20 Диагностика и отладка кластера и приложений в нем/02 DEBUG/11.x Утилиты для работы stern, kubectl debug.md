**1. Визуальный ряд**
*   Логотип `stern`.
*   Скриншот терминала: `stern --all-namespaces web` (агрегированные цветные логи нескольких подов).
*   Логотип `kubectl debug`.
*   Скриншот терминала: `kubectl debug my-pod-7d5b8c9c4-xl2v9 -it --image=nicolaka/netshoot -- sh`.
*   Иконки: журнал (логи), отладчик (жучок), контейнер.

**2. Демо-сценарий (если уместен)**
*   Показать в реальном времени команду `stern` для агрегации логов всех подов с меткой `app=web` из нескольких namespace'ов.
*   Показать в реальном времени команду `kubectl debug` для запуска ephemeral container'а с образом `nicolaka/netshoot` и выполнения команды `tcpdump` или `strace`.

**3. Ключевые тезисы**
*   `stern` — мощный инструмент для агрегации и фильтрации логов нескольких подов.
*   `kubectl debug` — решение для отладки в контейнерах без стандартных инструментов (`scratch`, `distroless`).
*   `kubectl debug` использует концепцию ephemeral containers, которая в 2025 году является стабильной.

**4. Описание (для выступающего)**
*   **Цель слайда:** Представить два специализированных инструмента, которые значительно упрощают повседневную работу с кластером.
*   **Ключевое сообщение:** Эти утилиты решают самые болезненные проблемы: агрегацию логов и отладку в минимальных образах.
*   **Основные тезисы:**
    *   **`stern`:** Расширяет `kubectl logs`, позволяя агрегировать логи из нескольких подов, namespace'ов и фильтровать их по регулярным выражениям. Вывод цветной, что делает его легко читаемым. *(Из субтитров 2019: "Селектор позволяет выбрать логи со всех подов, с определенными лейблами")*.
    *   **`kubectl debug`:** Плагин, который запускает временный (ephemeral) контейнер внутри пода для отладки. Это критически важно, когда в основном контейнере нет `sh`, `bash`, `tcpdump` или `strace`. Позволяет использовать полнофункциональные образы отладки (например, `nicolaka/netshoot`). *(Из PDF 2019, слайд 5.1)*.
    *   В 2025 году функциональность `kubectl debug` стала стабильной частью Kubernetes (Ephemeral Containers), и его использование стало стандартной практикой.
*   **Связь с источниками:** Тезисы основаны на PDF 2019 года (слайды 5.1, 5.3, 5.5), субтитрах (00:11:15 - 00:13:54) и чате (вопросы о `debug`).

**6. Типовые вопросы и ответы (Q&A)**
*   **В:** Работает ли `kubectl debug` с containerd/CRI-O?
    *   **О:** Да, в 2025 году `kubectl debug` (ephemeral containers) поддерживает различные CRI, включая containerd и CRI-O. Процесс установки и интеграции значительно упростился по сравнению с 2019 годом.
*   **В:** Безопасен ли `kubectl debug`?
    *   **О:** Да, если правильно настроены RBAC. Вы можете создать роли, разрешающие `debug` только определенным пользователям или только для определенных namespace'ов.
*   **В:** Чем `stern` лучше `kubectl logs -l app=web --all-namespaces`?
    *   **О:** `stern` предлагает цветной вывод, более гибкую фильтрацию (по регулярным выражениям), возможность игнорировать строки и более удобный интерфейс для мониторинга нескольких потоков логов одновременно.

**7. Примеры использования / Типовые сценарии**
*   **Мониторинг:** Использовать `stern` для наблюдения за логами всех сервисов в production во время деплоя.
*   **Диагностика `CrashLoopBackOff`:** Использовать `kubectl debug` для запуска `strace` на процессе приложения и выявления проблем с открытием файлов или сетевыми вызовами.
*   **Анализ сети:** Использовать `kubectl debug` для запуска `tcpdump` внутри пода, чтобы захватить трафик.
