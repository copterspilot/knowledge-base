eBPF и Inspektor-Gadget: глубинная диагностика ядра

**1. Визуальный ряд**
*   Логотип `Inspektor-Gadget`.
*   Скриншот терминала: `kubectl gadget trace open -n my-app`.
*   Скриншот терминала: `kubectl gadget trace network -n my-app`.
*   Скриншот терминала: `kubectl gadget top tcp`.
*   Иконки: eBPF, лупа, ядро Linux.

**2. Демо-сценарий (если уместен)**
*   Показать в реальном времени команду `kubectl gadget trace open` для отслеживания файлов, открываемых приложением в поде.

**3. Ключевые тезисы**
*   `inspektor-gadget` — набор инструментов на основе eBPF для глубокой интроспекции на уровне ядра.
*   eBPF позволяет безопасно вмешиваться в работу ядра для наблюдаемости и безопасности.
*   Инструменты `inspektor-gadget` предоставляют "суперсилы" для диагностики сложных проблем.

**4. Описание (для выступающего)**
*   **Цель слайда:** Дать глубокое понимание возможностей `inspektor-gadget` и технологии eBPF.
*   **Ключевое сообщение:** `inspektor-gadget` позволяет видеть то, что невозможно увидеть с помощью стандартных команд `kubectl`.
*   **Основные тезисы:**
    *   **eBPF (extended Berkeley Packet Filter):** Это технология, позволяющая запускать безопасный код в пространстве ядра Linux без необходимости изменения исходного кода ядра. Это основа для многих современных инструментов наблюдаемости и безопасности.
    *   **`inspektor-gadget`:** Это проект от Kinvolk, который предоставляет набор CLI-инструментов, использующих eBPF для трейсинга. Основные команды:
        *   `trace open`: Отслеживает системные вызовы `open`, `openat` для просмотра открываемых файлов.
        *   `trace network`: Отслеживает сетевые вызовы (создание сокетов, подключения).
        *   `top tcp`: Показывает самые активные TCP-соединения.
        *   `top files`: Показывает самые часто открываемые файлы.
    *   Эти инструменты позволяют диагностировать проблемы, связанные с доступом к файлам, сетевыми задержками, потреблением ресурсов, которые невидимы для стандартных методов.

**6. Типовые вопросы и ответы (Q&A)**
*   **В:** Нужно ли компилировать код на eBPF?
    *   **О:** Нет. `inspektor-gadget` предоставляет готовые программы на eBPF. Вам нужно только использовать CLI-команды.
*   **В:** Можно ли использовать `inspektor-gadget` в managed-кластерах (GKE, EKS)?
    *   **О:** Это зависит от провайдера. Некоторые ограничивают права, но многие современные managed-сервисы начинают поддерживать eBPF.
*   **В:** В чем разница между `inspektor-gadget` и `kubectl debug` с `strace`?
    *   **О:** `inspektor-gadget` использует eBPF, что позволяет трейсить системные вызовы на уровне ядра, не запуская `strace` внутри контейнера. Это более эффективно и работает даже с минимальными образами.

**7. Примеры использования / Типовые сценарии**
*   **Диагностика `CrashLoopBackOff`:** Использование `trace open` для выявления попыток открыть несуществующий файл конфигурации.
*   **Анализ сетевых проблем:** Использование `trace network` для отслеживания попыток подключения к недоступному сервису.
*   **Поиск утечек ресурсов:** Использование `top tcp` для выявления большого количества открытых соединений.
