3. **Ключевые тезисы**
    - **Локальная разработка vs. кластер**:
        - Разработка на локальной машине **отличается** от работы в кластере.
        - Проблемы с **сетевыми настройками**, зависимостями и конфигурацией.
    - **Облачные API и ресурсы**:
        - Локально сложно **эмулировать облачные сервисы** (например, AWS S3, GCP Pub/Sub).
        - Проблемы с **безопасностью** и доступом к ресурсам.
    - **Тестирование распределённых систем**:
        - Сложно тестировать **взаимодействие между микросервисами**.
        - Проблемы с **сетевыми задержками** и распределёнными транзакциями.
    - **Нехватка ресурсов**:
        - Локальная машина может **не вытянуть** все микросервисы.
        - Проблемы с **памятью и CPU** при запуске множества контейнеров.

---

4. **Описание (для выступающего)**
    - Разработка в Kubernetes **сложнее**, чем в традиционных окружениях.
    - Основные проблемы связаны с **разницей между локальным и кластерным окружением**.
    - Важно объяснить, что **облачные зависимости** могут блокировать локальную разработку.
    - Подчеркнуть, что **тестирование распределённых систем** требует специальных инструментов.
    - Упомянуть, что **нехватка ресурсов** — это типичная проблема при разработке микросервисов.

5. **Связь с прошлыми материалами**
    - В презентации 2019 года обсуждались проблемы локальной разработки и зависимости от облачных API.
    - В чате поднимались вопросы о **тестировании распределённых систем** и нехватке ресурсов.

        - _"Что делать, если на ноутбуке не хватает памяти для всех контейнеров?"_ → Использовать удалённые кластеры или оптимизировать ресурсы.

6. **Типовые вопросы и ответы (Q&A)**
    - **Вопрос:** _"Как эмулировать облачные сервисы локально?"_ **Ответ:** Использовать инструменты вроде `LocalStack` для AWS или `Minikube` с добавлением.
    - **Вопрос:** _"Как тестировать взаимодействие между микросервисами?"_ **Ответ:** Использовать `Telepresence` или `Istio` для локальной отладки.
    - **Вопрос:** _"Что делать, если микросервисы не помещаются на локальную машину?"_ **Ответ:** Использовать удалённые кластеры или инструменты вроде `Tilt` для оптимизации ресурсов.

7. **Примеры использования / Типовые сценарии**
    - **Сценарий 1:** Разработчик не может протестировать взаимодействие с облачным API. Использует `LocalStack` для эмуляции.
    - **Сценарий 2:** Микросервисы не помещаются на локальную машину. Использует `Telepresence` для подключения к удалённому кластеру.
    - **Сценарий 3:** Нужно протестировать сетевые задержки. Использует `Istio` для симуляции проблем сети.
