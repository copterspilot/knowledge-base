**Продвинутые утилиты: `stern` и `kubectl debug` для диагностики и отладки**

---

#### **Описание слайда**

1. **Визуальный ряд**
    - **Логотипы инструментов**: `stern` и `kubectl debug`.
    - **Скриншоты вывода команд**:
        - Пример работы `stern` с цветным выводом логов нескольких подов.
        - Пример запуска `kubectl debug` с созданием отладочного контейнера.
    - **Схемы использования**:
        - Для `stern`: агрегация логов из нескольких подов в реальном времени.
        - Для `kubectl debug`: добавление временного контейнера в под для отладки.
    - **Иконки**:
        - 📜 — для `stern` (агрегация логов).
        - 🐛 — для `kubectl debug` (отладка).
    - **Фон**: Тёмный с акцентом на терминальный вывод.

---

2. **Демо-сценарий** Показать **живые примеры**:
    - Установить `stern` через `krew` и запустить просмотр логов:
         ```
         kubectl stern <pod-selector> --tail 20
         ```
    - Использовать `kubectl debug` для создания отладочного контейнера в поде:
         ```
         kubectl debug -it <pod-name> --image=busybox --target=<container-name>
         ```

---

3. **Ключевые тезисы**
    - **`stern`**:
        - Позволяет **агрегировать логи** из нескольких подов в реальном времени.
        - Поддерживает **цветной вывод** и фильтрацию по времени (`--since`).
        - Удобен для **мониторинга распределённых приложений**.
    - **`kubectl debug`**:
        - Создаёт **временный отладочный контейнер** в существующем поде.
        - Позволяет **запускать инструменты отладки** (например, `curl`, `tcpdump`).
        - Поддерживает **разные режимы** (например, `--copy-to` для копирования пода).
    - Эти утилиты **расширяют возможности диагностики** и упрощают работу с кластером.

---

4. **Описание (для выступающего)**
    - **`stern`** решает проблему **разрозненных логов** в распределённых системах, предоставляя единый интерфейс для их просмотра.
    - **`kubectl debug`** позволяет **диагностировать проблемы внутри подов**, не изменяя их конфигурацию.
    - Важно объяснить, что `kubectl debug` **требует прав** на создание контейнеров в поде.
    - Подчеркнуть, что **отладочные контейнеры временные** и удаляются после завершения сессии.
    - Упомянуть, что `stern` **не заменяет полноценные системы логирования** (например, EFK), но удобен для быстрой диагностики.

        - _"Можно ли использовать `stern` для логов из разных namespace?"_ → Да, с флагом `--all-namespaces`.
        - _"Как отладить под, если в нём нет нужных инструментов?"_ → Использовать `kubectl debug` с образом, содержащим необходимые утилиты (например, `busybox` или `nicolaka/netshoot`).

---

6. **Типовые вопросы и ответы (Q&A)**
    - **Вопрос:** _"Как установить `stern`?"_ **Ответ:** Через `krew`: `kubectl krew install stern`.
    - **Вопрос:** _"Можно ли сохранить логи из `stern` в файл?"_ **Ответ:** Да: `kubectl stern <pod-selector> > logs.txt`.
    - **Вопрос:** _"Что делать, если `kubectl debug` не создаёт контейнер?"_ **Ответ:** Проверить права доступа и наличие ресурсов на узле.

7. **Примеры использования / Типовые сценарии**

    - **Сценарий 3:** Нужно проанализировать состояние файловой системы в поде. Создаём отладочный контейнер и проверяем файлы.
