2. **Демо-сценарий** Показать **живой пример** использования `kubectl`:
    - Запустить команду `kubectl get pods` для просмотра списка подов.
    - Использовать `kubectl describe pod <pod-name>` для анализа состояния пода.
    - Продемонстрировать просмотр логов с помощью `kubectl logs <pod-name> --tail=20`.

---

3. **Ключевые тезисы**
    - `kubectl` — **основной CLI-инструмент** для управления Kubernetes-кластером.
    - Позволяет выполнять **базовые и продвинутые операции**:
        - Получение информации о ресурсах (`get`, `describe`).
        - Просмотр логов (`logs`).
        - Взаимодействие с подами (`exec`, `cp`).
    - Поддерживает **расширения** через плагины (например, `krew`).
    - **Незаменим** для диагностики и отладки кластера.

---

4. **Описание (для выступающего)**
    - `kubectl` — это **первый инструмент**, с которым знакомятся администраторы Kubernetes.
    - Он позволяет **взаимодействовать с API кластера** и управлять ресурсами.
    - Важно подчеркнуть, что **даже в 2025 году** `kubectl` остаётся актуальным и активно развивается.
    - Упомянуть, что **большинство задач** по диагностике начинаются с использования `kubectl`.
    - Объяснить, что **команды `kubectl`** можно комбинировать для сложных сценариев (например, фильтрация выводов через `jq` или `grep`).

5. **Связь с прошлыми материалами**
    - В презентации 2019 года `kubectl` также рассматривался как основной инструмент.
    - В субтитрах и чате обсуждались **базовые команды** (`get`, `describe`, `logs`) и их применение.
    - Вопросы из чата:
        - _"Как быстро найти ошибку в поде?"_ → Использовать `kubectl describe pod` и `kubectl logs`.
        - _"Можно ли редактировать ресурсы напрямую через `kubectl`?"_ → Да, с помощью `kubectl edit`, но это **не рекомендуется** для продакшн-среды.

---

6. **Типовые вопросы и ответы (Q&A)**
    - **Вопрос:** _"Какие команды `kubectl` используются чаще всего?"_ **Ответ:** `get`, `describe`, `logs`, `exec`.
    - **Вопрос:** _"Можно ли автоматизировать выполнение команд `kubectl`?"_ **Ответ:** Да, с помощью скриптов (Bash, Python) или инструментов вроде `k9s`.
    - **Вопрос:** _"Что делать, если `kubectl` не подключается к кластеру?"_ **Ответ:** Проверить конфигурацию (`~/.kube/config`) и доступность API-сервера.

7. **Примеры использования / Типовые сценарии**
    - **Сценарий 1:** Под не запускается. Используем `kubectl describe pod` для анализа ошибок.
    - **Сценарий 2:** Нужно посмотреть логи приложения. Используем `kubectl logs <pod-name> --follow`.
    - **Сценарий 3:** Требуется запустить команду внутри пода. Используем `kubectl exec -it <pod-name> -- /bin/bash`.
