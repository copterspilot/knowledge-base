#### **Описание слайда**

1. **Визуальный ряд**
    - **Логотипы инструментов**: `ksniff` и `inspektor-gadget`.
    - **Скриншоты работы инструментов**:
        - Пример вывода `ksniff` с анализом сетевого трафика в Wireshark.
        - Пример работы `inspektor-gadget` с отображением системных вызовов и сетевых соединений.
    - **Схемы использования**:
        - Для `ksniff`: захват и анализ сетевого трафика в реальном времени.
        - Для `inspektor-gadget`: мониторинг системных вызовов и событий на уровне ядра с использованием eBPF.
    - **Иконки**:
        - 🌐 — для `ksniff` (сетевой трафик).
        - 🔍 — для `inspektor-gadget` (глубокая диагностика).
    - **Фон**: Тёмный с акцентом на технические детали.

---

2. **Демо-сценарий** Показать **живые примеры**:
    - Установить `ksniff` и запустить захват трафика для конкретного пода:
         ```
         kubectl sniff <pod-name> -n <namespace> -f "tcp port 80"
         ```
    - Использовать `inspektor-gadget` для мониторинга системных вызовов в поде:
         ```
         kubectl gadget trace exec <pod-name>
         ```

---

3. **Ключевые тезисы**
    - **`ksniff`**:
        - Позволяет **захватывать и анализировать сетевой трафик** в Kubernetes.
        - Использует **tcpdump** для захвата пакетов и отправляет их в **Wireshark** для анализа.
        - Поддерживает **фильтрацию трафика** по различным критериям (например, порт, IP-адрес).
    - **`inspektor-gadget`**:
        - Инструмент на основе **eBPF** для мониторинга системных вызовов, сетевых соединений и процессов.
        - Позволяет **отслеживать активность** на уровне ядра без значительных накладных расходов.
        - Поддерживает **различные гаджеты** для анализа (например, `trace exec`, `trace open`).
    - Эти инструменты **необходимы для сложных случаев**, когда стандартные команды не дают достаточно информации.

---

4. **Описание (для выступающего)**
    - **`ksniff`** решает проблему **анализа сетевого трафика** в Kubernetes, предоставляя удобный интерфейс для захвата и визуализации пакетов.
    - **`inspektor-gadget`** позволяет **глубоко анализировать системные вызовы и события**, что полезно для диагностики проблем на уровне ОС.
    - Важно объяснить, что **оба инструмента требуют прав** на выполнение привилегированных операций в кластере.
    - Подчеркнуть, что **`ksniff` и `inspektor-gadget`** могут быть **ресурсоёмкими** и должны использоваться с осторожностью в продакшн-среде.
    - Упомянуть, что **eBPF** (используемый в `inspektor-gadget`) — это современная технология для безопасного мониторинга ядра.

6. **Типовые вопросы и ответы (Q&A)**
    - **Вопрос:** _"Как установить `ksniff`?"_ **Ответ:** Через `krew`:
        
         Copy
        
        `kubectl krew install sniff`
        
    - **Вопрос:** _"Можно ли анализировать трафик между подами?"_ **Ответ:** Да, `ksniff` захватывает весь трафик, проходящий через интерфейсы пода.
    - **Вопрос:** _"Какие гаджеты доступны в `inspektor-gadget`?"_ **Ответ:** Список гаджетов можно посмотреть в [документации](https://github.com/inspektor-gadget/inspektor-gadget).

7. **Примеры использования / Типовые сценарии**

    - **Сценарий 2:** Требуется отследить системные вызовы в поде. Запускаем `inspektor-gadget` с гаджетом `trace exec`.
    - **Сценарий 3:** Нужно диагностировать проблемы с файловой системой. Используем `inspektor-gadget` с гаджетом `trace open`.
