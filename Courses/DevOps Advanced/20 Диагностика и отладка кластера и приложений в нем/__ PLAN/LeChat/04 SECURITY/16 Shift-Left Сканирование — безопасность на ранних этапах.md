**Shift-Left Сканирование: обеспечение безопасности на этапе разработки**

1. **Визуальный ряд**
    - **Иллюстрация концепции Shift-Left**:
        
        - Стрелка, показывающая сдвиг безопасности влево (на ранние этапы разработки).
        - Схема DevOps-пайплайна с выделением этапов сканирования.
    - **Логотипы инструментов**:
        
        - **Trivy** (для сканирования уязвимостей в контейнерах).
        - **Dockle** (для проверки лучших практик в Docker-образах).
        - **Snyk** (для сканирования зависимостей и уязвимостей).
        - **Anchore** (для глубокого анализа образов).
    - **Примеры команд**:
         ```
         trivy image <your-image>
         dockle <your-image>
         snyk test --docker <your-image>
         ```
    - **Сравнительная таблица инструментов**:

| Инструмент | Основное назначение                      | Преимущества                                |
| ---------- | ---------------------------------------- | ------------------------------------------- |
| Trivy      | Сканирование уязвимостей в образах       | Быстрое, поддерживает множество форматов    |
| Dockle     | Проверка лучших практик в Docker-образах | Простой, фокус на безопасности              |
| Snyk       | Сканирование зависимостей и уязвимостей  | Интеграция с CI/CD, поддержка многих языков |
| Anchore    | Глубокий анализ образов                  | Поддержка политик безопасности              |

- **Иконки**:
	- 🔍 — для сканирования.
	- 🛡️ — для безопасности.
	- 🔄 — для интеграции в пайплайн.
- **Фон**: Светлый с акцентом на безопасности и инструментах.

---

2. **Демо-сценарий** Показать **живые примеры**:
    - Сканирование Docker-образа с помощью **Trivy**:
         ```
         trivy image nginx:latest
         ```
    - Проверка образа на соответствие лучшим практикам с **Dockle**:
         ```
         dockle nginx:latest
         ```
    - Сканирование зависимостей с **Snyk**:        
         ```
         snyk test --docker nginx:latest
         ```

---

3. **Ключевые тезисы**
    - **Shift-Left Сканирование** — это **перенос проверок безопасности** на ранние этапы разработки.
    - **Преимущества**:
        - **Раннее выявление уязвимостей** (экономия времени и ресурсов).
        - **Снижение рисков** при развёртывании в продакшн.
        - **Интеграция в CI/CD** для автоматической проверки.
    - **Инструменты**:
        - **Trivy**: быстрое сканирование уязвимостей в контейнерах.
        - **Dockle**: проверка лучших практик в Docker-образах.
        - **Snyk**: сканирование зависимостей и уязвимостей в коде.
        - **Anchore**: глубокий анализ образов с поддержкой политик безопасности.
    - **Shift-Left** помогает **повысить качество и безопасность** приложений.

---

4. **Описание (для выступающего)**
    - **Shift-Left** — это **изменение подхода** к безопасности: вместо проверок на этапе развёртывания, сканирование происходит **на этапе разработки**.
    - Важно объяснить, что **раннее выявление уязвимостей** позволяет **уменьшить затраты** на их исправление.
    - Подчеркнуть, что **интеграция в CI/CD** делает процесс **автоматическим и прозрачным**.
    - Упомянуть, что **Trivy и Snyk** — это **популярные инструменты** с открытым исходным кодом.
    - Объяснить, что **Dockle** фокусируется на **лучших практиках** для Docker-образов.

6. **Типовые вопросы и ответы (Q&A)**
    - **Вопрос:** _"Как начать с Shift-Left Сканирования?"_ **Ответ:** Начать с интеграции **Trivy или Snyk** в CI/CD-пайплайн.
    - **Вопрос:** _"Можно ли использовать эти инструменты для сканирования кода?"_ **Ответ:** Да, **Snyk** поддерживает сканирование кода на уязвимости.
    - **Вопрос:** _"Как часто нужно сканировать образы?"_ **Ответ:** На каждом этапе сборки и перед развёртыванием в продакшн.
