**1. Визуальный ряд:**
*   Схема работы ksniff: Pod -> tcpdump -> Wireshark (локально)
*   Скриншот Wireshark с анализом HTTP/2 трафика из пода
*   Сравнительная таблица сетевых плагинов:
   
| Плагин              | Метод               | Требуемые права       | Особенности         |
| ------------------- | ------------------- | --------------------- | ------------------- |
| **ksniff**          | Статический tcpdump | Elevated              | Простота            |
| **kubectl-tcpdump** | eBPF-based          | Привилегированный Pod | Эффективность       |
| **cilium monitor**  | eBPF/hubble         | Низкие                | Интеграция с Cilium |
   
*   Пример вывода команды `ksniff` в терминале
*   Диаграмма: Пакетный трафик между сервисами в кластере

**2. Демо-сценарий:**
*   Захват и анализ трафика в реальном времени:
    ```bash
    # Захват трафика из пода в Wireshark
    ksniff -p my-app-pod -n production -o - | wireshark -k -i -
    
    # Альтернатива: сохранение в файл
    ksniff -p my-app-pod -n production -o capture.pcap
    
    # Использование kubectl-tcpdump (eBPF)
    kubectl tcpdump -p my-app-pod -n production -i any -w - | wireshark -k -i -
    ```

**3. Ключевые тезисы:**
*   "Ksniff — мост между Kubernetes и Wireshark для глубокого анализа трафика"
*   "eBPF-based инструменты более эффективны но требуют настройки"
*   "Анализ трафика помогает диагностировать TLS, HTTP и сетевые проблемы"
*   "Всегда используйте фильтры для уменьшения объема захватываемых данных"
*   "Захват трафика в продакшене — только для критичных инцидентов"

**6. Типовые вопросы и ответы (Q&A):**
*   **В:** Как избежать перехвата sensitive данных?
    *   **О:** Использовать фильтры, анализировать в isolated средах, соблюдать compliance
*   **В:** Что делать если в поде нет tcpdump?
    *   **О:** Ksniff автоматически использует sidecar контейнер с tcpdump
*   **В:** Как анализировать TLS трафик?
    *   **О:** Использовать SSL key logging или eBPF-based инструменты
