Структуры курса `DevOps Advanced` и общей цели темы "Диагностика и отладка кластера и приложений в нем", давайте определим **ключевые цели** всей презентации и распределим их по трем категориям.

Это поможет четко сфокусировать занятие и избежать перегрузки информацией.

---

### **Категория 1: Основные цели (подробно рассматриваем)**
Это **основная цель** презентации. Эти цели должны быть достигнуты у всех студентов к концу занятия. Они будут подкреплены **демонстрациями, примерами и практическими упражнениями**.

| Цель                                                                                                                                                                                                       |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Научить студентов системному подходу к диагностике.**<br>Студент должен уметь применять цикл: `get` → `describe` → `logs` → `exec/debug` для анализа проблем.                                            |
| **Научить использовать ключевые команды `kubectl`.**<br>Студент должен свободно владеть командами `kubectl get`, `describe`, `logs`, `exec`, `port-forward`, `debug`.                                      |
| **Научить диагностировать и устранять типичные проблемы с подами.**<br>Студент должен уметь определять причины `CrashLoopBackOff`, `ImagePullBackOff`, `Pending`, `OOMKilled` на основе событий и логов.   |
| **Научить использовать визуальные и расширенные инструменты диагностики.**<br>Студент должен понимать возможности `k9s`, `Lens`, `stern` и `kubectl debug` (ephemeral containers) и уметь их применять.    |
| **Научить разработчиков ускорять цикл разработки в Kubernetes.**<br>Студент должен понимать концепцию DevEx и уметь использовать `Skaffold`, `Tilt` или `telepresence` для локальной разработки.           |
| **Научить проводить базовое тестирование конфигурации и образов.**<br>Студент должен уметь проверять манифесты с помощью `kubeval`/`polaris` и сканировать образы на уязвимости с помощью `Trivy`/`Grype`. |
| **Научить восстанавливать работоспособность кластера.**<br>Студент должен уметь диагностировать проблему узла (`NotReady`) и проверять состояние `kubelet`, диска и памяти.                                |

---

### **Категория 2: Обзорные цели (при необходимости нужно будет изучить самостоятельно)**
Эти цели **упоминаются** и **показываются**, но **не являются фокусом**. Цель — дать студенту понимание существования этих областей и направить к ресурсам для самостоятельного изучения.

| Цель                                                                                                                                                                                                                                      |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Познакомить студентов с концепцией Chaos Engineering.**<br>Студент должен знать, что такое `LitmusChaos` и `Chaos Mesh`, и для чего они используются, но не обязан уметь их настраивать.                                                |
| **Познакомить студентов с инструментами eBPF.**<br>Студент должен знать, что такое `inspektor-gadget` и `bpftrace`, и как они помогают в глубокой диагностике сети и безопасности.                                                        |
| **Познакомить студентов с концепцией Platform Engineering.**<br>Студент должен понимать, что платформа может упростить DevEx, но не обязан знать, как ее строить.                                                                         |
| **Познакомить студентов с современными трендами.**<br>Студент должен знать, что такие направления, как AIOps и AI-Driven Debugging, развиваются, и понимать их потенциальное влияние.                                                     |
| **Познакомить студентов с архитектурой и внутренним устройством Kubernetes.**<br>Студент должен понимать, что компоненты `kube-apiserver`, `kubelet`, `etcd` могут быть источником проблем, но не обязан глубоко разбираться в их работе. |

---
