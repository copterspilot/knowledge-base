**1. Визуальный ряд**
*   Скриншот терминала: `stern --tail=10 frontend`.
*   Скриншот терминала: `stern --selector app=backend`.
*   Скриншот терминала: `stern --since 5m --context production`.
*   Иконки: `stern`, `kubectl`, логи.

**2. Демо-сценарий (если уместен)**
*   Показать в реальном времени команду `stern` для агрегации логов всех подов с меткой `app=frontend`.

**3. Ключевые тезисы**
*   `stern` — это мощный CLI-инструмент для агрегации и фильтрации логов.
*   Он объединяет логи из нескольких подов в одном цветном потоке.
*   Позволяет легко фильтровать и искать нужные сообщения.

**4. Описание (для выступающего)**
*   **Цель слайда:** Представить `stern` как современный, незаменимый инструмент для анализа логов в сложных средах.
*   **Ключевое сообщение:** `kubectl logs` — это хорошо, но `stern` — это следующий уровень.
*   **Основные тезисы:**
    *   **Проблема:** В среде с множеством реплик и микросервисов, использование `kubectl logs` для каждого пода по отдельности крайне неэффективно.
    *   **Решение:** `stern` решает эту проблему, позволяя агрегировать логи из всех подов, соответствующих селектору (например, `app=frontend`), в одном цветном потоке.
    *   **Функциональность:** Поддерживает цветовое кодирование, фильтрацию по контексту (namespace, cluster), поиск по регулярным выражениям, вывод только новых логов (`--tail`), вывод логов за определенный период (`--since`).
    *   **Установка:** Устанавливается через `krew` (`krew install stern`), что делает его доступным и легко управляемым.
*   **Связь с источниками:** Тезисы основаны на анализе современных практик и инструментов, не представленных в материалах 2019 года.

**6. Типовые вопросы и ответы (Q&A)**
*   **В:** В чем разница между `stern` и `kubectl logs --selector`?
    *   **О:** `kubectl logs --selector` выводит логи последовательно (сначала все логи одного пода, потом другого). `stern` выводит логи в реальном времени, смешивая их по времени, что позволяет видеть полную картину.
*   **В:** Можно ли использовать `stern` для поиска ошибок?
    *   **О:** Да, `stern` поддерживает фильтрацию по регулярным выражениям, что позволяет легко находить сообщения об ошибках (например, `stern --selector app=backend "error|fail"`).
*   **В:** Нужно ли устанавливать `stern` на все машины?
    *   **О:** Да, `stern` — это CLI-инструмент, который устанавливается на машину разработчика или инженера. Его удобно устанавливать через `krew`.

**7. Примеры использования / Типовые сценарии**
*   **Мониторинг инцидента:** Использование `stern` для отслеживания логов всех подов `frontend` во время инцидента.
*   **Отладка развертывания:** Использование `stern` для наблюдения за логами всех новых подов во время деплоя.
*   **Поиск ошибок:** Использование `stern` с фильтром для поиска всех сообщений об ошибках в кластере.
