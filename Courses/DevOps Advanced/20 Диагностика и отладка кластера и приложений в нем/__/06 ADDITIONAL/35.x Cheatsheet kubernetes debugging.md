### **Cheatsheet: Отладка (Debugging) в Kubernetes**

**Цель:** Быстро найти и устранить проблему с подом или приложением.

---

#### **1. Базовый цикл диагностики (Ops)**

Это ваша основа. Начинайте с этих команд.

| Задача                             | Команда                                | Пояснение                                                                                                          |
|:---------------------------------- |:-------------------------------------- |:------------------------------------------------------------------------------------------------------------------ |
| **Посмотреть состояние подов**     | `kubectl get pods`                     | Найти под в `CrashLoopBackOff`, `Pending`, `Error`.                                                                |
| **Посмотреть состояние нод**       | `kubectl get nodes`                    | Убедиться, что все ноды в статусе `Ready`.                                                                         |
| **Посмотреть события кластера**    | `kubectl get events --watch`           | Наблюдать за событиями в реальном времени. **Ключ к диагностике!**                                                 |
| **Получить детальную информацию**  | `kubectl describe pod <имя_пода>`      | Проанализировать секцию `Events`. Ищите `FailedScheduling`, `FailedMount`, `Back-off restarting failed container`. |
| **Посмотреть логи**                | `kubectl logs <имя_пода>`              | Посмотреть логи текущего контейнера.                                                                               |
|                                    | `kubectl logs <имя_пода> --previous`   | **КРИТИЧНО!** Посмотреть логи **упавшего** контейнера.                                                             |
|                                    | `kubectl logs -l app=my-app --tail=10` | Агрегировать логи всех подов с меткой `app=my-app`.                                                                |
| **Выполнить команду в контейнере** | `kubectl exec -it <имя_пода> -- sh`    | Войти в контейнер и проверить конфигурацию, файловую систему, доступность зависимостей.                            |

---

#### **2. Диагностика "CrashLoopBackOff"**

**Цель:** Устранить причину постоянного рестарта пода.

| Шаг                                 | Команда                              | Что искать                                                                                    |
|:----------------------------------- |:------------------------------------ |:--------------------------------------------------------------------------------------------- |
| 1. Подтвердить проблему             | `kubectl get pods`                   | Статус `CrashLoopBackOff`.                                                                    |
| 2. Проверить события                | `kubectl describe pod <имя_пода>`    | `Back-off restarting failed container`, `Liveness probe failed`, `OOMKilled`.                 |
| 3. Анализ логов упавшего контейнера | `kubectl logs <имя_пода> --previous` | `panic`, `Connection refused`, `File not found`, `Configuration error`.                       |
| 4. Проверить ресурсы                | `kubectl describe pod <имя_пода>`    | `Limits` и `Requests`. Не превышает ли приложение лимит памяти?                               |
| 5. Проверить liveness-пробу         | `kubectl describe pod <имя_пода>`    | Правильный `path`, `port`, `timeout`?                                                         |
| 6. Проверить конфигурацию           | `kubectl describe pod <имя_пода>`    | Правильно ли смонтированы `ConfigMaps` и `Secrets`? Правильно ли заданы переменные окружения? |

---

#### **3. Отладка в минимальных образах (scratch, distroless)**

**Цель:** Диагностировать проблему, когда в контейнере нет `sh`, `bash`, `curl`, `netstat`.

| Инструмент             | Команда                                                        | Пояснение                                                                                                                                            |
|:---------------------- |:-------------------------------------------------------------- |:---------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`kubectl debug`**    | `kubectl debug <имя_пода> -it --image=nicolaka/netshoot -- sh` | Запустить временный (ephemeral) контейнер с полным набором утилит (`tcpdump`, `strace`, `nslookup`). **Решение проблемы!**                           |
| **`inspektor-gadget`** | `kubectl gadget trace open -n <namespace>`                     | Отследить, какие файлы открывает приложение.                                                                                                         |
|                        | `kubectl gadget trace network -n <namespace>`                  | Отследить сетевые вызовы.                                                                                                                            |
|                        | `kubectl gadget top tcp`                                       | Показать самые активные TCP-соединения.                                                                                                              |
| **`ksniff`**           | `kubectl sniff <имя_пода>`                                     | Захватить сетевой трафик из пода и проанализировать его в Wireshark. Работает даже с минимальными образами (использует привилегированный контейнер). |

---

#### **4. Удаленная отладка (Remote Debugging)**

**Цель:** Подключить локальную IDE к приложению, запущенному в кластере.

| Шаг                          | Команда / Действие                                                                                                                                                                                                        |
|:---------------------------- |:------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Настроить приложение      | Добавить в манифест `containerPort` для порта отладчика (например, 2345 для `dlv`). Настроить запуск с флагами отладчика (e.g., `dlv --listen=:2345 --headless=true --api-version=2 --accept-multiclient exec ./my-app`). |
| 2. Пробросить порт           | `kubectl port-forward pod/<имя_пода> 2345:2345`                                                                                                                                                                           |
| 3. Настроить IDE             | В VS Code, GoLand и т.д. создать конфигурацию удаленной отладки, указав `localhost` и порт `2345`.                                                                                                                        |
| 4. Подключиться и отлаживать | Запустить конфигурацию в IDE, установить брейкпоинты.                                                                                                                                                                     |

---

#### **5. Инструменты для разработчиков (DevEx)**

**Цель:** Ускорить цикл разработки и отладки.

| Инструмент              | Команда                                                                        | Пояснение                                                                                                                                                              |
|:----------------------- |:------------------------------------------------------------------------------ |:---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`telepresence`**      | `telepresence connect`<br>`telepresence intercept <deployment> --port 8080:80` | Создать двухсторонний туннель. Локальный процесс получает доступ к кластеру, а кластер может обращаться к локальному процессу. **Идеально для отладки микросервисов.** |
| **`ksync`**             | `ksync create ./local-code ./pod-code --selector=app=my-app`                   | Двусторонняя синхронизация файлов. **Внимание:** Может быть нестабильным.                                                                                              |
| **`Tilt` / `Skaffold`** | `tilt up`                                                                      | Автоматизация локального CI/CD цикла: отслеживание изменений -> пересборка образа -> деплой -> логи.                                                                   |

---

#### **6. Полезные команды `kubectl`**

| Команда                                           | Пояснение                                                |
|:------------------------------------------------- |:-------------------------------------------------------- |
| `kubectl top node`                                | Потребление ресурсов нодами.                             |
| `kubectl top pod --sort-by=memory`                | Потребление ресурсов подами, отсортированными по памяти. |
| `kubectl get events --watch`                      | Мониторинг событий в реальном времени.                   |
| `kubectl get <type> <name> -o yaml`               | Получить YAML "живого" объекта из кластера.              |
| `kubectl cp ./local-file my-pod:/app/remote-file` | Скопировать файл из локальной машины в контейнер.        |
| `kubectl port-forward svc/my-service 8080:80`     | Пробросить порт сервиса на локальную машину.             |

---

**Советы из чата и субтитров:**
*   **"какэтодебажить это прям боль)"** — Используйте `kubectl debug` и `telepresence`, чтобы уменьшить эту боль.
*   **"Вопросы - обязательно. Готовьте )))"** — Всегда задавайте вопросы, чтобы глубже понять тему.
*   **"Чем плохо что в контейнере процесс работает под рутом?"** — Это нарушение принципа минимальных привилегий, увеличивающее поверхность атаки. Используйте `Pod Security Admission` (PSA) для принудительного применения политик.
