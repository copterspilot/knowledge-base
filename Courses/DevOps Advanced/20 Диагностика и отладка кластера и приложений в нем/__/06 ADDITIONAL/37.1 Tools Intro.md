### **OPS: Диагностика и отладка кластера**

Инструменты для администраторов и SRE для анализа состояния кластера и приложений.

*   **`kubectl` (встроенные команды):**
    *   **`get`, `describe`, `logs`, `events`:** Базовые команды для получения информации, диагностики и анализа событий.
    *   **`exec`, `port-forward`, `cp`:** Команды для прямого взаимодействия с подами.
*   **`kubectl debug` (встроенный):**
    *   Запускает временный (ephemeral) контейнер внутри пода для отладки, особенно в образах `scratch` или `distroless`. **Ключевое для диагностики.**
*   **`stern` (krew):**
    *   Мощный инструмент для агрегации и фильтрации логов нескольких подов с цветным выводом.
*   **`ksniff` (krew):**
    *   Плагин для захвата сетевого трафика из пода и его анализа в Wireshark. Работает с любыми образами через привилегированные контейнеры.
*   **`inspektor-gadget` (CLI):**
    *   Набор инструментов на основе eBPF для глубокой интроспекции ядра: трейсинг системных вызовов, отслеживание открытия файлов и сетевых сокетов. **"Суперсилы" для продвинутой диагностики.**
*   **`kubectl trace`:** (Нет в презентации)
    *   Альтернатива `inspektor-gadget`, использующая eBPF для запуска `bpftrace` скриптов в кластере. Предоставляет схожий функционал.
*   **`k9s`:** (Нет в презентации)
    *   Терминальный пользовательский интерфейс (TUI) для Kubernetes. Позволяет быстро просматривать, управлять и отлаживать ресурсы в интерактивном режиме.

### **DEV: Локальная разработка и отладка**

Инструменты для ускорения цикла разработки и отладки кода в кластере.

*   **`telepresence`:**
    *   Двухсторонний прокси, позволяющий локальному процессу получать доступ к кластеру и наоборот. Подменяет `Deployment` локальным инстансом. **Идеально для отладки микросервисов.**
*   **`Tilt`:**
    *   Фреймворк для автоматизации локального CI/CD цикла. Отслеживает изменения, пересобирает образы, деплоит и агрегирует логи. **Полный цикл разработки.**
*   **`Skaffold`:**
    *   Аналог `Tilt` от Google, автоматизирующий локальную разработку и развертывание.
*   **`ksync` (krew):**
    *   Инструмент для двусторонней синхронизации файлов между локальной машиной и подом. **Полезен для быстрого обновления кода, но может быть нестабильным.**
*   **`kubers`:** (Нет в презентации)
    *   Инструмент для удаленной разработки, который позволяет работать с кодом в кластере, как с локальным файлом, используя VS Code Remote - Containers.

### **TEST: Тестирование и обеспечение надежности**

Инструменты для проверки манифестов, приложений и устойчивости системы.

*   **`LitmusChaos`:**
    *   Платформа для хаос-тестирования с оператором и CRD. Позволяет описывать сложные, повторяемые эксперименты по проверке отказоустойчивости.
*   **`kube-linter`:**
    *   Статический анализатор манифестов Kubernetes, проверяющий их на наличие проблем безопасности и надежности.
*   **`Polaris`:**
    *   Инструмент для проверки манифестов и конфигурации кластера на соответствие best practices. Имеет CLI, Dashboard и Webhook.
*   **`KUTTL` (Kubernetes Test Tools):**
    *   Декларативный фреймворк для тестирования операторов и приложений, использующий YAML.
*   **`Terratest`:**
    *   Императивный фреймворк на Go для написания сложных тестовых сценариев инфраструктуры.
*   **`Chaos Mesh`:** (Нет в презентации)
    *   Еще одна мощная платформа для хаос-тестирования от PingCAP, конкурирующая с `LitmusChaos`. Предоставляет широкий набор экспериментов.
*   **`Pumba`:**
    *   Простой инструмент для базовых хаос-экспериментов (убийство контейнеров, сетевые задержки). **Устаревает в пользу более сложных платформ.**

### **SEC: Безопасность и аудит**

Инструменты для сканирования образов, проверки конфигурации и аудита кластера.

*   **`Trivy` (Aqua):**
    *   Инструмент для сканирования образов контейнеров, манифестов и кластера на наличие уязвимостей (CVE).
*   **`Dockle` (Goodwithtech):**
    *   Проверяет образы контейнеров на соответствие best practices Dockerfile (запуск от root, наличие HEALTHCHECK).
*   **`kube-bench` (Aqua):**
    *   Проверяет соответствие конфигурации компонентов Kubernetes (kubelet, api-server) рекомендациям CIS Benchmarks.
*   **`Pod Security Admission` (PSA):**
    *   Встроенный в Kubernetes механизм для принудительного применения политик безопасности (например, запрет запуска подов с привилегиями). **Замена устаревшему `PodSecurityPolicy`.**
*   **`Kyverno`:**
    *   Инструмент для создания и применения политик безопасности через Admission Controller. Позволяет писать правила на языке, похожем на манифесты Kubernetes.
*   **`Gatekeeper` (OPA):**
    *   Реализация Open Policy Agent (OPA) для Kubernetes. Предоставляет мощный язык Rego для описания сложных политик. **Более гибкий, но сложный в освоении.**
*   **`Kubescape`:** (Нет в презентации)
    *   Комплексный инструмент для аудита безопасности, соответствия стандартам (NSA, CIS) и обнаружения уязвимостей в образах. **Объединяет функционал нескольких инструментов в одном.**
*   **`Sealed Secrets`:** (Нет в презентации)
    *   Инструмент для безопасного хранения секретов в Git-репозиториях. Шифрует секреты на локальной машине, а расшифровка происходит только в кластере. **Ключ для GitOps-подхода к секретам.**
