**1. Визуальный ряд**
*   Две колонки:
    *   **Левая колонка: `kubectl logs`**
        *   Скриншот терминала: `kubectl logs -l app=frontend --tail=10`
        *   Подпись: "Вывод для одного пода. Нужно запускать отдельно для каждого."
    *   **Правая колонка: `stern`**
        *   Скриншот терминала: `stern --tail=10 frontend`
        *   Подпись: "Агрегированный цветной вывод для всех подов с меткой `app=frontend`."
*   Иконки: `kubectl`, `stern`.

**2. Демо-сценарий (если уместен)**
*   Показать в реальном времени сравнение вывода `kubectl logs -l app=frontend` и `stern frontend`.

**3. Ключевые тезисы**
*   `kubectl logs` — это базовый инструмент для просмотра логов одного пода.
*   `stern` — это продвинутый инструмент для агрегации и фильтрации логов нескольких подов.
*   `stern` значительно упрощает диагностику в средах с множеством реплик.

**4. Описание (для выступающего)**
*   **Цель слайда:** Помочь слушателям понять, когда использовать базовую команду `kubectl logs`, а когда стоит перейти на более мощный инструмент `stern`.
*   **Ключевое сообщение:** `stern` — это эволюция `kubectl logs` для сложных сред.
*   **Основные тезисы:**
    *   **`kubectl logs`:**
        *   **Плюсы:** Встроен в `kubectl`, прост в использовании, доступен везде.
        *   **Минусы:** Показывает логи только одного пода. Для просмотра логов всех подов с определенной меткой нужно либо запускать команду несколько раз, либо использовать `--selector`, что выводит логи последовательно (не в реальном времени и не смешано).
    *   **`stern`:**
        *   **Плюсы:** Агрегирует логи всех подов, соответствующих селектору, в одном цветном потоке в реальном времени. Поддерживает продвинутую фильтрацию (включая регулярные выражения), цветовое кодирование, вывод логов за определенный период (`--since`).
        *   **Минусы:** Требует установки (`brew install stern`).
*   **Связь с источниками:** Тезисы основаны на анализе современных практик и потребностях инженеров, упомянутых в чате ("а есть ли какой-то консольный top, но для контейнеров?").

**5. Связь с прошлыми материалами**

**6. Типовые вопросы и ответы (Q&A)**
*   **В:** Нужно ли полностью отказываться от `kubectl logs`?
    *   **О:** Нет. `kubectl logs` — это отличный инструмент для быстрой проверки логов одного конкретного пода. `stern` используется, когда нужно видеть общую картину по группе подов.
*   **В:** Можно ли использовать `stern` для поиска ошибок?
    *   **О:** Да, `stern` отлично подходит для поиска ошибок. Например, команда `stern --selector app=backend "error|fail"` покажет все сообщения, содержащие "error" или "fail", из всех подов бэкенда.
*   **В:** Влияет ли `stern` на производительность кластера?
    *   **О:** Нет. `stern` — это клиентский инструмент, который просто читает логи через `kubectl logs`. Он не оказывает нагрузки на кластер сверх той, которую оказывает сама команда `kubectl logs`.

**7. Примеры использования / Типовые сценарии**
*   **Мониторинг инцидента:** Использование `stern` для отслеживания логов всех подов `frontend` во время инцидента.
*   **Отладка развертывания:** Использование `stern` для наблюдения за логами всех новых подов во время деплоя.
*   **Поиск ошибок:** Использование `stern` с фильтром для поиска всех сообщений об ошибках в кластере.

Вот таблица сравнения `kubectl logs` и `stern`.

| **Параметр**                 | **`kubectl logs`**                                       | **`stern`**                                                                      |
|:---------------------------- |:-------------------------------------------------------- |:-------------------------------------------------------------------------------- |
| **Назначение**               | Просмотр логов одного пода или контейнера.               | Агрегация и фильтрация логов из нескольких подов.                                |
| **Вывод**                    | Последовательный вывод логов.                            | Смешанный, цветной вывод логов в реальном времени.                               |
| **Фильтрация**               | Ограниченная (по контейнеру, количеству строк, времени). | Мощная (по регулярным выражениям, меткам, namespace, контексту).                 |
| **Цветовое кодирование**     | Нет.                                                     | Да, для разных уровней логов (info, warn, error) и разных подов.                 |
| **Вывод новых логов**        | `--follow` (`-f`).                                       | `--tail` (аналогично `--follow`).                                                |
| **Логи упавших контейнеров** | `--previous` (`-p`).                                     | Поддерживается (через `--previous`).                                             |
| **Установка**                | Входит в состав `kubectl`.                               | Требует установки (например, через `krew install stern`).                        |
| **Использование**            | `kubectl logs <pod-name>`                                | `stern <selector>` (например, `stern frontend`)                                  |
| **Преимущества**             | Простота, встроен в `kubectl`, доступен везде.           | Высокая производительность диагностики, цветовое кодирование, мощная фильтрация. |
| **Недостатки**               | Неудобен для работы с множеством реплик, нет цветов.     | Требует установки, дополнительная зависимость.                                   |

**Вывод:** `kubectl logs` — это базовый, встроенный инструмент. `stern` — это продвинутый инструмент, который значительно упрощает диагностику в средах с множеством реплик.
