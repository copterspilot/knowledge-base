**1. Визуальный ряд**
*   Логотип `.NET Aspire`.
*   Скриншот кода C# с аннотацией `@ServiceBinding`.
*   Скриншот YAML-манифеста, сгенерированного Aspire для Kubernetes.
*   Иконки: `.NET`, `Docker`, `Kubernetes`.

**2. Демо-сценарий (если уместен)**
*   Нет. (Тема является частью презентации, демонстрация требует специфической среды разработки).

**3. Ключевые тезисы**
*   `.NET Aspire` — это фреймворк для ускорения разработки и развертывания приложений .NET.
*   Он автоматически генерирует манифесты Kubernetes и Dockerfiles.
*   Упрощает локальную разработку и переход к production.

**4. Описание (для выступающего)**
*   **Цель слайда:** Представить `.NET Aspire` как современный инструмент для разработчиков .NET, который решает проблемы DevEx.
*   **Ключевое сообщение:** `.NET Aspire` автоматизирует рутинные задачи, позволяя разработчикам сосредоточиться на бизнес-логике.
*   **Основные тезисы:**
    *   **Автоматизация инфраструктуры:** Aspire позволяет разработчикам описывать свои приложения и их зависимости (базы данных, очереди, кэши) на C#. На основе этого описания фреймворк автоматически генерирует все необходимые артефакты: Dockerfiles, манифесты Kubernetes, Helm-чарты.
    *   **Ускорение локальной разработки:** Aspire упрощает запуск всего приложения (включая зависимости) локально с помощью одной команды `dotnet run`. Это решает проблему "у меня на localhost работало, а тут — не работает".
    *   **Единый подход:** Обеспечивает единообразие в создании инфраструктуры для всех приложений .NET в команде.
    *   **Поддержка GitOps:** Сгенерированные манифесты можно легко интегрировать в GitOps-пайплайны.
*   **Связь с источниками:** Тезисы основаны на анализе современных практик и инструментов, не представленных в материалах 2019 года.

**6. Типовые вопросы и ответы (Q&A)**
*   **В:** `.NET Aspire` — это замена `telepresence` или `ksync`?
    *   **О:** Нет. Aspire решает другую задачу. `telepresence` и `ksync` помогают подключить локальный процесс к кластеру. Aspire помогает создать и развернуть само приложение в кластере, автоматизируя создание инфраструктуры.
*   **В:** Поддерживает ли Aspire другие языки, кроме .NET?
    *   **О:** Нет. Aspire — это фреймворк, специфичный для экосистемы .NET.
*   **В:** Нужно ли отказываться от ручного написания манифестов?
    *   **О:** Не обязательно. Aspire генерирует манифесты, которые можно использовать как основу и дорабатывать вручную при необходимости.

**7. Примеры использования / Типовые сценарии**
*   **Быстрый старт нового проекта:** Разработчик создает новое приложение .NET и использует Aspire для автоматического создания Dockerfile и манифестов Kubernetes.
*   **Локальная разработка:** Разработчик использует Aspire для запуска своего микросервиса вместе с зависимостями (PostgreSQL, Redis) на локальной машине.
*   **CI/CD пайплайн:** Сгенерированные Aspire манифесты используются в пайплайне для деплоя приложения в кластер.
