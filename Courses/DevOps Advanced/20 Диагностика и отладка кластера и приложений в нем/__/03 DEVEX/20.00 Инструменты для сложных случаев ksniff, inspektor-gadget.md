**1. Визуальный ряд**
*   Две колонки:
    *   **Левая колонка: `ksniff`**
        *   Логотип `ksniff`.
        *   Схема: Под → `tcpdump` → Wireshark.
        *   Иконка: сеть, глаз.
    *   **Правая колонка: `inspektor-gadget`**
        *   Логотип `inspektor-gadget`.
        *   Схема: Под → eBPF → Системные вызовы, Файлы, Сетевые сокеты.
        *   Иконка: ядро, супергерой.
*   Скриншот терминала: `kubectl sniff my-pod-7d5b8c9c4-xl2v9`.

**2. Демо-сценарий (если уместен)**
*   Показать в реальном времени команду `kubectl sniff` для захвата трафика и открытия его в Wireshark.

**3. Ключевые тезисы**
*   `ksniff` — инструмент для анализа сетевого трафика на уровне пода.
*   `inspektor-gadget` — набор инструментов для глубокой диагностики на уровне ядра.
*   Оба инструмента используются для решения проблем, недоступных для стандартных команд.

**4. Описание (для выступающего)**
*   **Цель слайда:** Представить два мощных инструмента для диагностики сложных, "невидимых" проблем.
*   **Ключевое сообщение:** Когда стандартные команды не дают ответа, приходят на помощь `ksniff` и `inspektor-gadget`.
*   **Основные тезисы:**
    *   **`ksniff`:** Это плагин для `kubectl`, который позволяет захватить сетевой трафик из пода и перенаправить его напрямую в Wireshark. Он особенно полезен для анализа трафика в минимальных образах, где нет `tcpdump`. Если под не имеет привилегий, `ksniff` может создать временный привилегированный контейнер в том же сетевом пространстве имен.
    *   **`inspektor-gadget`:** Это набор инструментов, использующих технологию eBPF. Он позволяет "заглянуть" внутрь работающего пода и увидеть, какие файлы он открывает, какие сетевые сокеты создает и какие системные вызовы выполняет. Это "суперсила" для диагностики проблем с производительностью или безопасностью.

**6. Типовые вопросы и ответы (Q&A)**
*   **В:** Нужно ли устанавливать Wireshark на ноду?
    *   **О:** Нет. `ksniff` перенаправляет трафик через `kubectl` на локальную машину, где запущен Wireshark.
*   **В:** Безопасен ли `inspektor-gadget`?
    *   **О:** Да, он использует безопасный механизм eBPF. Однако, как и любой инструмент с расширенными привилегиями, к нему нужно применять политики RBAC.
*   **В:** Можно ли использовать `ksniff` для анализа трафика между подами?
    *   **О:** Да, `ksniff` захватывает весь трафик, проходящий через сетевой интерфейс пода, включая входящий и исходящий.

**7. Примеры использования / Типовые сценарии**
*   **Анализ проблемы с DNS:** Использование `ksniff` для проверки, какие DNS-запросы отправляет под.
*   **Поиск утечки файловых дескрипторов:** Использование `inspektor-gadget` для отслеживания открытия и закрытия файлов.
*   **Диагностика `Connection refused`:** Использование `ksniff` для анализа сетевых пакетов и выявления причины отказа в подключении.
