## **Часть 1: Ops. Диагностика и отладка кластера**

### **Слайд 3: `kubectl` — главный проводник**
- **Ключевое сообщение:** `kubectl` — основа диагностики. Освойте его — и вы решите 90% проблем.
- **Команды:**
  - `get`, `describe`, `logs`, `exec`, `top`, `debug`
- **Рекомендация:** Установите `krew` — менеджер плагинов.
- **Источник:** Learnk8s.io, официальная документация

---

### **Слайд 4: Первичный осмотр: `kubectl get`, `top`**
- **Цель:** Получить общую картину.
- **Примеры:**
  ```bash
  kubectl get pods -A
  kubectl top node --sort-by=cpu
  kubectl get events --sort-by=.metadata.creationTimestamp
  ```
- **Что искать:** `CrashLoopBackOff`, `Pending`, `ImagePullBackOff`
- **Источник:** Stencel & Berton, Уильям Д.

---

### **Слайд 5: Глубокая диагностика: `kubectl describe`, `logs`**
- **`kubectl describe pod <pod>`** → события (Events): `FailedScheduling`, `FailedMount`, `OOMKilled`
- **`kubectl logs <pod>`** → стандартные логи
- **`kubectl logs <pod> --previous`** → критично для `CrashLoopBackOff`
- **`kubectl logs -l app=frontend`** → массовый сбор логов
- **Иструмент:** `stern` — агрегированные логи в реальном времени
- **Источник:** Naik et al., Learnk8s

---

### **Слайд 6: Базовый цикл диагностики инцидента**
- **Визуализация цикла:**
  1. `get` → обзор
  2. `describe` → события
  3. `logs` → логи
  4. `exec` → интерактивная отладка
  5. `debug` → временные контейнеры
  6. Исправление → повторная проверка
- **Ключевое сообщение:** Диагностика — это цикл, а не случайные команды.
- **Источник:** Бёрнс Брендан, Kannaiah Govardhana

---

### **Слайд 7: `krew` — менеджер плагинов**
- **Зачем?** Расширить `kubectl`.
- **Полезные плагины:**
  - `debug` — ephemeral containers
  - `stern` — агрегированные логи
  - `view-utilization` — потребление ресурсов
  - `inspektor-gadget` — безопасность, сеть
- **Команда:** `kubectl krew install debug`
- **Источник:** Learnk8s, официальная документация

---

### **Слайд 8: Отладка с помощью `kubectl debug`**
- **Что это?** Ephemeral containers — временное добавление контейнера в Pod.
- **Пример:**
  ```bash
  kubectl debug -it <pod> --image=busybox --target=app-container
  ```
- **Когда использовать:** Когда в основном контейнере нет `sh`, `curl`, `tcpdump`.
- **Источник:** Официальная документация Kubernetes

---

### **Слайд 9: Сетевая диагностика: Calico, Istio, CNI**
- **Проблемы:** Pod не видит сервис, DNS не работает, трафик блокируется.
- **Инструменты:**
  - `nslookup`, `dig`, `curl`
  - `tcpdump` внутри Pod’а
  - `k8snetlook` — диагностика сети (из `Kubernetes Изнутри`)
- **Чек-лист:**
  - Проверить DNS (`coredns`)
  - Проверить CNI (Calico, Cilium)
  - Проверить NetworkPolicy
- **Источник:** Стронг Дж., Лэнси В., KubernetesIznutri

---

### **Слайд 10: Восстановление работоспособности кластера**
- **Проблемы узла:** `NotReady`, нехватка ресурсов, сбой `kubelet`.
- **Диагностика:**
  - `kubectl get nodes`
  - `kubectl describe node <node>`
  - `systemctl status kubelet`
  - `df -h`, `free -m`
- **Что делать:**
  - Проверить диск, память, `kubelet`
  - Перезапустить `kubelet` (если нужно)
- **Источник:** Sachdeva Piyush, Boorshtein & Surovich

## **Часть 2: Dev. Локальная разработка и удалённая отладка**

### **Слайд 11: Проблемы локальной разработки**
- **Цикл "редактирование-сборка-деплой" — слишком долгий.**
- **Расхождение сред:** локально работает, в кластере — нет.
- **Сложная отладка:** нет доступа к переменным, стеку вызовов.
- **Цель:** Сделать разработку в Kubernetes такой же удобной, как локально.

---

### **Слайд 12: Инструменты для ускорения разработки**
- **Telepresence:** локальный код + доступ к кластеру.
- **Skaffold:** автоматизация сборки и деплоя.
- **Tilt:** визуальный интерфейс, быстрая обратная связь.
- **ksync:** синхронизация файлов в Pod.
- **Сравнение:** когда что использовать?
- **Источник:** Learnk8s

---

### **Слайд 13: Удалённая отладка приложений**
- **Проблема:** "А мне бы просто подебажить..." (из PDF 2019).
- **Решения:**
  - `kubectl port-forward` + IDE
  - `telepresence` + отладчик
  - `kubectl debug` + отладчик в контейнере
- **Пример:** отладка Java-приложения с `jdb` или Go с `dlv`.
- **Источник:** Martin P. — Kubernetes Programming with Go
