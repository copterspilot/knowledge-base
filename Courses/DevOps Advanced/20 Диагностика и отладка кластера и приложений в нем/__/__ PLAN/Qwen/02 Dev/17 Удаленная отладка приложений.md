### **Слайд 27: Удаленная отладка приложений**

*   **Часть 2. Dev. Локальная разработка и удаленная отладка**
*   **Заголовок:** Удаленная отладка приложений
*   **Ключевые элементы (примерный вид слайда):**
    *   Заголовок: **Подключение локального отладчика к приложению в кластере**
    *   Иконки: Отладчик (жучок), линии связи между ноутбуком и кластером.
    *   Список подходов/инструментов:
        *   `Squash` (менее активен)
        *   Интеграция IDE (VS Code, IntelliJ) + `telepresence`/`kubectl port-forward`
        *   `kubectl debug` (Ephemeral Containers)

---

*   **Описание (для выступающего / Расширенное описание темы):**
    *   **Цель слайда:** Представить инструменты и методы, позволяющие разработчикам подключать свои локальные IDE и отладчики (например, delve для Go, debugpy для Python) к приложениям, запущенным внутри кластера Kubernetes, для пошаговой отладки.
    *   **Ключевое сообщение:** Современные подходы к удаленной отладке в Kubernetes включают использование `kubectl debug` для запуска отладчиков в ephemeral containers, интеграцию IDE с `telepresence` или `port-forward`, а также специализированные инструменты. `Squash` упоминается как менее активный проект.
    *   **Основные тезисы:**
        *   **Проблема:** После развертывания приложения в кластере необходимо иметь возможность пошаговой отладки его кода, установки точек останова, просмотра значений переменных, как это делается локально. *(Из PDF 2019, слайд 12.1)* "А мне бы просто подебажить....".
        *   **Решения:**
            *   **`Squash` (менее активен):** *(Из PDF 2019, слайд 12.1, 12.2)* Специализированный инструмент для удаленной отладки приложений в K8s. *(Из PDF 2019, слайд 12.1)* Запускал привилегированные поды для отладки, поддерживал `gdb`, Java-отладчик, `dlv` (Go). *(Из PDF 2019, слайд 12.1)* Поддержка Python/Node.js была ограничена. *(Из PDF 2019, слайд 12.1)* Основная IDE - VS Code. *(Из PDF 2019, слайд 12.1)* В 2025 году проект считается менее активным по сравнению с другими подходами. *(Из обновленного описания темы)*
            *   **Интеграция IDE + `telepresence`/`port-forward`:** *(Из обновленного описания темы)* Современный и гибкий подход. Приложение настраивается для запуска отладчика (например, `dlv`, прослушивающего порт). Используется `telepresence intercept` или `kubectl port-forward` для проксирования этого порта на локальную машину. Локальная IDE подключается к `localhost:<port>` для отладки. *(Из обновленного описания темы)* *(Из субтитров 2019)* "какэтодебажить это прям боль)". *(Из PDF 2019, слайд 11)* Telepresence позволяет обращаться к локальному процессу из кластера.
            *   **`kubectl debug` (Ephemeral Containers):** *(Из обновленного описания темы)* Создание ephemeral container с отладчиком (например, `delve`, `debugpy`) внутри namespace целевого пода. *(Из обновленного описания темы)* Запуск отладчика внутри этого контейнера и подключение к нему (например, через `port-forward`). *(Из обновленного описания темы)* Это современный и рекомендуемый способ, использующий нативные возможности K8s (Ephemeral Containers стали стабильными). *(Из обновленного описания темы, слайда 11)*
        *   **Актуальность 2025:** Акцент на интеграции с IDE и использовании `kubectl debug`. `Squash` упоминается как устаревающий. *(Из обновленного описания темы)*

*   **Типовые вопросы и ответы по теме слайда:**
    *   **В:** В чем разница между `kubectl debug` и `Squash` для отладки?
    *   **О:** `Squash` был специализированным инструментом, требовавшим установки своего оператора и использующим привилегированные поды. `kubectl debug` использует нативную функцию Kubernetes (Ephemeral Containers), что делает его более интегрированным и, возможно, безопасным. Также `kubectl debug` позволяет использовать любой образ отладки.
    *   **В:** Как подключить отладчик Go (Delve) к приложению в кластере?
    *   **О:** 1) Запустить приложение с флагом `dlv`: `dlv exec ./myapp --headless --listen=:40000 --api-version=2 --accept-multiclient`. 2) Использовать `kubectl port-forward pod/myapp-pod 40000:40000`. 3) Подключить локальный Delve клиент или IDE (VS Code Go plugin) к `localhost:40000`.
    *   **В:** Можно ли использовать `telepresence` для отладки?
    *   **О:** Да, `telepresence` (особенно v2) позволяет "перехватывать" трафик к сервису и перенаправлять его на локально запущенное приложение с отладчиком, что очень удобно.

*   **Примеры использования / Типовые сценарии:**
    *   **Отладка бизнес-логики Go:** Запуск пода с приложением, настроенным на запуск `dlv`. Использование `kubectl debug` или `port-forward` для подключения VS Code к `dlv` и установки точек останова.
    *   **Отладка Python-приложения:** Запуск приложения с `python -m debugpy --listen 0.0.0.0:5678 --wait-for-client -m myapp`. Использование `kubectl port-forward` и подключение PyCharm/VS Code к `localhost:5678`.
