**Аудит кластера и Compliance: инструменты и подходы для проверки безопасности и соответствия стандартам**

#### **Описание слайда**

1. **Визуальный ряд**
    - **Схема процесса аудита**:
        
        - Этапы: **Сбор данных** → **Анализ** → **Отчётность** → **Исправление**.
    - **Логотипы инструментов**:
        
        - **kube-bench** (для проверки соответствия стандартам CIS).
        - **kube-hunter** (для поиска уязвимостей в кластере).
        - **Polaris** (для проверки лучших практик).
        - **OpenSCAP** (для сканирования узлов на соответствие стандартам безопасности).
    - **Примеры команд**:
         ```
         kube-bench run --targets node
         kube-hunter --remote some-cluster
         polaris audit --audit-path ./manifests`
         ```
    - **Сравнительная таблица инструментов**:

| Инструмент  | Назначение                                    | Преимущества                               |
| ----------- | --------------------------------------------- | ------------------------------------------ |
| kube-bench  | Проверка соответствия стандартам CIS          | Поддержка CIS Benchmarks, детальные отчёты |
| kube-hunter | Поиск уязвимостей в кластере                  | Простота использования, сканирование сети  |
| Polaris     | Проверка лучших практик                       | Интеграция с Kubernetes, дашборд           |
| OpenSCAP    | Сканирование узлов на соответствие стандартам | Поддержка SCAP, глубокий анализ            |

- **Иконки**:        
	- 🔍 — для аудита.
    - 📋 — для отчётности.
    - 🔒 — для безопасности.
- **Фон**: Светлый с акцентом на инструментах и процессе аудита.

---

2. **Демо-сценарий** Показать **живые примеры**:
    - Запуск проверки кластера с **kube-bench**:
         ```
         kube-bench run --targets node,etcd,controlplane
         ```
    - Сканирование кластера на уязвимости с **kube-hunter**:        
         ```
         kube-hunter --pod --report yaml
         ```
    - Проверка манифестов с **Polaris**:        
         ```
         polaris audit --audit-path ./manifests --format score
         ```

---

3. **Ключевые тезисы**
    - **Аудит кластера** — это **проверка безопасности и соответствия стандартам**.
    - **kube-bench**:
        - Проверяет кластер на **соответствие стандартам CIS**.
        - Генерирует **детальные отчёты** с рекомендациями по исправлению.
    - **kube-hunter**:
        - Ищет **уязвимости** в кластере, включая сетевые и конфигурационные проблемы.
        - Поддерживает **разные режимы сканирования** (внутри кластера и снаружи).
    - **Polaris**:
        - Проверяет **манифесты и ресурсы** на соответствие лучшим практикам.
        - Поддерживает **разные форматы отчётов** (CLI, Dashboard).
    - **OpenSCAP**:
        - Сканирует **узлы кластера** на соответствие стандартам безопасности.
        - Использует **SCAP-профили** для глубокого анализа.
    - **Аудит и Compliance** помогают **обеспечить безопасность** и **соблюдение стандартов**.

---

4. **Описание (для выступающего)**
    - **Аудит кластера** — это **необходимый процесс** для обеспечения безопасности и соответствия стандартам.
    - **kube-bench** — это **стандарт де-факто** для проверки соответствия CIS Benchmarks.
    - **kube-hunter** помогает **выявлять уязвимости**, которые могут быть использованы злоумышленниками.
    - **Polaris** позволяет **проверять манифесты** на соответствие лучшим практикам.
    - **OpenSCAP** обеспечивает **глубокий анализ узлов** на соответствие стандартам безопасности.
    - Важно подчеркнуть, что **регулярный аудит** помогает **предотвратить проблемы** и **обеспечить соответствие стандартам**.

---

5. **Связь с прошлыми материалами**
    - В презентации 2019 года упоминался **kube-bench** как инструмент для проверки соответствия CIS.
    - В чате обсуждались **проблемы с настройкой kube-hunter** и преимущества **Polaris**.
    - Вопросы из чата:
        - _"Как часто нужно проводить аудит кластера?"_ → Регулярно, особенно после изменений конфигурации.
        - _"Можно ли автоматизировать аудит?"_ → Да, с помощью **CI/CD и скриптов**.

---

6. **Типовые вопросы и ответы (Q&A)**
    - **Вопрос:** _"Какой инструмент выбрать для начала?"_ **Ответ:** **kube-bench** — для проверки соответствия CIS.
    - **Вопрос:** _"Можно ли использовать kube-hunter в продакшн-среде?"_ **Ответ:** Да, но **осторожно**, чтобы не нарушить работу кластера.
    - **Вопрос:** _"Как интегрировать Polaris в CI/CD?"_ **Ответ:** Настроить **автоматическую проверку** манифестов на этапе развёртывания.
