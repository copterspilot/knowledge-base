#### **Описание слайда**

1. **Визуальный ряд**
    - **Примеры команд** с подсветкой синтаксиса:
         ```
         kubectl exec -it <pod-name> -- /bin/bash
         kubectl cp <pod-name>:/path/to/file ./local/path
         kubectl port-forward pod/<pod-name> 8080:80
         ```
    - **Схема взаимодействия**:
        - Слева: Локальная машина.
        - Справа: Под в кластере.
        - Стрелки, показывающие направление передачи данных (`exec`, `cp`, `port-forward`).
    - **Иллюстрации**:
        - Терминал с открытой сессией `exec`.
        - Пример копирования файла (`cp`).
        - Схема проброса портов (`port-forward`).
    - **Иконки**:
        - 🚀 — для `exec` (запуск команд в поде).
        - 📁 — для `cp` (копирование файлов).
        - 🔌 — для `port-forward` (проброс портов).
    - **Фон**: Тёмный (для контраста с терминальным выводом).

---

2. **Демо-сценарий** Показать **живые примеры**:
    - Подключиться к поду и запустить интерактивную оболочку:
         ```
         kubectl exec -it <pod-name> -- /bin/bash
         ```
    - Скопировать файл из пода на локальную машину:
         ```
         kubectl cp <pod-name>:/app/config.json ./config.json
         ```
    - Пробросить порт для доступа к веб-приложению в поде:
        ```
        kubectl port-forward pod/<pod-name> 8080:80
        ```
        Затем открыть `http://localhost:8080` в браузере.

---

3. **Ключевые тезисы**
    - **`kubectl exec`** — позволяет **запускать команды** внутри контейнера пода:
        - Полезно для **отладки** и выполнения административных задач.
        - Поддерживает **интерактивный режим** (`-it`).
    - **`kubectl cp`** — копирует **файлы** между локальной машиной и подом:
        - Удобно для **обмена конфигурационными файлами** или логами.
    - **`kubectl port-forward`** — пробрасывает **порты** с пода на локальную машину:
        - Позволяет **тестировать сервисы** без прямого доступа к кластеру.
        - Полезно для отладки **веб-приложений** или API.
    - Эти команды **расширяют возможности диагностики** и взаимодействия с кластером.

---

4. **Описание (для выступающего)**
    - **`kubectl exec`** — это **"швейцарский нож"** для отладки: позволяет запускать любые команды внутри контейнера, как если бы вы были внутри него.
    - **Важно**: Использовать `-it` для интерактивных сессий (например, запуск `bash`).
    - **`kubectl cp`** удобен для **быстрого обмена файлами**, но не заменяет полноценные системы резервного копирования.
    - **`kubectl port-forward`** — это **"туннель"** для доступа к сервисам в кластере, но **не подходит для высоких нагрузок** (трафик идёт через `kube-apiserver`).
    - Подчеркнуть, что эти команды **незаменимы** для отладки, но требуют **осторожности** (например, изменения в поде через `exec` не сохранятся после пересоздания).

---

5. **Связь с прошлыми материалами**
    - В презентации 2019 года эти команды также упоминались как ключевые для взаимодействия с подами.
    - В субтитрах обсуждалось, как **`port-forward`** помогает тестировать сервисы без публичного доступа.
    - Вопросы из чата:
        - _"Можно ли скопировать файл из локальной машины в под?"_ → Да: `kubectl cp ./local/file <pod-name>:/path/in/pod`.
        - _"Почему `port-forward` отключается, если под перезапускается?"_ → Потому что проброс привязан к конкретному поду.

---

6. **Типовые вопросы и ответы (Q&A)**
    - **Вопрос:** _"Как запустить команду в конкретном контейнере пода?"_ **Ответ:** Указать контейнер через `-c`: `kubectl exec -it <pod-name> -c <container-name> -- /bin/bash`.
    - **Вопрос:** _"Можно ли пробросить порт на сервис, а не на под?"_ **Ответ:** Да: `kubectl port-forward service/<service-name> 8080:80`.
    - **Вопрос:** _"Что делать, если `port-forward` не работает?"_ **Ответ:** Проверить, доступен ли под (`kubectl get pods`) и правильно ли указаны порты.

7. **Примеры использования / Типовые сценарии**
    - **Сценарий 1:** Нужно отладить приложение в поде. Подключаемся через `exec` и запускаем `bash`.
    - **Сценарий 2:** Требуется скопировать конфигурационный файл из пода. Используем `kubectl cp`.
    - **Сценарий 3:** Нужно протестировать веб-приложение в поде. Пробрасываем порт с помощью `port-forward`.
