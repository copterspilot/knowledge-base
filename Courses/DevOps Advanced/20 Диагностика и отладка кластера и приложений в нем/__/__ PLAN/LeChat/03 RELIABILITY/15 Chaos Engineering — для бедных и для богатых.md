**Chaos Engineering: инструменты и подходы для тестирования устойчивости систем**

---

#### **Описание слайда**

1. **Визуальный ряд**
    - **Логотипы инструментов**:
        - **Chaos Mesh** (для сложных сценариев в Kubernetes).
        - **Litmus Chaos** (для управляемого хаос-тестирования).
        - **Pumba** (для простых сценариев).
        - **Gremlin** (коммерческое решение).
    - **Сравнительная таблица инструментов**:

| Инструмент       | Тип          | Основные возможности                   | Сложность настройки |
| ---------------- | ------------ | -------------------------------------- | ------------------- |
| **Chaos Mesh**   | Продвинутый  | Поддержка Kubernetes, сложные сценарии | Высокая             |
| **Litmus Chaos** | Управляемый  | CRD для Kubernetes, интеграция с CI/CD | Средняя             |
| **Pumba**        | Простой      | Убийство контейнеров, сетевые задержки | Низкая              |
| **Gremlin**      | Коммерческий | Полноценная платформа, поддержка       | Высокая             |

- **Иконки**:
	- 🎲 — для хаос-тестирования.
    - 💥 — для инъекции сбоев.
    - 🔄 — для тестирования устойчивости.
- **Фон**: Тёмный с акцентом на инструментах и сценариях.

2. **Демо-сценарий** Показать **живые примеры**:
    - Запуск простого хаос-теста с **Pumba** (убийство контейнера):
         ```
         pumba kill --signal SIGKILL <container-name>
         ```
    - Создание сложного сценария с **Chaos Mesh** (сетевые задержки):
         ```
         apiVersion: chaos-mesh.org/v1alpha1
         kind: NetworkChaos
         metadata:
           name: network-delay
         spec:
           action: delay
           mode: one
           selector:
             namespaces:
               - default
           delay:
             latency: "100ms"
         ```
    - Запуск управляемого хаос-теста с **Litmus Chaos**:
         ```
         kubectl apply -f https://litmuschaos.github.io/litmus/chaos-operator.yaml
         ```

---

3. **Ключевые тезисы**
    - **Chaos Engineering** — это **намеренное внесение сбоев** для проверки устойчивости систем.
    - **Для "бедных"** (простые инструменты):
        - **Pumba**: простой инструмент для убийства контейнеров и сетевых задержек.
        - **Chaos Toolkit**: открытая платформа для создания хаос-тестов.
    - **Для "богатых"** (продвинутые инструменты):
        - **Chaos Mesh**: сложные сценарии для Kubernetes.
        - **Litmus Chaos**: управляемый хаос с поддержкой CRD.
        - **Gremlin**: коммерческая платформа с полной поддержкой.
    - **Цель хаос-тестирования** — **повышение надёжности** систем за счёт выявления слабых мест.

---

4. **Описание (для выступающего)**
    - **Chaos Engineering** помогает **выявить скрытые проблемы** в распределённых системах.
    - **Простые инструменты** (например, **Pumba**) подходят для **быстрого тестирования** без сложной настройки.
    - **Продвинутые инструменты** (например, **Chaos Mesh**, **Litmus Chaos**) позволяют **создавать сложные сценарии** и интегрироваться с CI/CD.
    - Важно подчеркнуть, что **хаос-тестирование должно быть контролируемым** и не наносить вреда продакшн-среде.
    - Упомянуть, что **Gremlin** — это **коммерческое решение** с расширенными возможностями.

6. **Типовые вопросы и ответы (Q&A)**
    - **Вопрос:** _"Какой инструмент выбрать для начала?"_ **Ответ:** **Pumba** — простой и эффективный.
    - **Вопрос:** _"Можно ли тестировать продакшн-среду?"_ **Ответ:** Нет, только в **тестовых или staging-средах**.
    - **Вопрос:** _"Как интегрировать хаос-тестирование в CI/CD?"_ **Ответ:** Использовать **Litmus Chaos** или **Chaos Mesh** с автоматическими пайплайнами.
