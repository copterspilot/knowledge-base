### **03 kubectl — главный проводник**

**1. Визуальный ряд:**
*   Крупная стилизованная иконка или логотип `kubectl`
*   Скриншот терминала с выполнением команд: `kubectl version --client` и `kubectl cluster-info`
*   Схематичное изображение: `kubectl` как мост между пользователем и Kubernetes API
*   Текст: "kubectl — это CLI для взаимодействия с Kubernetes API"

**2. Демо-сценарий:**
*   Live-демонстрация в терминале:
    ```bash
    # Проверяем версию клиента
    kubectl version --client
    
    # Проверяем информацию о кластере
    kubectl cluster-info
    
    # Показываем текущий контекст
    kubectl config current-context
    
    # Показываем список доступных контекстов
    kubectl config get-contexts
    ```
*   Краткий показ структуры ~/.kube/config (без показа чувствительных данных)

**3. Ключевые тезисы:**
*   "kubectl — это ваш основной инструмент для любого взаимодействия с кластером"
*   "Все, что можно сделать через UI — делается через kubectl под капотом"
*   "Первые команды для проверки: version — проверить версию, cluster-info — проверить подключение"
*   "kubectl конфигурируется через kubeconfig файл (~/.kube/config)"
*   "Важно понимать: kubectl не управляет кластером напрямую, а общается с API-сервером"

**4. Описание для выступающего:**
Необходимо подчеркнуть фундаментальную важность kubectl как основного инструмента. Объяснить архитектурный принцип — взаимодействие через API-сервер. Показать базовые команды для "здравствуй, мир!". Убедиться, что у всех участников есть базовый доступ к кластеру для дальнейших демонстраций.

**5. Связь с прошлыми материалами:**
*   Из чата: "Главный инструмент администратора - это kubectl" (из старой презентации)
*   Из субтитров: "kubectl для самых маленьких" (базовое введение в инструмент)
*   Из чата: "Всем с вечером!" -> начать с простых и понятных команд для вовлечения аудитории

**6. Типовые вопросы и ответы (Q&A):**
*   **В:** Что делать если `kubectl cluster-info` не работает?
    *   **О:** Проверить kubeconfig файл, контекст, права доступа и доступность API-сервера
*   **В:** Как выбрать версию kubectl?
    *   **О:** Рекомендуется использовать версию kubectl в пределах ±1 минорной версии от кластера
*   **В:** Чем отличается kubectl от dashboard?
    *   **О:** Dashboard — это веб-интерфейс, который использует kubectl под капотом

**7. Типовые примеры/сценарии:**
*   **Сценарий:** Новый сотрудник подключается к кластеру в первый раз
*   **Действия:** 
    1. Проверить версию kubectl
    2. Проверить текущий контекст
    3. Проверить доступность кластера
    4. Просмотреть базовую информацию о кластере
*   **Пояснение:** Эти команды должны стать рефлекторными для начала работы с любым кластером
