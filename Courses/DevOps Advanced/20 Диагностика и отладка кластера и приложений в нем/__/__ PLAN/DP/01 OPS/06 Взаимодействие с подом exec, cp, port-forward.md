### **06 Взаимодействие с подом: exec, cp, port-forward**

**1. Визуальный ряд:**
*   Скриншот терминала с примерами команд:
    ```bash
    kubectl exec -it <pod-name> -- /bin/bash
    kubectl cp <pod-name>:/path/to/file ./local-file
    kubectl port-forward <pod-name> 8080:80
    ```
*   Схема работы port-forward: Локальная машина -> API Server -> Pod
*   Диаграмма: Различные способы доступа к подам (exec, cp, port-forward)
*   Иконки: 🔄 (взаимодействие), 📡 (проброс портов), 📁 (копирование файлов)

**2. Демо-сценарий:**
*   Live-демонстрация:
    ```bash
    # Интерактивное подключение к контейнеру
    kubectl exec -it nginx-pod -- /bin/bash
    ls /etc/nginx/
    cat /etc/nginx/nginx.conf
    exit

    # Копирование файлов из пода
    kubectl cp nginx-pod:/etc/nginx/nginx.conf ./nginx-config-backup.conf

    # Копирование файлов в под
    kubectl cp ./custom-config.conf nginx-pod:/tmp/

    # Проброс порта для доступа к приложению
    kubectl port-forward nginx-pod 8080:80 &
    curl http://localhost:8080
    ```

**3. Ключевые тезисы:**
*   "`kubectl exec` — ваш SSH для контейнеров: для отладки и диагностики напрямую"
*   "`kubectl cp` — безопасное копирование файлов когда SCP недоступен"
*   "`kubectl port-forward` — быстрый доступ к сервисам без настройки Ingress/LoadBalancer"
*   "Port-forward работает через API server — идеально для временного доступа"
*   "Используйте `-c` для выбора конкретного контейнера в поде"

**6. Типовые вопросы и ответы (Q&A):**
*   **В:** Что делать если в контейнере нет bash?
    *   **О:** Использовать `/bin/sh` или другие доступные оболочки
*   **В:** Как копировать файлы рекурсивно?
    *   **О:** Добавлять `-r` флаг для рекурсивного копирования
*   **В:** Port-forward останавливается при разрыве соединения?
    *   **О:** Да, это временное решение. Для постоянного доступа нужен Ingress

**7. Типовые примеры/сценарии:**
*   **Сценарий:** Диагностика проблем с конфигурацией nginx
*   **Действия:**
    1. `kubectl exec` — проверить конфигурационные файлы
    2. `kubectl cp` — скопировать конфиги для анализа
    3. `kubectl port-forward` — проверить работу сервиса локально
*   **Пояснение:** Комбинация этих команд позволяет полностью проанализировать работу сервиса
