**1. Визуальный ряд:**
*   Сравнительная таблица подходов:

| Метод                                | Сложность | Безопасность      | Автоматизация |
| ------------------------------------ | --------- | ----------------- | ------------- |
| **Для "бедных"** (ручное)            | Низкая    | ❌ Высокий риск   | ❌            |
| **Для "богатых"** (Litmus/ChaosMesh) | Высокая   | ✅ Контролируемый | ✅            |
   
*   Примеры "бедных" методов:
    ```bash
    # Ручной chaos
    kubectl delete pod --selector=app=critical --force
    kubectl cordon node <node-name>
    iptables -A INPUT -p tcp --dport 80 -j DROP
    ```
*   Архитектура LitmusChaos: ChaosCenter, ChaosEngine, ChaosExperiments
*   Скриншот дашборда ChaosMesh с запущенными экспериментами
*   Принцип "гипотеза -> эксперимент -> вывод"

**2. Демо-сценарий:**
*   Демонстрация контролируемого хаоса:
    ```bash
    # Установка Litmus
    kubectl apply -f https://litmuschaos.github.io/litmus/2.14.0/litmus-2.14.0.yaml
    
    # Запуск эксперимента с отказом пода
    kubectl apply -f pod-delete-experiment.yaml
    
    # Мониторинг эксперимента
    kubectl get chaosresults
    ```
*   Показать разницу между хаотичным и контролируемым подходом

**3. Ключевые тезисы:**
*   "Chaos Engineering — это не ломание ради ломания, а проверка гипотез о надежности"
*   "Ручные методы ('для бедных') — опасны но иногда необходимы для быстрой проверки"
*   "LitmusChaos/ChaosMesh ('для богатых') — безопасные, контролируемые, измеримые эксперименты"
*   "Начинайте с малого: один эксперимент в неделю в staging среде"
*   "Извлекайте уроки из каждого эксперимента и улучшайте систему"

**6. Типовые вопросы и ответы (Q&A):**
*   **В:** С чего начать внедрение chaos engineering?
    *   **О:** С простых экспериментов в staging: удаление одного пода, временная недоступность сети
*   **В:** Как убедить руководство в необходимости хаос-тестов?
    *   **О:** Посчитать стоимость простоя и показать как хаос-тесты снижают риски
*   **В:** Можно ли запускать в продакшене?
    *   **О:** Только после успешных тестов в staging и с полным пониманием рисков

**7. Типовые примеры/сценарии:**
