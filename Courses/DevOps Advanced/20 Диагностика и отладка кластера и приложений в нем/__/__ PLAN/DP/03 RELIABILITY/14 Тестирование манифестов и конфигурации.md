**1. Визуальный ряд:**
*   Сравнительная таблица инструментов тестирования:
   
| Инструмент     | Тип тестирования   | Язык | Интеграция с CI |
| -------------- | ------------------ | ---- | --------------- |
| **KUTTL**      | e2e тесты          | YAML | ✅              |
| **Terratest**  | Интеграционные     | Go   | ✅              |
| **kube-score** | Статический анализ | -    | ✅              |
| **conftest**   | Политики (OPA)     | Rego | ✅              |
| **kubeval**    | Валидация схемы    | -    | ✅              |
   
*   Пример кода KUTTL теста:
    ```yaml
    apiVersion: kuttl.dev/v1beta1
    kind: TestAssert
    commands:
    - command: kubectl get pod/my-app -o jsonpath='{.status.phase}'
      expect: Running
    ```
*   Схема работы CI/CD pipeline с тестами
*   Скриншот отчета тестирования в GitLab CI/GitHub Actions

**2. Демо-сценарий:**
*   Live-демонстрация тестирования:
    ```bash
    # Статический анализ манифестов
    kube-score score deployment.yaml
    
    # Проверка на соответствие политикам
    conftest test deployment.yaml -p policies/
    
    # Запуск KUTTL тестов
    kubectl kuttl test --start-kind=false
    ```

**6. Типовые вопросы и ответы (Q&A):**
*   **В:** Что важнее: статический анализ или e2e тесты?
    *   **О:** Нужно и то и другое: статика ловит синтаксические ошибки, e2e — логические
*   **В:** Как начать внедрять тестирование?
    *   **О:** Начать с kube-score в pre-commit, затем добавить KUTTL для критичных компонентов
*   **В:** Нужны ли тесты для всех манифестов?
    *   **О:** В идеале — да, но начинайте с самых критичных

**7. Типовые примеры/сценарии:**
*   **Сценарий:** Тестирование Helm-чарта

*   **Результат:** Гарантия что чарт работает правильно в любом окружении
