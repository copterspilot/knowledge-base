Тема занятия: "Обеспечение безопасности в Kubernetes"

---

### Определение целей занятия

**Цели занятия**
- настраивать RBAC, NetworkPolicies, PodSecurityPolicies;   
- сканировать образы на уязвимости;

**Основные цели**
- Настраивать и применять **Role-Based Access Control (RBAC)** для управления доступом пользователей и сервисных аккаунтов.
- Реализовывать и применять **Pod Security Standards (PSS)** с помощью встроенного **Pod Security Admission (PSA)**.
- Создавать и управлять **сетевыми политиками (NetworkPolicy)** для изоляции подов и контроля трафика между ними.
- Сканировать Docker-образы на наличие уязвимостей (CVE) с помощью инструментов `Trivy` или `Grype`.

**Связанные цели**
- Проверять Kubernetes-манифесты на соответствие best practices с помощью `polaris` и `kube-score`.
- Применять политики безопасности на уровне admission-контроллера с помощью `Kyverno` и `OPA/Gatekeeper`.
- Обеспечивать безопасность цепочки поставок (Supply Chain Security) с помощью `cosign` (подпись образов) и `Syft` (генерация SBOM).
- Аудировать конфигурацию кластера на соответствие стандартам безопасности (например, CIS Benchmarks) с помощью `kube-bench`.
- Управлять секретами с помощью `Sealed Secrets` и интегрировать внешние хранилища секретов (например, HashiCorp Vault).

### Закрепляемые на занятии навыки

---

#### **Общие (фундаментальные для понимания базовых)**

*   **Понимание принципа многоуровневой защиты (Defense in Depth):** Способность объяснить, почему безопасность в Kubernetes требует нескольких слоев (хост, контейнер, сеть, приложение).
*   **Понимание принципа наименьших привилегий (Least Privilege):** Понимание, что субъектам (пользователям, сервисным аккаунтам) должны предоставляться только те права, которые им строго необходимы.
*   **Понимание жизненного цикла приложения (Shift-Left Security):** Осознание того, что безопасность начинается на этапе разработки и CI/CD, а не после развертывания в production.
*   **Понимание архитектуры Kubernetes:** Базовое понимание компонентов control plane (API-сервер, etcd, kubelet) и их роли в безопасности.

#### **Базовые (основные по теме)**

*   **Настройка RBAC:** Умение создавать `Role`/`ClusterRole` и `RoleBinding`/`ClusterRoleBinding` для управления доступом пользователей и сервисных аккаунтов.
*   **Проверка прав доступа:** Умение использовать команды `kubectl auth can-i` и `kubectl who-can` для диагностики прав.
*   **Настройка сетевых политик:** Умение создавать `NetworkPolicy` для изоляции подов и контроля трафика между ними.
*   **Применение Pod Security Standards (PSS):** Умение настраивать встроенный `Pod Security Admission (PSA)` с уровнями `baseline` и `restricted` для изоляции подов.
*   **Сканирование образов:** Умение использовать `Trivy` или `Grype` для поиска уязвимостей (CVE) в Docker-образах на этапе CI/CD.
*   **Управление секретами:** Понимание рисков хранения `Secrets` в Git и умение использовать `Sealed Secrets` для безопасного хранения.

#### **Продвинутые (выходящие за рамки базовых)**

*   **Применение политик безопасности:** Умение устанавливать и настраивать адмит-контроллеры `Kyverno` или `OPA/Gatekeeper` для автоматического принудительного применения политик (например, "все образы должны быть из внутреннего реестра").
*   **Обеспечение безопасности цепочки поставок (Supply Chain Security):** Умение использовать `cosign` для подписи образов и `Syft` для генерации SBOM (Software Bill of Materials).
*   **Аудит безопасности кластера:** Умение использовать `kube-bench` для проверки конфигурации кластера на соответствие стандартам CIS Benchmarks.
*   **Диагностика с помощью eBPF:** Умение использовать `inspektor-gadget` для трассировки системных вызовов, сетевых соединений и операций с файлами в реальном времени.
*   **Проверка манифестов:** Умение использовать `polaris`, `kube-score` или `conftest` для проверки Kubernetes-манифестов на соответствие best practices и выявления анти-паттернов.

#### **Экспертные (требующие опыта и погружения)**

*   **Интеграция политик в GitOps:** Умение настраивать `Kyverno` или `Gatekeeper` для проверки манифестов в процессе синхронизации Argo CD.
*   **Создание кастомных политик:** Умение писать сложные политики на языке Rego для `OPA/Gatekeeper`.
*   **Автоматизация ответа на инциденты:** Понимание концепций AIOps и способность настроить автоматическое реагирование на аномалии, обнаруженные с помощью `inspektor-gadget`.
*   **Внедрение Zero Trust:** Умение проектировать и внедрять модель Zero Trust с использованием Service Mesh (например, Istio) и mTLS.

#### **Связанные (зависимые навыки, выходящими за тему занятия)**

*   **Работа с CI/CD пайплайнами:** Умение интегрировать инструменты безопасности (`Trivy`, `polaris`) в системы вроде GitLab CI, GitHub Actions или Jenkins.
*   **Основы работы с Git и GitOps:** Понимание концепций GitOps и умение работать с Git как с "единственным источником истины".
*   **Основы сетевых технологий:** Понимание основ TCP/IP, DNS и принципов работы брандмауэров.
*   **Основы Linux и командной строки:** Уверенное владение командной строкой Linux и базовыми командами (`ps`, `netstat`, `find`).
*   **Основы криптографии:** Понимание принципов работы цифровых подписей, сертификатов и шифрования (для понимания `cosign` и `Sealed Secrets`).

#### **Доступные публичные ресурсы (прямые ссылки)**

Эти ресурсы являются открытыми и доступны без специальных прав доступа.

1.  **Официальная документация Kubernetes:**
    *   **Ссылка:** `https://kubernetes.io/docs/`
    *   **Описание:** Первый и главный источник истины по всем аспектам Kubernetes. Содержит руководства, концепции, справочную документацию и примеры. **Высоко рекомендуется для изучения.**

2.  **CNCF Landscape:**
    *   **Ссылка:** `https://landscape.cncf.io/`
    *   **Описание:** Интерактивная карта экосистемы облачных нативных технологий. Позволяет увидеть все проекты, входящие в CNCF, и понять, как они связаны между собой. Отличный инструмент для обзора рынка.

3.  **GitHub-репозитории с примерами кода:**
    *   **Ссылка (William Denniss):** `https://github.com/WilliamDenniss/kubernetes-for-developers`
    *   **Описание:** Репозиторий с примерами кода из книги Уильяма Денниса. Содержит практические манифесты и конфигурации.
    *   **Ссылка (John Strong):** `https://github.com/strongjz/Networking-and-Kubernetes`
    *   **Описание:** Репозиторий с примерами кода из книги Стронга Дж. и Лэнси В. по сетям в Kubernetes.

4.  **Проект eBPF:**
    *   **Ссылка:** `https://ebpf.io/`
    *   **Описание:** Официальный сайт проекта eBPF. Содержит документацию, новости, туториалы и информацию о проектах, использующих eBPF (Cilium, Falco, Hubble).

5.  **Проект Sigstore:**
    *   **Ссылка:** `https://sigstore.dev/`
    *   **Описание:** Инициатива для повышения безопасности цепочки поставок программного обеспечения. Является домом для инструментов `cosign`, `fulcio` и `rekor`.

6.  **Docker Hub:**
    *   **Ссылка:** `https://hub.docker.com/`
    *   **Описание:** Крупнейший публичный реестр Docker-образов. Место, где можно найти базовые образы и сторонние приложения.

7.  **Stack Overflow:**
    *   **Ссылка:** `https://stackoverflow.com/questions/tagged/kubernetes`
    *   **Описание:** Крупнейший форум для программистов. Раздел по Kubernetes содержит тысячи вопросов и ответов по решению практических проблем.
