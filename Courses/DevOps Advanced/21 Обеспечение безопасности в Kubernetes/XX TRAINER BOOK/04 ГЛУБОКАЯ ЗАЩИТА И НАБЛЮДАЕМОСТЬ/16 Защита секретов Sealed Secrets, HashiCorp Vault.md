### **Статья 16: Защита секретов: `Sealed Secrets`, `HashiCorp Vault`**

#### **Введение**

Представьте, что вы храните пароль от базы данных в манифесте Kubernetes. Даже если вы закодируете его в Base64, любой, у кого есть доступ к API-серверу или etcd, может легко его расшифровать. Это небезопасно. Решение — использовать специализированные инструменты. `Sealed Secrets` позволяет безопасно хранить секреты в Git-репозитории, а `HashiCorp Vault` предоставляет централизованную, мощную платформу для управления конфиденциальными данными. `Sealed Secrets` — это must-have для GitOps.

#### **Проблема: Уязвимость встроенного механизма Secrets**

Встроенные объекты `Secret` в Kubernetes не являются безопасным решением по умолчанию.
*   **Base64 — это не шифрование:** Base64 — это просто кодировка, а не криптография. Данные остаются читаемыми.
*   **Хранение в etcd:** Все секреты хранятся в etcd, и если этот компонент скомпрометирован, все секреты становятся доступны.
*   **Отсутствие ротации:** Встроенные `Secret` не поддерживают автоматическую ротацию.

#### **`Sealed Secrets`: Безопасность для GitOps**

`Sealed Secrets` — это проект от Bitnami, который решает проблему хранения секретов в системе управления версиями.

*   **Как это работает:**
    1.  **Шифрование:** Вы шифруете ваш объект `Secret` с помощью публичного ключа с помощью утилиты `kubeseal`. Результат — объект `SealedSecret`.
    2.  **Хранение:** Вы можете безопасно сохранить `SealedSecret` в ваш Git-репозиторий.
    3.  **Расшифровка:** Когда `SealedSecret` применяется к кластеру, контроллер `Sealed Secrets` использует приватный ключ (который хранится только в кластере) для расшифровки и создания обычного `Secret`.
*   **Преимущества:**
    *   **Идеален для GitOps:** Полностью совместим с подходами Argo CD и Flux.
    *   **Простота:** Легко установить и использовать.
    *   **Безопасность:** Расшифровка происходит только в кластере, что исключает риск утечки при хранении в Git.
*   **Ограничения:** Подходит для статических секретов. Не предоставляет функций централизованного управления и аудита.

#### **`HashiCorp Vault`: Централизованное управление**

`HashiCorp Vault` — это промышленное решение для управления секретами, которое выходит далеко за рамки возможностей встроенных `Secret`.

*   **Ключевые возможности:**
    *   **Динамические секреты:** Vault может генерировать временные учетные данные (например, для базы данных), которые автоматически отменяются после истечения срока действия.
    *   **Ротация:** Автоматическая ротация сертификатов и других секретов.
    *   **Аудит:** Полная запись всех операций с секретами.
    *   **Многоплатформенность:** Может управлять секретами не только для Kubernetes, но и для облачных провайдеров, баз данных и других систем.
*   **Интеграция с Kubernetes:**
    *   **Vault Agent Injector:** Автоматически внедряет `initContainer` в под, который извлекает секреты из Vault и помещает их в общую файловую систему.
    *   **CSI Driver for Secrets Store:** Монтирует секреты из Vault (и других хранилищ) как тома в под.
    *   **External Secrets Operator:** Синхронизирует секреты из Vault в объекты `Secret` Kubernetes.

#### **Заключение**

Выбор между `Sealed Secrets` и `HashiCorp Vault` зависит от ваших потребностей. Для небольших и средних команд, использующих GitOps, `Sealed Secrets` — отличный выбор благодаря своей простоте и безопасности. Для крупных предприятий с высокими требованиями к безопасности, аудиту и централизованному управлению, `HashiCorp Vault` — это промышленный стандарт.
