### **Статья 4: `kubectl auth can-i`: Проверка прав в реальном времени**

#### **Введение**

Представьте, что вы готовы развернуть приложение в production, но не уверены, достаточно ли у вас прав. Вместо того чтобы запускать команду и получать ошибку `Forbidden`, используйте `kubectl auth can-i`. Эта команда — ваш "радар безопасности", который позволяет проверить, разрешено ли вам выполнить определенное действие, прежде чем вы его совершите. Как указано в `Burns B., Villalba E., Strebel D., Evenson L. - Kubernetes Best Practices`, проверка прав — это простой, но эффективный способ предотвратить ошибки и инциденты.

#### **Что такое RBAC?**

Прежде чем использовать `can-i`, важно понимать, что лежит в основе: **RBAC (Role-Based Access Control)**. Это механизм управления доступом в Kubernetes, который определяет, кто (пользователь или сервисный аккаунт) может что делать (глагол: get, list, create, delete) с какими ресурсами (pods, services, secrets) в каком namespace.

#### **Как работает `kubectl auth can-i`**

Команда `auth can-i` отправляет запрос к API-серверу Kubernetes, чтобы проверить, соответствует ли ваш текущий контекст (пользователь, группы, сервисный аккаунт) какой-либо существующей роли или кластерной роли.

*   **Синтаксис:**
    ```bash
    kubectl auth can-i <verb> <resource> [-n <namespace>]
    ```
    *   `<verb>`: Действие (create, get, list, update, delete).
    *   `<resource>`: Ресурс Kubernetes (pods, deployments, secrets).
    *   `-n <namespace>`: Опционально, namespace, в котором проверяется доступ.

*   **Результат:** Команда возвращает `yes` или `no`.

#### **Практические примеры**

1.  **Проверка перед деплоем:**
    ```bash
    # Проверяем, можем ли мы создать поды в production
    kubectl auth can-i create pods -n production
    ```
    Если команда вернет `no`, вы сразу узнаете, что у вас недостаточно прав, и сможете обратиться к администратору, не прерывая рабочий процесс.

2.  **Проверка прав сервисного аккаунта:**
    ```bash
    # Проверяем, может ли сервисный аккаунт 'frontend-sa' читать секреты
    kubectl auth can-i --as=system:serviceaccount:default:frontend-sa get secrets
    ```
    Флаг `--as` позволяет проверить права от имени другого пользователя или сервисного аккаунта. Это полезно для отладки проблем с доступом.

3.  **Проверка на уровне кластера:**
    ```bash
    # Проверяем, можем ли мы создавать новые namespace
    kubectl auth can-i create namespaces
    ```
    Без указания `-n`, команда проверяет права на уровне кластера.

#### **Заключение**

`kubectl auth can-i` — это must-have инструмент для любого инженера, работающего с Kubernetes. Он позволяет избежать неприятных сюрпризов и упрощает диагностику проблем с доступом. В следующей статье мы рассмотрим RBAC более глубоко, на практике.
