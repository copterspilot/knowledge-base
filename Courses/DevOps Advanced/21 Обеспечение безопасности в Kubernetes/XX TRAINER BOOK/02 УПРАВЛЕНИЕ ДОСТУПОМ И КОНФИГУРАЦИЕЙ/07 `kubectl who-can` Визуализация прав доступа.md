### **Статья 7: `kubectl who-can`: Визуализация прав доступа**

#### **Введение**

`kubectl auth can-i` — отличный инструмент, чтобы проверить свои права. Но что, если вы хотите понять, **кто еще** в вашем кластере может выполнять опасные операции? Например, кто может создавать поды в production или читать секреты? Для этого существует `kubectl who-can`. Этот плагин анализирует все роли и привязки в кластере и предоставляет наглядный список всех субъектов, которые имеют право на выполнение указанного действия. Это must-have инструмент для аудита безопасности и отладки сложных конфигураций RBAC.

#### **Что такое `kubectl who-can`?**

`kubectl who-can` — это плагин для `kubectl`, который расширяет его функциональность. В отличие от встроенной команды `auth can-i`, которая проверяет права **одного** субъекта, `who-can` сканирует весь кластер, чтобы найти **всех** субъектов, которым разрешено выполнить действие.

*   **Принцип работы:** Плагин извлекает все объекты `Role`, `ClusterRole`, `RoleBinding` и `ClusterRoleBinding` и строит матрицу доступа. Затем он фильтрует эту матрицу по заданному действию и ресурсу.
*   **Установка:** Плагин устанавливается через `krew`:
    ```bash
    kubectl krew install who-can
    ```

#### **Практические примеры**

1.  **Аудит безопасности:**
    ```bash
    # Кто может читать секреты в namespace 'default'?
    kubectl who-can get secrets
    ```
    Эта команда покажет вам всех пользователей, группы и сервисные аккаунты, которые могут получить доступ к конфиденциальным данным. Это критически важно для соблюдения принципа минимальных привилегий.

2.  **Проверка доступа к production:**
    ```bash
    # Кто может создавать поды в namespace 'production'?
    kubectl who-can create pods -n production
    ```
    Если в списке окажутся неожиданные субъекты, это сигнал о том, что ваша конфигурация RBAC требует пересмотра.

3.  **Поиск причин инцидента:**
    ```bash
    # Кто мог удалить deployment?
    kubectl who-can delete deployments
    ```
    После инцидента эта команда поможет сузить круг подозреваемых, определив, какие учетные записи имели соответствующие права.

#### **Сравнение с `kubectl auth can-i`**

| Функция                 | `kubectl auth can-i`                  | `kubectl who-can`              |
|:----------------------- |:------------------------------------- |:------------------------------ |
| **Вопрос**              | "Могу ли *я* сделать это?"            | "Кто может сделать это?"       |
| **Субъект**             | Один (текущий или указанный с `--as`) | Все (в кластере или namespace) |
| **Установка**           | Встроена в `kubectl`                  | Требует установки через `krew` |
| **Основное применение** | Проверка перед выполнением операции   | Аудит и отладка RBAC           |

#### **Заключение**

`kubectl who-can` — это мощный инструмент для аудита безопасности и управления доступом. Он превращает сложную и запутанную конфигурацию RBAC в понятный и читаемый список. Используйте его регулярно, чтобы убедиться, что доступ к вашему кластеру контролируется и соответствует политикам вашей организации. В следующей статье мы рассмотрим, как контролировать трафик между подами с помощью `NetworkPolicy`.
