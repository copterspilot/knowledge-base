#### **A**

*   **Admission Controller (Адмит-контроллер):** Компонент API-сервера Kubernetes, который проверяет и изменяет объекты (например, поды, секреты) до их сохранения в etcd. Используется для принудительного применения политик безопасности (например, `Pod Security Admission`, `Kyverno`).
*   **AIOps (Искусственный интеллект для эксплуатации):** Использование искусственного интеллекта и машинного обучения для автоматизации задач эксплуатации, включая обнаружение аномалий, определение корневой причины инцидентов и предсказание проблем.
*   **Audit Logging (Аудит-логирование):** Функция Kubernetes, которая записывает все запросы к API-серверу. Используется для отслеживания действий пользователей и сервисных аккаунтов, что критически важно для compliance и расследования инцидентов.
*   **Автономная защита:** Концепция, при которой система безопасности способна самостоятельно обнаруживать, анализировать и реагировать на угрозы без вмешательства человека, используя автоматизацию, eBPF и AIOps.

#### **C**

*   **CIS Benchmark (CIS Benchmarks):** Стандартизированные рекомендации по безопасности от организации Center for Internet Security. `kube-bench` использует эти рекомендации для аудита конфигурации кластера Kubernetes.
*   **CNI (Container Network Interface):** Интерфейс и набор спецификаций для подключения контейнеров к сети. Решения вроде Calico, Cilium и Weave Net являются CNI-провайдерами, которые также реализуют `NetworkPolicy`.
*   **Container Runtime (Время выполнения контейнеров):** Программа, отвечающая за запуск и управление контейнерами (например, `containerd`, `CRI-O`). Безопасность контейнер-рантайма является критически важным слоем.

#### **D**

*   **Defence in Depth (Глубокая защита):** Стратегия безопасности, при которой применяется несколько слоев защиты (хост, контейнер, сеть, приложение), чтобы даже при проникновении злоумышленника через один слой другие оставались целыми.
*   **DevSecOps:** Культура и практика, при которой безопасность (Security) интегрируется в каждый этап жизненного цикла разработки (Dev) и эксплуатации (Ops), начиная с самого начала.

#### **E**

*   **eBPF (extended Berkeley Packet Filter):** Технология ядра Linux, позволяющая безопасно запускать программы внутри ядра. Используется для высокопроизводительной сетевой фильтрации, трассировки и безопасности (например, в `Cilium`, `inspektor-gadget`).
*   **Egress (Исходящий трафик):** Сетевой трафик, исходящий из пода или группы подов. `NetworkPolicy` может контролировать egress-трафик.
*   **Etcd:** Распределенное хранилище ключ-значение, которое является "единственным источником истины" для всех данных кластера Kubernetes. Его безопасность критически важна.

#### **G**

*   **GitOps:** Практика управления инфраструктурой и приложениями с помощью Git, где Git-репозиторий является "единственным источником истины". Инструменты вроде Argo CD автоматически синхронизируют состояние кластера с манифестами в Git.
*   **GitLeaks:** Инструмент для поиска секретов (паролей, токенов, ключей) в истории Git-репозитория.

#### **I**

*   **Ingress (Входящий трафик):** Сетевой трафик, поступающий в под или группу подов. `NetworkPolicy` может контролировать ingress-трафик.
*   **Ingress Controller:** Компонент, который реализует ресурс `Ingress`, обеспечивая доступ к сервисам извне кластера (например, через LoadBalancer).
*   **Inspektor-gadget:** Набор инструментов командной строки, основанный на eBPF, для диагностики и наблюдаемости в Kubernetes. Позволяет трассировать системные вызовы, сеть и файловую систему.

#### **K**

*   **krew:** Менеджер плагинов для `kubectl`. Позволяет легко устанавливать и использовать сторонние инструменты (например, `kubectl-debug`, `kubectl-who-can`).
*   **Kyverno:** Адмит-контроллер для Kubernetes, написанный на Go. Позволяет определять политики безопасности и управления конфигурацией на языке YAML. Идеален для простых и распространенных сценариев.

#### **L**

*   **Least Privilege (Принцип наименьших привилегий):** Фундаментальный принцип безопасности, согласно которому субъекту (пользователь, сервисный аккаунт) должны быть предоставлены только те права, которые ему **строго необходимы** для выполнения своей задачи.
*   **LLM (Large Language Model):** Большая языковая модель. В контексте безопасности используется для анализа логов и событий, генерации отчетов о корневой причине инцидентов и предоставления контекстных инсайтов.

#### **M**

*   **Manifest (Манифест):** Файл в формате YAML или JSON, который описывает желаемое состояние объекта Kubernetes (например, Deployment, Service, NetworkPolicy).
*   **Multi-tenancy (Мультитенантность):** Архитектура, при которой один и тот же кластер Kubernetes используется несколькими независимыми командами (тенантами). Безопасность и изоляция между тенантами являются ключевой задачей.

#### **N**

*   **Namespace (Пространство имен):** Логический изолятор в кластере Kubernetes. Позволяет разделить ресурсы между различными проектами, командами или средами (dev, staging, prod).
*   **NetworkPolicy (Сетевая политика):** Объект Kubernetes, который определяет, какой сетевой трафик разрешен для группы подов. Реализует принцип изоляции.
*   **Node (Узел):** Физическая или виртуальная машина, на которой запущены компоненты Kubernetes (kubelet, kube-proxy, container runtime). Безопасность узлов — это первый слой защиты.

#### **O**

*   **OPA (Open Policy Agent):** Общий, независимый от платформы движок политик. `Gatekeeper` — это реализация OPA для Kubernetes, использующая язык Rego для описания сложных политик.

#### **P**

*   **Pod Security Admission (PSA):** Встроенный в Kubernetes адмит-контроллер, который заменяет устаревшие PodSecurityPolicies (PSP). Применяет `Pod Security Standards`.
*   **Pod Security Standards (PSS):** Современные стандарты безопасности для подов, определяющие три уровня: `privileged`, `baseline`, `restricted`. Заменяют PSP.
*   **Pod (Под):** Наименьшая развертываемая единица в Kubernetes, которая может содержать один или несколько контейнеров. Является основным объектом для применения политик безопасности.
*   **Privileged Container (Привилегированный контейнер):** Контейнер, которому предоставлены права, эквивалентные правам root на хосте. Использование таких контейнеров является серьезной уязвимостью.
*   **Principle of Least Privilege (Принцип наименьших привилегий):** См. **Least Privilege**.

#### **R**

*   **RBAC (Role-Based Access Control / Управление доступом на основе ролей):** Система авторизации в Kubernetes, которая позволяет управлять доступом к ресурсам на основе ролей и привязок к субъектам (пользователи, группы, сервисные аккаунты).
*   **Resource Limits (Лимиты ресурсов):** Ограничения на использование CPU и памяти для контейнера. Помогают предотвратить "криптомайнинг" и нехватку ресурсов на узле.
*   **Root User (Пользователь root):** Администратор системы с полными правами. Запуск контейнеров от имени root является плохой практикой. Рекомендуется использовать `non-root` пользователей.

#### **S**

*   **SBOM (Software Bill of Materials / Ведомость материалов программного обеспечения):** Документ, перечисляющий все компоненты (библиотеки, зависимости) и их версии, из которых состоит приложение. Генерируется с помощью `Syft`.
*   **Secret (Секрет):** Объект Kubernetes для хранения чувствительной информации (пароли, токены). По умолчанию хранится в etcd в виде base64, что **не является безопасным**. Требует дополнительной защиты.
*   **Security Context (Контекст безопасности):** Поле в манифесте пода или контейнера, которое определяет права и привилегии, которые будут иметь процессы в контейнере (например, запуск от имени non-root).
*   **Sealed Secrets:** Решение для безопасного хранения секретов Kubernetes в Git. Секрет шифруется локально и расшифровывается только в кластере.
*   **Service Account (Сервисный аккаунт):** Специальный аккаунт для приложений, работающих в кластере Kubernetes. Используется для аутентификации подов в API-сервере.
*   **Shift-Left Security (Безопасность "сдвиг влево"):** Практика интеграции проверок безопасности как можно раньше в процесс разработки (в CI/CD), чтобы выявлять и устранять уязвимости до их попадания в production.
*   **Supply Chain Security (Безопасность цепочки поставок):** Комплексная практика обеспечения доверия ко всем компонентам приложения, от исходного кода до образов и зависимостей. Включает сканирование, подпись образов (`cosign`) и генерацию SBOM.

#### **T**

*   **Trivy:** Инструмент для сканирования образов контейнеров и файловых систем на наличие уязвимостей (CVE), конфигурационных ошибок и секретов.

#### **Z**

*   **Zero Trust (Ноль доверия):** Философия безопасности, согласно которой доверие не должно быть присвоено по умолчанию ни внутри, ни снаружи сети. Каждый запрос должен быть аутентифицирован и авторизован. В Kubernetes реализуется с помощью Service Mesh (например, Istio).

### **Рекомендуемые ресурсы для ознакомления**

1.  **`Lapaz Raul - Learning Kubernetes Security, 2nd Edition (2025)`**
    *   **Почему:** Самая свежая и всесторонняя книга по теме. Охватывает все ключевые аспекты, включая PSS, PSA, Supply Chain Security и eBPF, что делает ее идеальным справочником для 2025 года.

2.  **`Boorshtein Marc, Surovich Scott - Kubernetes An Enterprise Guide, 3rd Edition (2024)`**
    *   **Почему:** Отличное руководство для инженеров в корпоративной среде. Глубоко погружается в темы безопасности, включая детальное сравнение PSA, Kyverno и OPA/Gatekeeper.

3.  **`Burns B., Villalba E., Strebel D., Evenson L. - Kubernetes Best Practices (2024)`**
    *   **Почему:** Практическое руководство от одного из создателей Kubernetes. Предоставляет четкие, применимые на практике рекомендации по безопасности и другим аспектам.

4.  **`Stencel Grzegorz, Berton Luca - Kubernetes Recipes (2025)`**
    *   **Почему:** Книга в формате "рецептов" с конкретными решениями для повседневных задач. Идеальна для быстрого поиска решений по настройке Network Policies, RBAC и другим аспектам безопасности.

5.  **`Gkatziouras Emmanouil, Adams Rom, Xi Chen - Kubernetes Secrets Handbook (2024)`**
    *   **Почему:** Специализированная книга, полностью посвященная управлению секретами — одной из самых критичных тем безопасности.

6.  **Официальная документация Kubernetes - Безопасность**
    *   **Ссылка:** `https://kubernetes.io/docs/concepts/security/`
    *   **Почему:** Первый и главный источник истины. Всегда актуальна и содержит исчерпывающие сведения по всем аспектам безопасности.

7.  **Документация `inspektor-gadget`**
    *   **Ссылка:** `https://github.com/inspektor-gadget/inspektor-gadget`
    *   **Почему:** Лучший ресурс для изучения передовых инструментов диагностики и безопасности на основе eBPF.

8.  **Документация `Kyverno` и `Gatekeeper`**
    *   **Ссылки:** `https://kyverno.io/`, `https://open-policy-agent.github.io/gatekeeper/website/`
    *   **Почему:** Официальные документации, содержащие примеры, руководства и лучшие практики по написанию политик безопасности.
