### **Статья: Сравнение инструментов: `Trivy` vs `Checkov` vs `GitLeaks` (уязвимости, конфигурации, секреты)**

#### **Введение**

Представьте, что вы строите дом. Вы бы не стали использовать один и тот же инструмент для проверки фундамента, стен и электропроводки. Точно так же, в мире DevOps нет универсального "детектора угроз". Нужны специализированные инструменты для разных типов рисков. `Trivy`, `Checkov` и `GitLeaks` — это три таких "детектора", каждый из которых ищет свой тип "дефектов". Как указано в `combined.txt`, использование этих инструментов в связке — это must-have практика для современных DevOps-команд. В этой статье мы проведем детальное сравнение, чтобы вы понимали, когда и какой инструмент использовать.

#### **Часть 1: `Trivy`: Поиск уязвимостей (CVE)**

`Trivy` — это универсальный сканер безопасности, который в первую очередь ищет **известные уязвимости (CVE)**.

*   **Что проверяет:**
    *   **Образы контейнеров:** Находит CVE в базовом образе (например, `alpine`, `ubuntu`) и установленных пакетах.
    *   **Зависимости приложения:** Сканирует `package.json`, `requirements.txt`, `go.mod` и другие файлы для поиска уязвимых библиотек.
    *   **Конфигурации (IaC):** Проверяет манифесты Kubernetes, Terraform-файлы на наличие небезопасных настроек.
    *   **Секреты:** Может искать чувствительные данные (опционально).
*   **Идеальный сценарий:** Вы хотите убедиться, что ваш новый Docker-образ не содержит критических уязвимостей, таких как Log4Shell. Вы запускаете `trivy image my-app:latest`.
*   **Преимущество:** Широкий охват — один инструмент для нескольких задач.
*   **Источник:** `Lapaz Raul - Learning Kubernetes Security, 2nd Edition - 2025`, `Aversa Luigi - Security for Containers and Kubernetes - 2023`

#### **Часть 2: `Checkov`: Проверка конфигураций (IaC)**

`Checkov` — это статический анализатор кода инфраструктуры (Infrastructure as Code). Он ищет **анти-паттерны и нарушения best practices**.

*   **Что проверяет:**
    *   **Kubernetes манифесты:** Отсутствие `resources.limits`, запуск от `root`, небезопасные `securityContext`.
    *   **Terraform:** Небезопасные настройки облачных ресурсов (например, публичный S3-бакет).
    *   **CloudFormation, Pulumi, Dockerfile.**
*   **Идеальный сценарий:** Вы пишете новый манифест Kubernetes и хотите убедиться, что он соответствует рекомендациям безопасности. Вы запускаете `checkov -d ./k8s-manifests`.
*   **Преимущество:** Фокусируется именно на правильности конфигурации, а не на уязвимостях в коде или зависимостях.
*   **Источник:** `Stencel Grzegorz, Berton Luca - Kubernetes Recipes - 2025`, `Aversa Luigi - Security for Containers and Kubernetes - 2023`

#### **Часть 3: `GitLeaks`: Поиск секретов (Secrets)**

`GitLeaks` — это инструмент, предназначенный для одной задачи: **поиск чувствительных данных в коде**.

*   **Что проверяет:**
    *   **Токены API** (GitHub, AWS, Google Cloud).
    *   **Приватные ключи** (SSH, SSL).
    *   **Пароли и строки подключения.**
    *   Использует сигнатуры (patterns) для обнаружения сотен типов секретов.
*   **Идеальный сценарий:** Вы хотите предотвратить случайный коммит пароля базы данных в Git. Вы настраиваете `GitLeaks` как pre-commit хук или в CI/CD пайплайн.
*   **Преимущество:** Специализация и глубина поиска секретов, включая проверку истории коммитов.
*   **Источник:** `combined.txt`

#### **Часть 4: Практическое сравнение и интеграция**

| Критерий | **`Trivy`** | **`Checkov`** | **`GitLeaks`** |
| :--- | :--- | :--- | :--- |
| **Основное назначение** | Сканирование уязвимостей (CVE) | Проверка конфигураций (IaC) | Поиск секретов |
| **Где применяется** | В CI/CD при сборке образа | В CI/CD при изменении манифестов | В CI/CD и как pre-commit хук |
| **Пример команды** | `trivy image my-app:v1.2` | `checkov -d ./k8s-manifests` | `gitleaks detect --source .` |
| **Результат** | Список CVE с уровнем серьезности | Список нарушений best practices | Список найденных секретов |

#### **Часть 5: Сквозной сценарий: Комплексная проверка в CI/CD**

Вот как эти инструменты могут работать вместе в одном пайплайне:

```yaml
# .gitlab-ci.yml
stages:
  - security

pre-commit:
  stage: security
  script:
    # Проверяем, не коммитим ли мы случайно секреты
    - gitleaks detect --source . --no-git

scan-code:
  stage: security
  script:
    # Проверяем конфигурации на анти-паттерны
    - checkov -d . --soft-fail
    # Сканируем код на уязвимости (если используется Snyk, например)
    # - snyk test

build-and-scan:
  stage: security
  image: aquasec/trivy:latest
  script:
    # Собираем образ
    - docker build -t my-app:$CI_COMMIT_SHA .
    # Сканируем образ на уязвимости и конфигурации
    - trivy image --exit-code 1 --severity CRITICAL,HIGH my-app:$CI_COMMIT_SHA
```

#### **Чек-лист: Выбор инструмента**

| Вопрос | Ответ |
| :--- | :--- |
| Нужно ли найти уязвимости в Docker-образе? | Используйте **`Trivy`** |
| Нужно ли проверить манифест Kubernetes на best practices? | Используйте **`Checkov`** |
| Нужно ли предотвратить коммит пароля в Git? | Используйте **`GitLeaks`** |
| Можно ли обойтись одним инструментом? | Нет. Используйте все три для полного охвата. |

#### **Заключение**

`Trivy`, `Checkov` и `GitLeaks` — это не конкуренты, а **дополнения**. `Trivy` находит "дыры" в вашем коде и зависимостях, `Checkov` проверяет, правильно ли вы "собрали" вашу инфраструктуру, а `GitLeaks` следит за тем, чтобы вы не "выкинули ключи" в публичный доступ. Используя все три инструмента, вы создаете многоуровневую систему защиты. В следующей статье мы рассмотрим, как применять политики безопасности с помощью `Kyverno` и `OPA/Gatekeeper`.
