### **Топ-3: Самые горячие темы (Активно обсуждаются, быстро развиваются)**

1.  **AI-Driven Security: Автоматическое определение корневой причины (RCA) с помощью LLM**
    *   **Почему актуально:** Это "футуристическая" тема, которая активно муссируется в блогах (Google Chronicle, Microsoft Sentinel) и на конференциях. Сообщество обсуждает, как большие языковые модели (LLM) могут анализировать миллионы логов и событий, чтобы не просто показать ошибку, а сгенерировать отчет: "Сервис X ведет себя аномально, вероятная причина — истечение TTL сессии в Redis. Рекомендую проверить подключение." Это переход от реактивной к автономной безопасности.
    *   **Источник:** `Stencel Grzegorz, Berton Luca - Kubernetes Recipes - 2025`

2.  **eBPF Everywhere: Глубинная интроспекция ядра для безопасности и наблюдаемости**
    *   **Почему актуально:** eBPF стал фундаментом для многих современных инструментов. Сообщество активно обсуждает его применение за пределами сети (Cilium) — для безопасности (Falco), наблюдаемости (`inspektor-gadget`) и даже профилирования. Тема "eBPF как универсальный язык для ядра Linux" — это настоящий тренд.
    *   **Источник:** `Stencel Grzegorz, Berton Luca - Kubernetes Recipes - 2025`

3.  **Platform Engineering: Создание внутренних платформ для упрощения жизни разработчиков**
    *   **Почему актуально:** DevOps эволюционирует в Platform Engineering. Вместо того чтобы каждый разработчик знал все о Kubernetes, создается внутренняя платформа (IDP), которая предоставляет им простые, безопасные шаблоны. Это напрямую связано с безопасностью, так как платформа может встраивать best practices и политики безопасности "из коробки". Тема активно обсуждается как следующий шаг после DevOps.
    *   **Источник:** `Stencel Grzegorz, Berton Luca - Kubernetes Recipes - 2025`, `Salatino M. - Platform Engineering on Kubernetes - 2024`

### **Следующие 4: Ключевые и быстро растущие темы**

4.  **Zero Trust в Kubernetes: Реализация недоверия по умолчанию**
    *   **Почему актуально:** Концепция "никогда не доверяй, всегда проверяй" становится стандартом. Сообщество активно обсуждает, как реализовать это в Kubernetes: с помощью mTLS (через Istio или Cilium), строгих NetworkPolicy и политик безопасности (Kyverno, OPA).
    *   **Источник:** `Dubey S., Mandar J. Kulkarni - Hands-On Kubernetes, Service Mesh and Zero-Trust - 2023`

5.  **Автоматизация безопасности с помощью GitOps: От обнаружения до автоматического патча**
    *   **Почему актуально:** Практика GitOps позволяет автоматизировать весь цикл. Сообщество интересуется сценариями, где система автоматически обнаруживает уязвимость (CVE), создает PR с патчем и разворачивает его, минуя человека. Это путь к автономной защите.
    *   **Источник:** `Vinto Natale, Bueno Alex Soto - GitOps Cookbook. Kubernetes Automation in Practice - 2023`

6.  **Безопасность цепочки поставок (Supply Chain Security): `cosign`, `Syft`, SBOM**
    *   **Почему актуально:** После инцидентов вроде Log4j, безопасность цепочки поставок стала приоритетом. Сообщество активно использует и обсуждает проекты от CNCF, такие как Sigstore (`cosign` для подписи, `fulcio` для CA, `rekor` для журнала). Генерация SBOM (`Syft`) стала обязательной практикой.
    *   **Источник:** `Lapaz Raul - Learning Kubernetes Security, 2nd Edition - 2025`, `Aversa Luigi - Security for Containers and Kubernetes - 2023`

7.  **Сравнение инструментов: `Trivy` vs `Checkov` vs `GitLeaks` (уязвимости, конфигурации, секреты)**
    *   **Почему актуально:** Разработчики и инженеры безопасности часто путаются в выборе инструментов. Активно обсуждается, когда использовать `Trivy` (уязвимости), `Checkov` (конфигурации IaC) и `GitLeaks` (поиск секретов в коде). Понимание их специализации — ключ к построению комплексной защиты.
    *   **Источник:** `Lapaz Raul - Learning Kubernetes Security, 2nd Edition - 2025`

### **Фундаментальные темы: Всегда важны, но обсуждаются как основы**

8.  **Практическое руководство по Pod Security Standards (PSS)**
    *   **Почему актуально:** PSS заменили устаревшие Pod Security Policies (PSP). Это must-have тема для любого, кто настраивает кластер. Обсуждения сосредоточены на практическом применении уровней `baseline` и `restricted`.
    *   **Источник:** `Lapaz Raul - Learning Kubernetes Security, 2nd Edition - 2025`, `Уильям Д. - Kubernetes для разработчиков (Для профессионалов) - 2025`

9.  **Полное руководство по RBAC: На практике**
    *   **Почему актуально:** Управление доступом — основа безопасности. Тема вечна, но всегда востребована. Сообщество ищет четкие руководства по созданию ролей, привязок и, особенно, по проверке прав с помощью `kubectl auth can-i` и `kubectl who-can`.
    *   **Источник:** `Burns B., Villalba E., Strebel D., Evenson L. - Kubernetes Best Practices - 2024`, `Бранд А., Ландер Р., Россо Д., Харрис Д. - Kubernetes на практике - 2022`

10. **Сетевые политики (NetworkPolicy): Контроль трафика между подами**
    *   **Почему актуально:** Безопасность на сетевом уровне критически важна для предотвращения "бокового перемещения" (lateral movement) злоумышленника. Тема фундаментальна и всегда востребована для понимания изоляции рабочих нагрузок.
    *   **Источник:** `Ibryam Bilgin, Huss Roland - Kubernetes Patterns, 2nd Edition - 2023`, `Бранд А., Ландер Р., Россо Д., Харрис Д. - Kubernetes на практике - 2022`


### **ТОП статей для по теме занятия**

11.  **Shift-Left Security: Практическое руководство по `Trivy` и `cosign`**
    *   **Почему подходит:** Объединяет сканирование образов (`Trivy`) и подпись (`cosign`) в единую практику "Shift-Left", что идеально соответствует философии DevOps.
    *   **Источник:** `Lapaz Raul - Learning Kubernetes Security, 2nd Edition - 2025`

12.  **Автоматизация безопасности с помощью `Kyverno` и `OPA/Gatekeeper`**
    *   **Почему подходит:** Показывает, как перейти от ручной проверки к автоматическому блокированию небезопасных конфигураций на уровне admission-контроллера, что является продвинутой практикой DevOps.
    *   **Источник:** `combined.txt`, `Chowdhury Soumiyajit Das - Mastering DevOps in Kubernetes - 2024`

13.  **Аудит безопасности кластера: `kube-bench` и `Kubescape`**
    *   **Почему подходит:** Раскрывает цель аудита, предлагая не только `kube-bench`, но и более современный инструмент `Kubescape`, что показывает эволюцию подходов.
    *   **Источник:** `Lapaz Raul - Learning Kubernetes Security, 2nd Edition - 2025`

14.  **Управление секретами в Kubernetes: `Sealed Secrets` и HashiCorp Vault**
    *   **Почему подходит:** Охватывает два основных подхода к управлению секретами — от простого (`Sealed Secrets`) до промышленного (`Vault`), что дает полную картину.
    *   **Источник:** `Gkatziouras Emmanouil, Adams Rom, Xi Chen - Kubernetes Secrets Handbook - 2024`, `DevOps Advanced`

15.  **Проверка манифестов: `polaris`, `kube-score`, `conftest`**
    *   **Почему подходит:** Предлагает сравнение инструментов для проверки best practices, что помогает слушателям выбрать подходящий для их стека.
    *   **Источник:** `combined.txt`, `Aversa Luigi - Security for Containers and Kubernetes - 2023`
