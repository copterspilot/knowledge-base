### **Статья 8: Применение политик безопасности: `Kyverno`, `OPA/Gatekeeper`**

#### **Что такое адмит-контроллеры?**

Представьте, что API-сервер Kubernetes — это охранник у ворот кластера. Каждый раз, когда вы хотите создать под, деплоймент или секрет, вы подаете запрос (REST API). Охранник проверяет вашу "пропускную карту" (RBAC) и решает, можно ли вас впустить.

**Адмит-контроллер (Admission Controller)** — это как **дополнительный слой проверки**. Даже если у вас есть пропуск (RBAC), этот контроллер может остановить вас и спросить: "А точно ли ваш под соответствует политике безопасности компании? А образ не содержит ли уязвимостей?"

#### **Kyverno и OPA/Gatekeeper: Ваша система политики**

`Kyverno` и `OPA/Gatekeeper` — это два самых популярных адмит-контроллера. Они позволяют вам определять **декларативные политики** безопасности, которые будут автоматически применяться ко всем объектам в кластере.

*   **Kyverno:** Создан специально для Kubernetes. Его политики пишутся на YAML, что делает их понятными для DevOps-инженеров. Идеален для типичных задач: "все образы должны быть из внутреннего реестра", "все поды должны иметь `resources.limits`".
*   **OPA (Open Policy Agent) / Gatekeeper:** Более универсальный и мощный. Политики пишутся на языке Rego. Он подходит для сложных сценариев и может использоваться за пределами Kubernetes.

#### **Пример: Запрет публичных образов с помощью Kyverno**

Допустим, вы хотите запрещать деплойменты, которые используют образы из публичных реестров (например, `docker.io/library/nginx`), чтобы снизить риск заражения.

1.  **Создайте политику `ClusterPolicy`:**
    ```yaml
    # disallow-public-images.yaml
    apiVersion: kyverno.io/v1
    kind: ClusterPolicy
    metadata:
      name: disallow-public-images
    spec:
      validationFailureAction: enforce # Блокировать нарушения
      background: false
      rules:
      - name: validate-image-registry
        match:
          resources:
            kinds:
            - Pod
            - Deployment
        validate:
          message: "Использование образов из публичных реестров запрещено. Используйте внутренний реестр."
          pattern:
            spec:
              containers:
              - image: "!docker.io/*" # Запрещает образы из docker.io
                image: "!quay.io/*" # Запрещает образы из quay.io
    ```

2.  **Примените политику:**
    ```bash
    kubectl apply -f disallow-public-images.yaml
    ```

3.  **Проверьте:**
    Попробуйте создать под с образом `nginx`. Попытка будет **отклонена** с сообщением об ошибке.

#### **Путь вперед**

Адмит-контроллеры — это ключ к **автоматизации безопасности**. Они превращают ваши best practices в "железные" правила, которые нельзя обойти. В следующих статьях мы рассмотрим, как использовать их для проверки манифестов в CI/CD.

**Запомните:** Безопасность не должна зависеть от человеческого фактора. Автоматизируйте ее с помощью `Kyverno` или `OPA/Gatekeeper`.
