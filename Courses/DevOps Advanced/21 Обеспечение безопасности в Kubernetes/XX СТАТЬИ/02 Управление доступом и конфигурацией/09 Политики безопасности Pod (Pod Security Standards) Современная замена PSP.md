### **Статья 7: Политики безопасности Pod (Pod Security Standards): Современная замена PSP**

#### **Почему PSP устарели?**

Раньше для обеспечения безопасности подов использовались **PodSecurityPolicies (PSP)**. Они были мощным инструментом, но имели серьезные недостатки:
1.  **Сложность:** PSP были чрезвычайно гибкими, что приводило к сложным и трудноуправляемым политикам.
2.  **Неправильная модель доступа:** Управление PSP было привязано к RBAC, что создавало путаницу и потенциальные дыры в безопасности.
3.  **Удаление из Kubernetes:** Из-за этих проблем PSP были объявлены устаревшими (deprecated) и **удалены из Kubernetes начиная с версии 1.25**.

#### **Что такое Pod Security Standards (PSS)?**

Pod Security Standards — это **новый, встроенный подход** к обеспечению безопасности подов. Он заменяет сложные PSP на три четко определенных уровня безопасности:
1.  **`privileged` (привилегированный):** Минимальные ограничения. Почти все разрешено. **Не рекомендуется использовать.**
2.  **`baseline` (базовый):** Блокирует очевидно небезопасные действия (например, запуск контейнеров от root, использование `hostPath`). Подходит для большинства рабочих нагрузок.
3.  **`restricted` (ограниченный):** Наиболее строгий уровень. Реализует лучшие практики (например, обязательное использование `non-root` пользователей, запрет привилегированных контейнеров). Подходит для чувствительных рабочих нагрузок.

#### **Как работает Pod Security Admission (PSA)**

Для применения PSS используется **Pod Security Admission (PSA)** — встроенный в Kubernetes адмит-контроллер.

*   **Настройка:** Вы настраиваете PSA на уровне namespace, указывая, какой уровень безопасности (`baseline` или `restricted`) должен применяться по умолчанию и какие исключения разрешены.
*   **Пример конфигурации namespace:**
    ```yaml
    # namespace.yaml
    apiVersion: v1
    kind: Namespace
    metadata:
      name: my-app
      labels:
        # Устанавливаем уровень безопасности
        pod-security.kubernetes.io/enforce: baseline
        # Устанавливаем уровень предупреждения (для миграции)
        pod-security.kubernetes.io/warn: restricted
        # Устанавливаем уровень аудита (логирование)
        pod-security.kubernetes.io/audit: restricted
    ```
    *   `enforce`: Применяет политику. Поды, нарушающие ее, не будут созданы.
    *   `warn`: Отправляет предупреждение в ответ API, но позволяет создать под.
    *   `audit`: Включает более подробное логирование в аудит-логах API-сервера.

#### **Путь вперед**

Pod Security Standards — это будущее безопасности подов в Kubernetes. Они проще, надежнее и встроены в саму платформу. В следующих статьях мы рассмотрим, как интегрировать эти политики в CI/CD пайплайн для еще большей безопасности.

**Запомните:** Миграция с PSP на PSS — это не опциональная задача. Это **обязательный шаг** для поддержки вашей системы в актуальном состоянии.
