### **Статья 3: `kubectl auth can-i`: Проверка прав в реальном времени**

#### **Что такое RBAC и почему он нужен?**

Role-Based Access Control (RBAC) — это система, которая определяет, **что может делать** пользователь или сервисный аккаунт в вашем кластере Kubernetes. Без RBAC у всех будет полный доступ, что является огромным риском.

RBAC работает по принципу **"принципа наименьших привилегий"**: вы даете сущности только те права, которые ей **строго необходимы** для выполнения своей задачи. Например, приложение может читать секреты, но не создавать новые поды.

#### **Как работает `kubectl auth can-i`**

Команда `kubectl auth can-i` — это ваш **"светофор безопасности"**. Она позволяет мгновенно проверить, есть ли у текущего пользователя (или другого пользователя) право на выполнение определенного действия.

*   **Синтаксис:**
    ```bash
    kubectl auth can-i <действие> <ресурс> [--namespace <имя>] [--as <пользователь>]
    ```

*   **Примеры:**
    ```bash
    # Может ли текущий пользователь создавать поды в namespace 'default'?
    kubectl auth can-i create pods --namespace default
    # Вывод: yes

    # Может ли текущий пользователь читать секреты в namespace 'prod'?
    kubectl auth can-i get secrets --namespace prod
    # Вывод: no

    # Может ли пользователь 'dev-team' обновлять деплойменты в любом namespace?
    kubectl auth can-i update deployments --as dev-team
    # Вывод: no
    ```

#### **Практическое применение**

Эта команда незаменима в следующих сценариях:
1.  **Настройка RBAC:** Перед тем как развернуть новое приложение, проверьте, достаточно ли прав у его сервисного аккаунта.
2.  **Диагностика:** Если приложение падает с ошибкой "Forbidden", используйте `can-i`, чтобы понять, какое именно право ему не хватает.
3.  **Аудит безопасности:** Регулярно проверяйте права пользователей, чтобы убедиться, что никто не имеет избыточных привилегий.

#### **Путь вперед**

`kubectl auth can-i` — это первый шаг к пониманию и контролю доступа в вашем кластере. В следующих статьях мы подробно рассмотрим, как создавать роли, связывать их с пользователями и сервисными аккаунтами.

**Запомните:** Безопасность начинается с контроля доступа. Используйте `auth can-i` как свой основной инструмент для проверки.
