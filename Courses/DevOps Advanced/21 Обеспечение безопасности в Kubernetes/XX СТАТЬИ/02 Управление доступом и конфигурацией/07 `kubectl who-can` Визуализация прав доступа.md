### **Статья 5: `kubectl who-can`: Визуализация прав доступа**

#### **Почему `who-can` — это следующий шаг после `auth can-i`**

Команда `kubectl auth can-i` отвечает на вопрос: **"Я могу это сделать?"** Она проверяет права одного субъекта. Но на практике часто возникает обратная задача: **"Кто может это сделать?"** Например, вы хотите узнать, какие пользователи и сервисные аккаунты имеют права на удаление подов в production.

Для решения этой задачи существует плагин **`kubectl-who-can`**.

#### **Установка плагина `who-can`**

`who-can` — это плагин для `kubectl`, который нужно установить через `krew` — менеджер плагинов.

```bash
# Установить krew (если еще не установлен)
(
  set -x; cd "$(mktemp -d)" &&
  curl -fsSLO "https://raw.githubusercontent.com/kubernetes-sigs/krew/v0.4.4/install.sh" &&
  KREW=./install.sh bash && KREW=./install.sh
)

# Установить плагин who-can
kubectl krew install who-can
```

#### **Как работает `kubectl who-can`**

Плагин `who-can` анализирует все `RoleBinding`, `ClusterRoleBinding`, `Role` и `ClusterRole` в кластере и определяет, какие субъекты имеют право на выполнение указанного действия.

*   **Синтаксис:**
    ```bash
    kubectl who-can <действие> <ресурс> [--namespace <имя>]
    ```

*   **Пример:**
    ```bash
    # Кто может создавать поды в namespace 'production'?
    kubectl who-can create pods --namespace production

    # Вывод:
    # USER           GROUPS  SERVICEACCOUNT
    # alice@corp.com         default:alice-sa
    # dev-team                 dev:dev-sa
    ```

#### **Практическое применение**

Этот плагин незаменим для:
1.  **Аудита безопасности:** Регулярно проверяйте, кто имеет права на критически важные операции (например, `create pods`, `delete nodes`).
2.  **Расследование инцидентов:** Если был создан под с вредоносным кодом, используйте `who-can`, чтобы найти всех потенциальных подозреваемых.
3.  **Управление доступом:** Перед изменением политик безопасности убедитесь, кто будет затронут.

#### **Путь вперед**

`kubectl who-can` — это мощный инструмент для визуализации вашей системы RBAC. Он превращает сложную, распределенную конфигурацию в понятный список. Вместе с `auth can-i` они образуют полный набор инструментов для контроля доступа.

**Запомните:** Безопасность — это прозрачность. Вы должны всегда знать, кто что может делать в вашем кластере.
