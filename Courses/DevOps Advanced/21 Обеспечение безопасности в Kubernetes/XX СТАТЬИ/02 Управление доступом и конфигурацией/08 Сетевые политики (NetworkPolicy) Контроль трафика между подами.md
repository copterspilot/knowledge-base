### **Статья 6: Сетевые политики (NetworkPolicy): Контроль трафика между подами**

#### **Что такое NetworkPolicy?**

Представьте, что ваш кластер Kubernetes — это город. Поды — это здания (офисы, магазины, дома). Без NetworkPolicy любой может свободно ходить по улицам и заходить в любое здание. **NetworkPolicy** — это ваши **законы о доступе**. Они определяют, кто (какой под) может ходить по каким улицам (сетевым интерфейсам) и заходить в какие здания (другие поды).

Официально, `NetworkPolicy` — это Kubernetes-объект, который использует **LabelSelector** для изоляции подов и контроля входящего (ingress) и исходящего (egress) трафика.

#### **Как работают NetworkPolicy?**

NetworkPolicy **не создают** сетевые пути. Они **изолируют** их. По умолчанию:
*   **Все поды могут общаться со всеми.** Это политика по умолчанию.
*   Когда вы создаете `NetworkPolicy`, она **применяется к группе подов**, определенных в `spec.podSelector`.
*   После этого поды в этой группе **становятся изолированными**, если только политика явно не разрешает им трафик.

#### **Пример: Изоляция бэкенд-подов**

Допустим, у вас есть приложение с frontend и backend. Вы хотите, чтобы:
*   Frontend мог общаться с backend.
*   Backend **не мог** инициировать соединения с frontend.
*   Никакие другие поды не могли бы общаться с backend.

```yaml
# backend-network-policy.yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: backend-policy
  namespace: default
spec:
  podSelector:
    matchLabels:
      app: backend # Эта политика применяется ко всем подам с меткой app=backend
  policyTypes:
  - Ingress
  - Egress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: frontend # Разрешить входящий трафик только от frontend
    ports:
    - protocol: TCP
      port: 8080
  egress:
  - to:
    - podSelector:
        matchLabels:
          app: database # Разрешить исходящий трафик только к database
    ports:
    - protocol: TCP
      port: 5432
```

#### **Ключевые моменты**

1.  **CNI-провайдер:** `NetworkPolicy` не работает "из коробки". Для их поддержки нужен CNI-провайдер, такой как **Calico**, **Cilium** или **Antrea**.
2.  **Направление трафика:** Политика определяет как `ingress` (входящий), так и `egress` (исходящий) правила.
3.  **Изоляция по умолчанию:** Создание политики для группы подов делает их изолированными. Нет "разрешающей по умолчанию" политики.

#### **Путь вперед**

NetworkPolicy — это мощный инструмент для построения "сегментированной" сети в вашем кластере. В следующих статьях мы рассмотрим, как проверить, что ваш CNI-провайдер их поддерживает, и как использовать `inspektor-gadget` для диагностики проблем с сетевой политикой.

**Запомните:** Если вы не разрешили трафик явно — он запрещен. Это основа безопасности.
