## [5] `kubectl auth can-i`: Проверка прав в реальном времени

**Содержимое слайда (для PowerPoint):**
-   **Заголовок:** `kubectl auth can-i`: Проверка прав в реальном времени
-   **Основной текст / список:**
    *   **Синтаксис:** `kubectl auth can-i <действие> <ресурс> [--namespace <имя>]`
    *   **Примеры:**
        *   `kubectl auth can-i create pods --namespace default` → `yes`
        *   `kubectl auth can-i get secrets --namespace prod` → `no`
        *   `kubectl auth can-i update deployments --as dev-team` → `no`
    *   **Ключевая концепция:** Принцип наименьших привилегий
-   **Дополнительная информация (внизу):** "Безопасность начинается с контроля доступа"

#### **Цель слайда**
Познакомить аудиторию с командой `kubectl auth can-i`, которая является основным инструментом для проверки прав доступа в реальном времени. Подчеркнуть важность принципа наименьших привилегий.

#### **1. Описание визуального оформления**
Слайд должен содержать крупный заголовок с командой. Основной текст — в виде списка с примерами. Ключевой пример (`can-i get secrets`) должен быть выделен цветом (например, красным). Внизу — иконка "светофора" и ключевая фраза.

#### **2. Ключевые тезисы**
*   `kubectl auth can-i` — это "светофор безопасности" для вашего кластера.
*   Он позволяет мгновенно проверить, есть ли у пользователя или сервисного аккаунта необходимое право.
*   Это основной инструмент для диагностики ошибок "Forbidden" и настройки RBAC.

#### **3. Описание для выступающего (речь)**
"Когда вы настраиваете RBAC, как вы узнаете, что сделали правильно? Вы можете попробовать выполнить действие и получить ошибку. Но есть более умный способ — использовать `kubectl auth can-i`. Эта команда отвечает на простой вопрос: 'Я могу это сделать?'. Она является вашим первым шагом к контролю доступа. Как написано в `Sachdeva Piyush - Certified Kubernetes Administrator Study Companion`, понимание RBAC и умение проверять права — это ключевые навыки для CKA."

#### **4. Демо-сценарий (если уместен)**
*   **Демо:** Показать в реальном времени команду `kubectl auth can-i get secrets --namespace default`. Затем создать `RoleBinding`, дающий доступ, и повторить команду, чтобы показать, как ответ меняется с `no` на `yes`.

#### **6. Типовые вопросы и ответы (Q&A):**
*   **В:** Можно ли проверить права другого пользователя?
    *   **О:** Да, используйте флаг `--as <пользователь>`. Например, `kubectl auth can-i create pods --as jane@company.com`.
*   **В:** Что означает ошибка "Forbidden"?
    *   **О:** Это означает, что вашему пользователю или сервисному аккаунту не хватает необходимого разрешения. Используйте `auth can-i`, чтобы точно определить, какого именно.

#### **7. Примеры использования / Типовые сценарии**
*   **Настройка RBAC:** Перед развертыванием нового приложения проверьте, достаточно ли прав у его сервисного аккаунта.
*   **Диагностика:** Если приложение падает с ошибкой "Forbidden", используйте `auth can-i`, чтобы понять, какое именно право ему не хватает.
