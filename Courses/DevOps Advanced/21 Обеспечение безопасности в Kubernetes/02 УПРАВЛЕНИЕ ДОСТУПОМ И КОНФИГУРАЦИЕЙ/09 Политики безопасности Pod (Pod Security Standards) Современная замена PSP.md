## [9] Политики безопасности Pod (Pod Security Standards): Современная замена PSP

**Содержимое слайда (для PowerPoint):**
-   **Заголовок:** Политики безопасности Pod (Pod Security Standards): Современная замена PSP
-   **Основной текст / список:**
    *   **Устаревший стандарт:** `PodSecurityPolicy (PSP)` — удалена из Kubernetes начиная с версии 1.25.
    *   **Современная замена:** `Pod Security Standards (PSS)` + `Pod Security Admission (PSA)`.
    *   **Уровни PSS:**
        *   `privileged`: Минимальные ограничения (не рекомендуется).
        *   `baseline`: Блокирует очевидные анти-паттерны (рекомендуется для большинства).
        *   `restricted`: Наиболее строгий уровень (для чувствительных рабочих нагрузок).
    *   **Пример настройки:**
        _yaml
        # namespace.yaml
        apiVersion: v1
        kind: Namespace
        metadata:
          name: my-app
          labels:
            pod-security.kubernetes.io/enforce: baseline
            pod-security.kubernetes.io/warn: restricted_
-   **Дополнительная информация (внизу):** "Migrate from PSP to PSS: Это обязательный шаг для поддержки кластера в 2025 году."

#### **Цель слайда**
Познакомить аудиторию с современной, встроенной системой безопасности подов — Pod Security Standards (PSS) и Pod Security Admission (PSA). Объяснить, почему PSP устарели, и показать, как настроить PSS в кластере.

#### **1. Описание визуального оформления**
Слайд должен контрастировать старое и новое. Слева — перечеркнутый значок "PSP" с красным крестом. Справа — три зеленых значка с уровнями `privileged`, `baseline`, `restricted`. В центре — стрелка перехода "PSP → PSS". Нижняя часть слайда — пример YAML-манифеста для настройки PSA.

#### **2. Ключевые тезисы**
*   `PodSecurityPolicy` официально устарела и удалена из Kubernetes.
*   `Pod Security Standards` — это современная, встроенная альтернатива.
*   Использование `Pod Security Admission` позволяет легко применять политики на уровне namespace.

#### **3. Описание для выступающего (речь)**
"Раньше для безопасности подов использовались `PodSecurityPolicies`. Но они были сложными и уязвимыми, поэтому были удалены из Kubernetes. Их заменили `Pod Security Standards` — три четких уровня безопасности. Вместо написания сложных политик, мы теперь просто выбираем уровень изоляции: `baseline` для большинства приложений или `restricted` для критически важных. Как указано в `Lapaz Raul - Learning Kubernetes Security, 2nd Edition`, PSA — это предпочтительный способ обеспечения безопасности подов в 2025 году."

#### **6. Типовые вопросы и ответы (Q&A):**
*   **В:** Можно ли использовать PSP в новых кластерах?
    *   **О:** Нет, PSP была удалена начиная с Kubernetes 1.25. Любое развертывание нового кластера должно использовать PSS.
*   **В:** Чем PSA отличается от Kyverno?
    *   **О:** PSA — это встроенный контроллер, специализированный на PSS. Kyverno — это универсальный адмит-контроллер, который может применять PSS, но также и любые другие политики.

#### **7. Примеры использования / Типовые сценарии**
*   **Миграция с PSP:** Плановое обновление кластера с PSP на PSS.
*   **Настройка production среды:** Применение уровня `restricted` к production namespace'ам.
*   **Обеспечение compliance:** Демонстрация, что кластер соответствует требованиям безопасности.
