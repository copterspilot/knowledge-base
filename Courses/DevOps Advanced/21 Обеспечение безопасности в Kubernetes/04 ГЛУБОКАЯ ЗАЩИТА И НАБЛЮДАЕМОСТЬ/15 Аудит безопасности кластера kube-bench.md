## [15] Аудит безопасности кластера: `kube-bench`

**Содержимое слайда (для PowerPoint):**
-   **Заголовок:** Аудит безопасности кластера: `kube-bench`
-   **Основной текст / список:**
    *   **Что это:** Инструмент от CNCF для автоматизации аудита конфигурации кластера на соответствие CIS Benchmarks.
    *   **Как работает:** Запускается на узлах и проверяет конфигурационные файлы и параметры компонентов (API-сервер, etcd, kubelet).
    *   **Результат:** Генерирует отчет с пометками `PASS`, `FAIL`, `WARN`, `INFO`.
    *   **Пример запуска:**
        _bash
        # Запуск на узле
        docker run --rm -v /etc:/etc:ro -v /var:/var:ro -t aquasec/kube-bench:latest
        # Запуск для control plane
        docker run --rm -v /etc:/etc:ro -v /var:/var:ro -t aquasec/kube-bench:latest --targets master_        
-   **Дополнительная информация (внизу):** "Безопасность — это не разовое действие. Регулярный аудит — это ключ к стабильности."

#### **Цель слайда**
Познакомить аудиторию с `kube-bench` как с официальным инструментом для аудита безопасности кластера. Показать, как использовать его для проверки соответствия стандартам безопасности.

#### **1. Описание визуального оформления**
Слайд должен содержать логотип CNCF и `kube-bench`. Основной текст — в виде списка. В центре — схема: "Кластер Kubernetes" → стрелка → "kube-bench" → стрелка → "Отчет (PASS/FAIL)". Внизу — ключевое сообщение о важности регулярных проверок.

#### **2. Ключевые тезисы**
*   `kube-bench` — это "детектор утечек" для вашей базовой конфигурации.
*   Он проверяет соответствие рекомендациям CIS, которые являются отраслевым стандартом.
*   Регулярное использование `kube-bench` должно быть частью процедуры эксплуатации.

#### **3. Описание для выступающего (речь)**
"`kube-bench` — это официальный инструмент от Cloud Native Computing Foundation. Его задача — ответить на вопрос: 'Насколько безопасно настроена моя базовая инфраструктура?' Он проверяет, включены ли аудит-логи, правильно ли настроены права доступа к etcd, используются ли сертификаты. Как указано в `Burns B., Villalba E., Strebel D., Evenson L. - Kubernetes Best Practices`, регулярный аудит — это основа для поддержания безопасного состояния кластера."

#### **6. Типовые вопросы и ответы (Q&A):**
*   **В:** Можно ли запустить `kube-bench` как Job в Kubernetes?
    *   **О:** Да, можно. Существуют манифесты для запуска `kube-bench` как `Job` или `DaemonSet`.
*   **В:** Что делать, если `kube-bench` показывает `FAIL`?
    *   **О:** Не игнорируйте это. Изучите пункт, определите, почему он не соответствует стандарту, и внесите необходимые исправления в конфигурацию.

#### **7. Примеры использования / Типовые сценарии**
*   **Аудит перед релизом:** Проведение аудита перед развертыванием нового кластера.
*   **Регулярный аудит:** Настройка `kube-bench` для запуска по расписанию (cron) и отправки отчетов в систему мониторинга.
