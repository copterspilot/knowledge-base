## [16] Защита секретов: `Sealed Secrets`, `HashiCorp Vault`

**Содержимое слайда (для PowerPoint):**
-   **Заголовок:** Защита секретов: `Sealed Secrets`, `HashiCorp Vault`
-   **Основной текст / список:**
    *   **Проблема:** Никогда не храните открытые `Secrets` в Git-репозитории.
    *   **`Sealed Secrets` (Bitnami):**
        *   Шифрует `Secrets` локально в `SealedSecret`.
        *   `SealedSecret` можно безопасно коммитить в Git.
        *   Расшифровывается только в кластере контроллером.
    *   **`HashiCorp Vault`:**
        *   Централизованное хранилище секретов.
        *   Динамические секреты, ограниченное время жизни.
        *   Интеграция через `CSI Driver` или `Vault Agent`.
    *   **Выбор:**
        *   `Sealed Secrets` — для простоты и GitOps.
        *   `HashiCorp Vault` — для масштаба и сложных сценариев.
-   **Дополнительная информация (внизу):** "Ни в коем случае не храните пароли в открытом виде в коде."

#### **1. Описание визуального оформления**
Слайд должен содержать две колонки: слева — `Sealed Secrets` (иконка замка, ключ, Git), справа — `HashiCorp Vault` (иконка сейфа, сервер). Между ними — вопрос "Какой выбрать?". Внизу — красная иконка "не" и ключевое предупреждение.

#### **2. Ключевые тезисы**
*   Хранение `Secrets` в Git в открытом виде — критическая ошибка.
*   `Sealed Secrets` — это простое и эффективное решение для большинства сценариев, особенно при использовании GitOps.
*   `HashiCorp Vault` — это мощное корпоративное решение для централизованного управления секретами.

#### **3. Описание для выступающего (речь)**
"Секреты Kubernetes — это объекты для хранения паролей и токенов. Но сам `Secret` хранится в etcd в виде base64, что не является безопасным. А если вы коммитите YAML-манифест с `Secret` в Git, вы совершаете большую ошибку. Для решения этой проблемы есть два пути. Первый — `Sealed Secrets`. Вы шифруете секрет локально, получаете `SealedSecret`, который можно безопасно хранить в Git. Второй путь — `HashiCorp Vault`. Это специализированный сервис, который динамически предоставляет секреты вашим подам. Как указано в `Gkatziouras Emmanouil, Adams Rom, Xi Chen - Kubernetes Secrets Handbook`, выбор зависит от сложности вашей инфраструктуры."

#### **6. Типовые вопросы и ответы (Q&A):**
*   **В:** Можно ли использовать `Sealed Secrets` с Argo CD?
    *   **О:** Да, `Sealed Secrets` отлично работает с GitOps-инструментами вроде Argo CD.
*   **В:** Нужен ли `Vault` для небольшой команды?
    *   **О:** Для небольших команд `Sealed Secrets` часто бывает более чем достаточно. `Vault` оправдан при большой сложности и строгих требованиях к compliance.

#### **7. Примеры использования / Типовые сценарии**
*   **GitOps:** Использование `Sealed Secrets` для безопасного хранения конфигураций в репозитории.
*   **Enterprise Security:** Централизованное управление всеми секретами организации с помощью `Vault`.
