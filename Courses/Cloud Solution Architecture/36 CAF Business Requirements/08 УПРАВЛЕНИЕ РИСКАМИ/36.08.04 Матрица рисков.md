Ниже представлена **матрица рисков** для выбора облачного провайдера, сфокусированная на трёх ключевых угрозах:

1. **Санкционные риски**  
2. **Риски безопасности**  
3. **Vendor lock-in (зависимость от провайдера)**

Матрица охватывает **западные, российские и китайские облачные платформы** и помогает принять взвешенное решение при выборе облачной стратегии в условиях геополитической нестабильности, регуляторных требований и долгосрочной устойчивости ИТ-инфраструктуры.

## 🔍 Интерпретация рисков

### 1. **Санкционные риски**
- **Высокие у AWS, GCP, частично Azure** — ограничения на доступ, оплату, поддержку.
- **Низкие у российских и китайских** — не подпадают под западные санкции.
- **Важно**: даже если сервис доступен, могут быть проблемы с оплатой, лицензированием и SLA.

### 2. **Риски безопасности**
- **Западные и российские (Sber, RT)** — высокая зрелость и соответствие.
- **Китайские** — технически продвинуты, но **доверие ограничено** из-за геополитики.
- **RT.Cloud, Selectel, SberCloud** — лучший выбор для **госсектора и критичных систем**.

### 3. **Vendor lock-in**
- **Высокий у всех major-провайдеров** — AWS, Azure, Alibaba, Huawei.
- **Меньше у open-source-ориентированных** (Selectel, частично Yandex).
- **Снижается при использовании**:
  - Kubernetes (GKE, EKS, Yandex Managed K8s),
  - Terraform,
  - Стандартных протоколов (S3-compatible, REST API).

## 🛠️ Рекомендации по снижению рисков

| Риск               | Меры по снижению                                                                                                                                       |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Санкции**        | Использовать российские облака для критичных данных. Хранить резервные копии в независимых хранилищах.                                                 |
| **Безопасность**   | Проводить аудит, использовать шифрование, MFA, регулярные проверки уязвимостей. Для госсектора — только провайдеры с ФСБ/ФСТЭК.                        |
| **Vendor lock-in** | Применять **инфраструктуру как код (IaC)**, **контейнеризацию**, **multi-cloud стратегию**, избегать проприетарных managed-сервисов без необходимости. |
