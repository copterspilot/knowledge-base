### **Инструкция: Составление плана миграции в облако для России 2025**

Предлагаемый план интегрирует лучшие практики (AWS, CAF) с ключевыми требованиями российского рынка (импортозамещение, соответствие ФЗ-152). Он разбит на три вехи, каждая из которых содержит чек-листы для обеспечения системности и контроля.

---

### **Веха 1: Оценка (ASSESSMENT)**

**Цель:** Получить полное понимание текущего состояния IT-инфраструктуры, бизнес-требований и рисков.

#### **Ключевые задачи и чек-листы:**

**1.1. Анализ бизнес-требований и мотивации**
*   [ ] Сформулированы цели миграции (Motivation): снижение TCO, ускорение Time-to-Market, обеспечение соответствия ФЗ-152, импортозамещение.
*   [ ] Определены ожидаемые выгоды (Business Outcomes): конкретные цифры по снижению затрат, повышению доступности, ускорению вывода продукта.
*   [ ] Выявлены ключевые ограничения (Constraints): бюджет, сроки, требования безопасности, политика импортозамещения.
*   [ ] Проведен внутренний аудит рисков (согласно `anti-malware.ru`).

**1.2. Инвентаризация и анализ приложений**
*   [ ] Составлен полный каталог всех приложений и сервисов.
*   [ ] Проведена оценка каждого приложения по критериям:
    *   [ ] Критичность для бизнеса (High/Medium/Low).
    *   [ ] Техническое состояние (устаревшее, поддерживаемое).
    *   [ ] Архитектура (монолит, микросервисы).
    *   [ ] Зависимости (от других сервисов, баз данных).
*   [ ] Определена стратегия миграции для каждого приложения (6R):
	* [ ] Rehost *(Ре-хостинг / "Lift and Shift" - "Поднять и перенести")*
	* [ ] Replatform *(Ре-платформинг / "Lift, Tinker and Shift" - "Поднять, немного изменить и перенести")*
	* [ ] Refactor *(Рефакторинг / "Rip and Replace" - "Вырвать и заменить"*
	* [ ] Repurchase *(Реперчейс / Переход на SaaS)*
	* [ ] Retain *(Ретейн / Сохранение)*
	* [ ] Retire *(Ретайр / Выведение из эксплуатации)*

**1.3. Анализ текущей инфраструктуры**
*   [ ] Оценены текущие вычислительные мощности (CPU, RAM, диски).
*   [ ] Проанализированы сетевые требования (пропускная способность, задержка).
*   [ ] Оценены объемы и типы хранилищ (блочные, файловые, объектные).
*   [ ] Проведен анализ производительности и нагрузки (пиковые и средние показатели).

---

### **Веха 2: Готовность и планирование (READINESS & PLANNING)**

**Цель:** Подготовить организацию, выбрать провайдера, разработать детальный план миграции и обеспечить соответствие требованиям.

#### **Ключевые задачи и чек-листы:**

**2.1. Выбор облачного провайдера**
*   [ ] Проведено сравнение провайдеров (МТС Web Services, Т1 Облако, Yandex.Cloud, VK Cloud и др.) по чек-листу:
    *   [ ] Соответствие ФЗ-152 и хранение данных в РФ.
    *   [ ] Наличие сертификатов ФСТЭК/ФСБ.
    *   [ ] Использование ПО из Единого реестра.
    *   [ ] SLA и гарантии доступности.
    *   [ ] Наличие собственного SOC.
    *   [ ] Ценовая политика и инструменты оптимизации затрат (см. `it-cost-optimization`).
*   [ ] Принято решение о выборе провайдера и заключен контракт.

**2.2. Проектирование облачной архитектуры (Cloud Landing Zone)**
*   [ ] Спроектирована архитектура Cloud Landing Zone (мультиаккаунт/мультипроект).
*   [ ] Разработана сетевая архитектура (VPC, подсети, шлюзы, брандмауэры).
*   [ ] Спроектирована иерархия управления доступом (IAM) и политики безопасности.
*   [ ] Спроектирована архитектура логирования и мониторинга.
*   [ ] Спроектирована архитектура отказоустойчивости и резервного копирования (DRaaS, Backup).

**2.3. Планирование изменений (People & Governance)**
*   [ ] Определены ключевые заинтересованные стороны (стейкхолдеры) из бизнеса и ИТ.
*   [ ] Разработан план коммуникации и управления ожиданиями.
*   [ ] Определены новые роли и обязанности (Cloud Center of Excellence).
*   [ ] Планируется обучение персонала (инфраструктура как код, DevOps).

---

### **Веха 3: Миграция (MIGRATIONS)**

**Цель:** Выполнить миграцию приложений в соответствии с планом, обеспечив минимальное влияние на бизнес.

#### **Ключевые задачи и чек-листы:**

**3.1. Подготовка среды и пилотная миграция**
*   [ ] Развернута и настроена облачная среда (согласно Cloud Landing Zone).
*   [ ] Созданы и протестированы конвейеры CI/CD.
*   [ ] Выбрано 1-2 некритичных приложения для пилотной миграции.
*   [ ] Проведена пилотная миграция и тестирование.
*   [ ] Собраны и проанализированы результаты пилота (TCO, производительность, проблемы).

**3.2. Планирование и выполнение основной миграции**
*   [ ] Утвержден финальный график миграции (с учетом окон миграции).
*   [ ] Для каждого приложения:
    *   [ ] Подготовлен детальный план миграции (шаги, откат).
    *   [ ] Перенесены данные (с проверкой целостности).
    *   [ ] Развернуты приложения в облаке.
    *   [ ] Проведено тестирование функциональности и производительности.
    *   [ ] Выполнено переключение трафика (cutover).
*   [ ] Постоянно мониторятся затраты и оптимизируются ресурсы (см. `it-cost-optimization`).

**3.3. Завершение и оптимизация**
*   [ ] Проведен финальный аудит безопасности и соответствия.
*   [ ] Устаревшая on-premise инфраструктура выведена из эксплуатации.
*   [ ] Обновлены документы по обслуживанию и сопровождению (рабочая тетрадь).
*   [ ] Проведен анализ постмортем (post-mortem) для выявления уроков.
*   [ ] Запущен процесс непрерывной оптимизации (FinOps) и внедрения новых облачных возможностей (например, ИИ/аналитика, см. `ai-data-analytics-guide`).

Этот план обеспечивает структурированный, контролируемый и соответствующий российской специфике подход к миграции в облако. Чек-листы на каждом этапе помогают отслеживать прогресс и минимизировать риски.
